# 双审计科研工作流：可迁移说明

```text
用途=供其他科研项目参考，不含本项目专有授权与角色设定
证据来源=本项目 2026-07-24 至 2026-07-25 的真实失败与修复
读法=第 2 节是核心论证，第 3 节是错误分类与检测手段，第 5 节是最值得抄走的部分
```

这份文档只讲一件事：**在"算法研究 + 快速迭代 + 结论要写进论文"这种场景下，代码审查为什么不足以保护结论，以及应该在哪里再加一层审计。**

所有例子都是真实发生过的缺陷，不是假想。每个例子后面都给出**可执行的检测手段**——因为一条无法执行的规则和没有规则是一样的。

---

## 1. 适用范围与不适用范围

**适用**：探索性算法研究；大部分方向会死；结论最终要变成论文里的断言；代码是证据的载体而不是交付产品。

**不适用**：工程产品线（那里兼容性、覆盖率、回归套件的价值远高于此处）；纯理论工作（没有实现层缺陷）。

一个前提必须先说清楚，否则后面所有权衡都会走偏：

> **要防的是"发表了错误的断言"，不是"浪费了工程"。**

这两个目标会给出**相反**的决策。前者要求在少数关键处不惜代价，后者要求处处节省。把它们混在一起，结果通常是：在无关紧要的地方加了一堆流程，而在真正会产生错误断言的地方一次都没检查。

---

## 2. 为什么要两次审计

### 2.1 核心论证

第二次审计（对实现的审查）通常是这样做的：**冻结设计 → 实现 → 拿 diff 对照设计审查**。

这套流程有一个结构性盲区：

> **对照冻结计划审查 diff，无法发现计划本身的缺陷——一个忠实实现的错误设计会通过审查。**

而且它会以最坏的方式通过：审查给出 APPROVE，测试全绿，然后实验跑出一个"阴性结果"，而这个阴性结果是设计缺陷的产物，不是科学事实。**这类错误最贵，因为它污染的是结论，而不是代码。**

本项目的原始案例：某个信用分配（credit）规则被正确实现，通过 18 个测试，然后被发现在设计强制的初始状态下**恒等于零**——它的 leave-one-out 对比在两个相同输入上求值。梯度恒为零，参数永远不动。如果不检查设计，这次实验会把它报告为"该机制无效"（behavioral no-access），而真相是"该机制从未被实例化"。

按 `Result interpretation` 的分类，这两者**退休的对象完全不同**：前者退休一个科学猜想，后者只退休一次实现。**把后者误读成前者，就是一个错误的发表断言。**

### 2.2 两次审计各自的位置

| | 审计一：设计冻结前 | 审计二：实现对设计 |
|---|---|---|
| 时机 | 设计写完、冻结之前 | 实现完成、提交之前 |
| 对象 | 设计本身的自洽性与可测量性 | diff 是否忠实于设计 |
| 能抓到 | 恒零信号、退化的零假设、无法触发的分支、平凡满足的不变量 | 语义漂移、越界修改、被破坏的不变量 |
| 抓不到 | 实现是否忠实 | **设计是否有意义** |
| 触发条件 | 设计引入/改变了信用定义、梯度路径、某个信号依赖的初始化、结果分支 | 触碰受保护语义的任何改动 |

**两者不可互换，也不是一条流水线上的两道工序**——它们看的是不同的东西。分析脚本、纯评估工作、机械重构可以跳过审计一。

### 2.3 第三层：审问提问本身

清单只能问它作者想到的问题。本项目的设计前检查清单**通过了**一份含有六个缺陷的契约，其中每一个都可以在纸上判定，但没有一个被问到过：章节间输入列表自相矛盾、一处要求的阈值在另一处从未冻结、一个退化的零假设、把蒙特卡洛预算与估计它的样本混为一谈、缺失的策略快照条件、在自己声明的支撑集之外取期望。

所以在把问题交给外部权威（人类专家 / 更强的模型 / 评审）之前，加一次**对抗性的自我审问**，只问一件事：

> **这份契约里，哪个承载性的决定是没有被问过就做掉的？**

结构性检查（可达性、非空白名单、字段完整）和"问题是否覆盖了决定"是两种不同的失败，而只有前者有自动化闸门。

## 3. 错误来源分类

这一节是本文档最实用的部分。每一类都给出真实案例和检测手段。

### A. 设计层缺陷（对 diff 审查不可见）

- **恒零信号**：信用规则在设计强制的入口状态恒为零。
- **阳性对照不成立**（本次最重要的发现，见 §5.1）：对照环境允许一个**不需要目标行为**的最优解，因此它的阴性结果不能说明任何事。

**检测**：在冻结设计前，对着设计回答——
1. 在设计强制的初始状态下，每个学习信号在数值上等于多少？
2. 每个可训练参数在入口处是否有活的梯度路径？
3. 是否有某个必需的不变量被**平凡地**满足，从而使测量变得空洞？
4. 是否有某个结果分支会因为**非科学原因**触发？
5. 冻结的初始化与信用定义是否互相抵消？

只回答"推导或小探针能在不训练的情况下判定"的问题；需要跑训练才能回答的属于实验，不属于这一层。

### B. 守卫绑错了对象

本项目有四道校验守卫把"允许使用固定的底层执行器"绑在了一个**完全无关的高层开关**上，只因为这几样东西当初是作为一个包一起验证的。后果：需要"执行器 + 学习型保持决策"同时成立的阳性对照**在配置层面就不可能存在**。

其中一道更隐蔽：某个 toy 环境的检查间隔（`Δ`）允许值也写在同一个分支里，于是另一条通道会**静默地**落到通用规则上，把 `Δ` 改掉而不报错。

**检测**：对每一道守卫问"它保护的到底是什么"，然后检查它的条件是否就是那个东西。守卫的条件里出现"当初一起验证过的另一个开关"，就是绑错了。

**特别注意**：把守卫收紧同样是错误来源。本项目一次"出于谨慎"的额外收紧，后来被测量证明**挡住的是达成能力所必需的优化预算，而不是它声称保护的信用语义**。真正的保护往往是结构性的（见 §5.3）。

### C. 权限倒置：自己写下的阻塞变成了对自己的授权

最隐蔽的一类。流程是：遇到一个问题 → 判断"这可能需要外部裁决" → **把它写进设计文档** → 下一轮读到这句话，当作必须等待的裁决 → 停摆。

而实际情况是：外部权威**早就**批准了那件事，被挡住的只是一道过期的校验守卫。把它再送一遍，等于请对方重新批准他已经批准的东西，并且把最稀缺的资源（外部评审轮次）花在零信息上。

**检测**：判断一个决定是否需要跨越边界，只用一条测试——

> **把这个选择反过来，会改变某个已注册的量或某个结果分支吗？**

只决定"一个已被授权的配置能不能启动"的选择，不通过这条测试。另外：**本对话写下的阻塞不是对本对话的权威**。文档记录决定，不创造许可闸门。

### D. 探针本身是错的

想验证"中心化状态是否真的到达了高层策略"，于是比较不同状态下**实际产生的 token**——结果完全相同，看起来像是信息通路是死的。

真相：`keep_head` 的权重是零初始化的，所以那个 logit 是一个常数偏置，两个体在入口处都会确定性地选择 KEEP，**因此 token 层面永远看不出差别，哪怕状态接得完全正确**。正确的观测量是 skill logits，换过去之后立刻看到它随目标符号变化。

**检测**：设计探针时问"如果被测的东西是好的，这个探针会给出什么？如果是坏的，又会给出什么？"两者相同，探针无效。零初始化、掩码、饱和、clip 都会制造这种假阴性。

### E. 归一化与阈值的算术使闸门无法为正确的理由触发

阈值和归一化必须**一起**检查，否则会出现一个正确的机制被算术淘汰。

本项目的实例：某个效应量的门槛是 `LCB95 ≥ 0.10`。若归一化取"整个视野上的可行区间"，而干预只作用一个检查间隔（视野的 1/6），则一个**完全正确**的机制算出来是 `0.083`——低于它自己的门槛。换成"构造性最优 − 无更新零假设"的差距做归一化，同一个效应是 `0.25`。

同一族的另一个坑：归一化若只从第 0 步的窗口测量，而该源在第一个检查到来前不会变化，则零假设在该窗口上**平凡最优**，归一化常数恰好为 0，下游直接除零。

**检测**：把预期的效应量代进阈值算一遍。**先算，再冻结。** 并且检查"零"是否可能：任何做分母的量都要问它能否为 0。

### F. 测试没有测它名字所说的东西

一个名为"把奖励注入到匹配的 rollout 智能体"的测试，约三次里失败两次。表面原因像是随机种子。真实原因是：它所命名的那条注入通道的开关**默认是关闭的**，那个奖励从未到达 rollout；让断言偶尔通过的是另一条**逐步的、在零处截断的**微奖励，其符号由随机初始化决定——于是 `!= 0.0` 在两个步骤上各是一次抛硬币。

这个测试还一度被误读为新改动引入的回归。

**检测**：对每个测试问"如果我删掉它声称在测的那段逻辑，它会失败吗？"以及"这个断言可能因为别的原因通过吗？"。特别怀疑 `!= 0`、`> 0`、`is not None` 这类弱断言——它们最容易被无关通路满足。修法不是加种子，而是**让被测通道真的打开，并断言它的路由性质**。

### G. 先验证据被过度采信

同一个 toy 上唯一的历史运行记录为"信用锚点失败"，数值处于随机水平。差点被当成"该源在信用上不可学"的既成事实。查了归档契约才发现：那次只跑了 **20 次外层更新、12,800 步**——是本次筛选预算的十分之一，且在另一套代码、另一个决策分支下。

那是"20 次更新内没学会"的证据，不是"学不会"的证据。

**检测**：引用任何历史结论前，打开它的归档契约，看**预算、代码路径、分支**。记录会比它的产物活得更久，而且会被后人当成结论。

### H. 把工程预算问题误判为科学结论

现象：奖励 200 次更新完全不动（随机水平 0.44 上下），梯度范数非零（0.26–0.48）。**非零梯度 + 行为不变**，看起来像信用分配失败。

真相：一次 PPO epoch × 200 次更新 = **200 步优化**，学习率 1e-4。策略根本没离开初始化——`keep_prob` 0.599 对初始值 0.6，skill 分布熵 1.096 对最大值 ln3 = 1.0986。把 epoch 提到 3、学习率提到 1e-3、更新提到 1000（即 3000 步优化）之后，**100 次更新内奖励升到 0.984，218 次更新达到 1.000**。

**检测**：在把"没学到"解释成科学结论之前，先数**优化步数**（不是环境步数），并检查策略是否离开了初始化（参数漂移不够，要看**行为分布**：熵、边缘概率）。非零梯度不是行为证据；**坍缩闸门必须先于解释**。

### I. 基础设施规则本身含有停滞

计算资源闸门脚本统计"重型 Python 进程数"，但**无法区分别人的负载和自己刚启动的作业**。于是它对自己的在跑任务返回 BUSY（CPU 仅 26.6%，上限 60%）。按文档字面执行，应对方式是"睡一小时后重查"——而那个作业本来就会在完成时通知你。**这是一次伪装成合规的停摆。**

修法：先读它报告的 pid；是自己的，就等通知，同时做不占计算的工作。

**检测**：对每条运维规则问"照字面执行会不会产生停滞或空转？"以及"这条规则的输入是否足以区分它要区分的两种情况？"

### J. 过度保守的钉死

见 §3.B 末段。收紧一道守卫和放松它一样需要证据。

## 4. 效率与风险的权衡

### 4.1 一条校准原则

> **除非风险是"错误的断言"，否则拿走结果。**

把检查分成两个集合，只对第一个不惜代价：

**严格集（会直接制造错误断言）**
- 初始状态是吸收态 / 信号恒零
- 条件化在不该固定的历史上
- 只支持"未能判定"却报告了"失败"
- 分支回答的不是它声称的断言
- 干预被读成自然策略行为
- 对照组不匹配
- 零假设不是被检验的那个对象

**宽松集（事后可恢复，不值得阻塞）**
- 分支可达性
- 未注册的常数
- 符号绑定

对论文还额外承载两条：**可复现性**（包本身就是证据）与**最小可支持的断言**。

### 4.2 最便宜的判别动作优先

按这个顺序找能改变决定的最便宜动作：**推导 → 构造反例 → 重新分析已有数据 → toy → 原型 → 正式计算**。只有在更便宜的手段都答不了这个问题时才去训练。

本次的实例：一个对照被"退休"是靠**纸上推导**（源允许一个不需要持久性的最优解）+ 已有 ledger 数据，而不是靠再跑一次实验。另一个对照的"无访问"结论是靠**算术**得到的：团队奖励 = 0.5×(两项匹配之和)，稳定在 0.475 ⇒ 两项之和 ≈ 0.95，而门槛要求 ≥ 1.5——不需要跑审计。

### 4.3 审计是触发式的，不是全量的

用最小的、能改变决定的证明：
- 一个辅助函数或 schema 改动 → 一个聚焦检查
- 一个持久的缺陷修复 → 一个复现/回归 + 聚焦重跑
- 受保护的跨文件工作 → 最多一次风险触发的顾问式审查，再审只在出现具体失败或异常之后

**不要有**：审查的审查、每个子任务的强制独立审查、兼容性套件、覆盖率指标、纸面闸门。测试执行真实的科学与运维不变量，不创造第二个权威。

### 4.4 什么时候停下来问

只escalate那些授权确实不覆盖的：真正扩大受保护的科学范围；对外部目标的不可逆动作；破坏性操作。**在授权范围内反复请示，本身就是缺陷，而不是谨慎。**

## 5. 我认为最值得抄走的部分

### 5.1 阳性对照必须使目标行为成为**必要**，而不只是**允许**

这是本次最有价值的一条，而且很容易被忽略。

一个用来验证"载体能否表达 X"的对照环境，必须让 X 成为达成最优的**必要条件**。本项目的 toy 有两个"时间尺度"，看起来天然需要"一个体保持、另一个体频繁更换"。但它的奖励是**两种智能体-任务分配中较好的那个**（置换不变），于是从任意一个最优配对出发，下一个最优配对既可以靠"保持 + 更换"达到，也可以靠**两个体同时更换、互换职责**达到——后者让每个承诺的寿命恰好等于一个检查间隔，**从不保持**。

两个不同的最优解，其中一个从不表现目标行为。于是这个对照的阴性结果**什么也不能说明**。实测签名非常干净：能力 1.0/1.0，`P(SET|flex) = 1.0`，`P(KEEP|stable) = 0.0`，全同步更换率 1.0，两个体的干预效应几乎相等（0.214 对 0.232）。

原设计其实预见到了"共享奖励"这个质疑，并驳回了它，理由是"在给定历史下当前分配打破了瞬时对称性，所以焦点干预有明确定义的效应"。**这句话是对的，但不够**：干预确实有明确定义，失效的是从它做出的推断。瞬时不对称给出一个焦点效应，但它**不使持久性成为必要**，而只有必要性才让阴性结果有信息量。

**可迁移的检查**：对任何阳性对照，写出它的最优策略集合。如果存在一个不表现目标行为的最优解，这个对照不成立。置换不变的多智能体奖励尤其危险——**角色交换会无代价地替代持久性**。

### 5.2 与结果相关的选择，必须在看到结果之前声明

一旦能力达成，"审计哪个 checkpoint"就从无关紧要变成了一个可以调结果的旋钮。事后再选，与拟合无法区分。

本项目的做法：在训练仍在进行、任何审计都还没跑过的时候，把"被审计对象 = 该次运行的最终 checkpoint"写进冻结契约，并明确"中间 checkpoint 只能作为训练轨迹注记，永远不是结果"。同时写明：能力提前达成意味着后续更新只是**锐化**策略，而锐化可能把某个条件推向任一方向——**两者都是最终策略的真实读数，都不构成去拿更早 checkpoint 的理由**。

同类的旋钮还有：归一化常数、聚类单位、置信区间方法、丢弃样本的规则、随机种子块。**全部在跑之前冻结，并把"为什么这样选"的论证一起写下来**，这样它可被审计，而不是可被辩解。

### 5.3 守卫必须能够失败；真正的保护往往是结构性的

一个永远不会触发的闸门等于没有闸门。本项目有过一个"零容忍 1e-8"的判据，作用在一个噪声量级 1e-3 的样本均值上——它在数学上无法触发。

反过来，**最好的保护不是标签，而是结构**。本项目想阻止"学习型保持"的载体继承一种未验证的信用模式。用"分支标签"去钉它，结果连带挡住了无害且必需的优化旋钮；而真正的保护一直都在：那种信用模式在实现上**要求"每次检查都强制更换"**，而那正是"保持"不成为决定的分支——所以它对该载体**在结构上不可达**，无论标签怎么写。

**可迁移的检查**：对每个闸门，构造一个应当触发它的输入并确认它触发。对每条禁止，先问"有没有一个结构性的理由让它自动成立"——如果有，用那个，别用标签。

### 5.4 用测量代替争论

本项目反复出现的模式：一个看似合理的因果解释，被一次很便宜的测量推翻。

- "状态没接到策略里" → 换探针后发现接到了（§3.D）
- "信用分配失败" → 数优化步数后发现策略没离开初始化（§3.H）
- "该源在信用上不可学" → 打开归档契约发现只跑了十分之一预算（§3.G）
- "两个归一化形式差不多" → 代入算术后发现一个会淘汰正确机制（§3.E）

**规则**：任何"我认为原因是 X"的判断，先问"最便宜的测量是什么"。本文档里几乎每个修复都来自一次几秒到几分钟的探针。

### 5.5 区分"执行一个裁决"与"做出一个裁决"

见 §3.C。这条规则同时解决了停摆和越权两个方向的问题，而且它给出的是一个**可判定的测试**，不是态度要求。

### 5.6 失败只留科学记录，不留装置

一个被验证为无望的方向，只保留"试了什么、返回了什么、为什么死了"，其余全部删掉，正文换成一个指针。理由是：**被退休的材料在每一次阅读中都与活的材料争夺注意力**。多年后能防止重犯的是失败记录本身，不是围绕它的文档体系。

同时——**退休的边界要划得尽量小**。本次退休的是"这个对照环境"，而不是载体、不是估计量、不是干预机制。审计脚本、干预钩子、事件 ledger、归一化全部原样迁移到替代源。**弄清一次失败到底退休了什么，本身就是省钱的行为。**

### 5.7 循环需要机制，不只需要意图

如果流程文档说"迭代自动继续"，但没有任何句子**重新调用**执行者，那么它就会在"手上没活、没有在跑的任务、也没有要回答的问题"那个空档里停住。意图不是机制。

本项目付出的代价是反复停摆，直到把"谁来重新唤醒"写成显式的驱动器：以**在跑任务的完成通知**为主驱动，以**定时唤醒**兜住通知覆盖不到的空档，并把"是否挂了驱动器"记录在持久的状态文件里——因为驱动器是会话级的，而边界记录不是。

## 6. 一页速查表

**冻结设计前**
- [ ] 在强制的初始状态下，每个学习信号数值是多少？
- [ ] 每个可训练参数在入口有活的梯度路径吗？
- [ ] 有不变量被平凡满足吗？
- [ ] 有分支会因非科学原因触发吗？
- [ ] 初始化与信用定义会互相抵消吗？
- [ ] **阳性对照的最优解集合里，有不表现目标行为的解吗？**
- [ ] 把预期效应量代进阈值算一遍，正确的机制能过吗？
- [ ] 所有做分母的量，能为 0 吗？
- [ ] 与结果相关的选择（checkpoint、归一化、聚类、丢弃规则）都冻结了吗？
- [ ] 这份契约里，哪个承载性决定没有被问过？

**实现提交前**
- [ ] diff 忠实于设计吗？
- [ ] 受保护语义（概率分解、梯度/detach、RNG、掩码、时钟、阈值）动了吗？动了就要显式接受的边界。
- [ ] 默认路径是否逐位不变？（新增可选参数时用金标准回归钉住）
- [ ] 每个新测试：删掉被测逻辑它会失败吗？断言可能因别的原因通过吗？
- [ ] 每个闸门：构造一个应触发它的输入，它触发了吗？

**读结果前**
- [ ] 访问/识别类分支是否**先于**行为类分支？
- [ ] 优化步数够吗？策略离开初始化了吗（看行为分布，不只看梯度）？
- [ ] 引用的历史结论，它的预算和代码路径核过了吗？
- [ ] 这次失败**最小**退休了什么？哪些东西其实完好？

## 7. 一句话总结

> 代码审查保护实现，**设计审计保护结论**。前者问"做对了吗"，后者问"这件事做对了还有意义吗"。绝大多数昂贵的科研错误活在第二个问题里，而它不会让任何测试变红。
