## Exact finite cooperative host

### Roster and mission worlds

The only roster sizes are `N in {3,5,7}`. Training uses `N=3` and `N=5`; `N=7`
is absent from training, tuning, normalization, checkpoint choice, and
calibration. Every episode uses a genuine `N`-element roster. There is no
max-seven padding surrogate, duplicated agent, dropped agent, or learned
`N`-specific parameter.

For odd `N`, define

`B_N = {x in {-1,+1}^N : abs(sum_i x_i)=1}`.

Draw two channel vectors `X^0` and `X^1` independently and uniformly from
`B_N`. Draw mission `m` uniformly from `{0,1}`. The route target is

`y = sign(sum_i X^m_i)`.

Odd `N` makes the target tie-free. Restricting both independent channels to
unit majority margin fixes the raw mission margin across all three roster sizes
and gives relevant and decoy channel pools the same magnitude `1/N`. Mission,
channel vectors, roster size, presentation, carrier allocation, slot order, and
route-label polarity are mutually exogenous except for the relationships stated
below. Complement-paired schedules make `y=+1` and `y=-1` exactly balanced.

A hidden directed `N`-cycle `rho` maps each recipient `i` to one other peer
`rho(i)`. It is a no-self bijection, is redrawn from a counter-keyed namespace,
and is conjugated under every roster relabeling. Both channel packets delivered
to recipient `i` come from peer `rho(i)`. Sender, recipient coordinate, cycle
position, and roster identity are never learner features. If every recipient
reads the mission-relevant channel, the selected values contain each roster
member's relevant bit exactly once, so their mean has sign `y`.

### Visible finite relation and sealed payloads

There are two presentations and two mission topics. Presentation `0` uses the
query/header atom pairs `CROSSWIND_QUERY`/`ANEMOMETER_HEADER` and
`THERMAL_QUERY`/`THERMISTOR_HEADER`. Presentation `1` uses
`LATERAL_FLOW_QUERY`/`CROSS_FLOW_HEADER` and
`UPDRAFT_QUERY`/`UPDRAFT_SENSOR_HEADER`. Each presentation has a fixed finite
compatibility table: its first query matches channel `0`'s header and its second
query matches channel `1`'s header. Both presentations occur in training and
evaluation; presentation is not a held-out semantic axis. The atoms are opaque
finite IDs to the learner. A four-by-four learned score table may memorize the
relation, so no language or open-vocabulary interpretation is permitted.

Each recipient receives exactly two valid carrier-token/packet pairs, one for
each channel. Before selection the learner sees only:

`(query_atom, two topic_header atoms in two legal slots, auth_ok=1, cap=1, legal_mask={0,1})`.

A packet payload is fixed-width
`(schema=SIGNED_SCALAR_V1, value=X^c_{rho(i)})`. The value is sealed until its
slot is selected. Topic, sender, recipient, mission relevance, arm, twin,
block, split, target, and future return are absent from the decoded payload.
Both channel packets have identical schema, size, validity, freshness,
quality, encoding cost, and service behavior. The nonmission channel is the
matched decoy. Because `X^0` and `X^1` are independent with the same exact law,
the decoy is not a sentinel, malformed packet, deterministic inverse, or
recoverable transform of the relevant payload.

Carrier validation proves only token provenance/integrity. It does not bind the
visible topic atom to the sealed channel payload, reveal the donor, or model
cryptographic security under compromise. Opaque token serials and registry
state remain private. Slot placement is balanced and independently shuffled.
Swapping the candidate slots must swap selector scores and choices under coupled
randomness without changing the semantic carrier selected.

### Two-stage public path

Stage 1 is simultaneous. One shared selector scores both visible carrier
exteriors for every UAV and selects exactly one slot. The selected payload is
opened exactly once and injected exactly once into the team pool. The other
payload is irreversibly unavailable. A two-payload census is rejected before
any payload is decoded. A failed read or service consumes its opportunity and
never permits a retry.

The pool publishes only

`mu = (1/N) * sum_i v_i`,

where `v_i` is the serviced signed scalar. It publishes no ordered values,
carrier/header/query field, slot or selector action, sender/recipient identity,
logit, validation evidence, allocation/twin/block label, or missingness signal.
There is no recurrent state across the stage boundary.

Stage 2 receives only `mu` and the fixed route menu `{LEFT,RIGHT}`. It samples
one common route action that is applied by all `N` UAVs. A seed-fixed hidden
route polarity counterbalances whether positive `y` maps to LEFT or RIGHT. Team
return is `3` if the common action matches `y` and `-1` otherwise. No individual
selection label, per-agent reward, majority label, intermediate bonus, or
supervised target is exposed. The best target-blind balanced common action has
exact expected value `1`; the oracle relevant-pool route value is `3`.

This is a finite common-payoff route-fork abstraction. Its cooperative content
is that no recipient sees the team target and the common action depends on the
set of serviced peer records. A support witness must hold one recipient's full
pre-pool view fixed while varying other peers so that the target changes. No
flight dynamics, radio loss, collision geometry, energy model, safety envelope,
or deployment environment is modeled.

## Authentic and reassociated carrier allocation

### Authentic allocation

A carrier token has a whole visible exterior plus a private opaque serial. For
twin `k`, recipient `i`, and topic `c`, write it as `C[k,i,c]`; write the sealed
channel packet as `P[k,i,c]`. In `AUTHENTIC`, token `C[k,i,c]` is associated
with packet `P[k,i,c]`. The query-compatible header therefore selects the
mission-relevant channel.

### Exact twin reassociation

For every exact stratum

`(split,N,mission,presentation,route_polarity,channel_pair,peer_cycle,slot_template,block)`

construct two opaque twins `k in {0,1}`. The twins have identical learner-visible
and latent mission facts but distinct valid token serials. A hidden fair block
bit `h` defines `d_k = h XOR k`. In `REASSOCIATED` twin `k`, associate the whole
donor token `C[1-k,i,c]` with current-twin packet `P[k,i,c XOR d_k]` for every
recipient and topic. As `c` ranges over `{0,1}`, both donor tokens and both
current packets are used exactly once. Every token moves from the other twin;
no token or packet is edited, lost, duplicated, or moved across the frozen
stratum.

For one hidden twin `d_k=0` and the topic/payload binding is congruent; for the
other `d_k=1` and it is inverted. Twin and `h` are never visible. Hence, for any
selector measurable from the complete allowed Stage-1 view, the probability
that either query-compatible or query-incompatible selection opens the relevant
channel is exactly `1/2` over the paired twins. There is no stable inverse code.
Because the same global `d_k` applies to the full roster, the relevant or decoy
selected vector has the exact channel-vector law; its pool marginal is matched,
while only its dependence on the unobserved target changes. The allocation
preserves the complete carrier multiset, cross-recipient token correlations,
validity-success marginals, slots, payloads, work, and timing.

`BIT_BLIND` is a separately resource-matched frozen evaluation diagnostic, not
a training arm. It validates and presents the same carriers but bypasses the
learned relation and uses a counter-keyed balanced physical-slot schedule. It
supports comparison to a simpler selector but does not establish that
carrier authentication is necessary relative to an equally predictive
nonauthenticated feature.

## Shared learner and paired training

Each semantic training arm owns one isolated 18-parameter learner. No weights,
optimizer state, transitions, normalization, or replay cross arms. Within an
arm, the same parameters are used for every UAV and both training roster sizes.
There are no agent embeddings, positional features, `N` input, `N`-specific
heads, padding masks, recurrence, critic, bootstrap target, replay,
regularization, or learned payload encoder.

The selector is a learned `4 x 4` table `W[query_atom,header_atom]`. Candidate
scores are the corresponding table entries and the two-slot policy is their
softmax. The fixed payload encoder emits the signed scalar. The invariant pool
is `mu`. The route policy is Bernoulli with logit `phi_0 + phi_1*mu`. All 18
parameters begin at zero. A consistent roster permutation leaves selector
probabilities equivariant and `mu`, the common-route distribution, and return
invariant.

Paired base seeds are `[11,23,37,53,71,89,107,127]`. World generation, peer
cycle, carrier/twin allocation, slot order, selector exploration, route action,
evaluation tie rank, mask, force, clamp, and roster permutation use separate
counter-keyed namespaces. The two training arms share exogenous coordinates and
paired draws but never parameters or transitions.

Training has exactly `1,024` macroblocks per arm and seed. Each macroblock has
five `N=3` episodes and three `N=5` episodes, giving exactly 15 UAV read/service
opportunities at each size. Every eight consecutive macroblocks exactly
balances mission, presentation, twin, target sign, slot polarity, route-label
polarity, and roster-size order. World order is independently shuffled within
that constraint and paired across arms.

One eighth of training team episodes are marked by a reward-blind exploration
schedule. On those episodes, each recipient's slot is forced by a balanced
counter-keyed schedule; the forced choice has no selector likelihood-ratio term
but still trains the payload/route path. Other episodes sample the learned
selector. All route actions sample the learned route policy. Forced choices are
tagged and never counted as learned selection.

After each macroblock, form the mean score-function objective separately for
`N=3` and `N=5`, normalizing selector log probabilities by active roster size,
and average the two size objectives with weight `1/2`. With team return `Y`,
the fixed baseline is the target-blind value `1`. Update once by plain SGD with
learning rate `0.05`:

`parameters <- parameters + 0.05 * grad(0.5*mean_3[(Y-1)*logp] + 0.5*mean_5[(Y-1)*logp])`,

where `logp` is the active learned-selector mean log probability plus the common
route-action log probability; forced selector terms are omitted. There is no
clipping, entropy term, weight decay, adaptive optimizer, learning-rate change,
or reward shaping. The only checkpoint is the state after update `1,024`.
No tuning, early stop, retry, reduced run, sweep, or validation-based choice is
permitted.

### Frozen controls and interventions

On the authentic-trained checkpoint, the same 512-coordinate banks also run:

- `BIT_BLIND`: balanced physical-slot selection with the real validation/read/
  service path;
- `SEMANTIC_MASK`: a fresh conditionally matched query/header relation allocation
  independent of mission relevance, never a stable global relabel;
- `FORCE_RELEVANT`: one resource-legal relevant packet per recipient;
- `FORCE_DECOY`: one resource-legal decoy packet per recipient;
- `POOL_CLAMP_A` and `POOL_CLAMP_R`: perform the named real allocation and read,
  then replace the route input with the identical oracle relevant pool while
  keeping weights, route tie/draw, and work fixed.

A pool replay additionally feeds each natural `A` and `R` selected pool through
each frozen route head with common route ties, without another host read. It
separates selected-pool effects from downstream parameter effects. Correct-
selection correlation alone is never called mediation.

`POOL_CLAMP_A` and `POOL_CLAMP_R` must be bit-identical after the clamp. A team
advantage surviving `SEMANTIC_MASK`, a polarity-confined or reversed effect, a
roster-permutation change, a candidate-swap inconsistency, or any residual clamp
contrast is an identification failure. `FORCE_RELEVANT - FORCE_DECOY` is the
controlled selected-payload handoff effect; it supports only a causally active
path for the frozen downstream policy, not exclusive or natural mediation.
