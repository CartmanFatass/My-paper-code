- **Question (planning terms).** On the coupled relay host, when one user cluster relocates mid-mission, how much complete backhauled service (C̄_bh) does the swarm's re-deployment carry — never re-deploying (KEEP), a cold full re-plan, a warm re-plan that holds the four unaffected sites — and how much room above the best ordinary rule does per-UAV departure timing (the learner's own KEEP/GO action space) leave? Consequence: whether the untied-K line (round-3 memo C4, "blocked: no cheap host with exogenous events") gets a host. No learner is declared by this entry.
- **Host (DM rule-2 judgment, folded into the Pro review).** `EventCoupledRelayHost(CoupledRelayHost)` in `experiments/candidates/coupled_host_replan_timing/`: identical to the coupled host until the event step t_e; at t_e one of the five clusters is re-drawn by the host's own cluster law (`uav_env.py` 541–555: new centre uniform in the 5 km arena, its 10 users ~ N(centre, 500 m) clipped); all other users unchanged. Event draw per world: `numpy.random.default_rng([world, 3])`, t_e uniform on {150, …, 350}, cluster index uniform on {0, …, 4}; the event is applied inside the subclass `step()` (the planner's `correction` callable must not touch the env). Reported per world: whether the relocated cluster was chain-served (far) or directly served (near) under the pre-event layout.
- **Zero-fit family (full information, deterministic given the world).** KEEP (pre-event targets held); cold SET-now (`search_placement` re-run at t_e on the new users, `assign_targets` from current positions); warm SET (four unaffected sites held; only the UAV(s) serving the relocated cluster — server and, if chain-served, its relay — re-placed by the planner's static evaluator at the same budget; the cold search seeded with the current layout via `extra_candidates` is run as a second warm candidate and the better of the two is the warm rule); departure-subset oracle (under warm SET's new targets, every subset of the six UAVs allowed to depart at t_e, others holding, × departure delay {0, 20, 50} steps for the departing set; the best rollout per world). Straight-line executor unchanged.
- **Readings.** Primary: post-event window C̄_bh (steps t_e..500, clock-aligned) per rule, paired same-world; secondary: all-500 mean, transition-loss steps (post-event steps with C_bh below the pre-event mean), split by far/near events. Stakes: S_switch = warm SET − KEEP; S_cold = warm SET − cold SET-now (layout-discard loss); room = oracle − best ordinary rule. Worlds: dev 1000–1031 first; hold-out 2000–2031 only if dev S_switch ≥ .02 (pre-declared).
- **Rule fixed before the run.** S_switch < .02 (paired SE ≈ .005 on 32 worlds): timing carries no stake on single-event coupled deployment — C4 stays blocked on this host family, the second slot stays open, nothing else bought. S_switch ≥ .02 and room < .03: an ordinary re-deployment reference exists on this host; the learner line is closed at zero fits (no consumer of the reference is claimed). room ≥ .05 (post-event scale): one single-instance anchored fit becomes declarable — declared separately, after `uav_availability_recovery` B01 is read, with information rights fixed (learner sees what the rules see or the oracle dominates it), a non-activation band (learner ≡ anchor on ≥ 95 % of decisions), the TRIED head ancestry (July R30, JDSL, FSD B07) named, cap 2 CPU-h. .03 ≤ room < .05: reported, no fit.
