## 2. Strongest surviving explanation and what changed scientifically

The update from B01 is from a plausible finite-fitting hypothesis to **one favorable observed package comparison**. It is not a change from scalar sufficiency to scalar impossibility.

For a fixed threshold eta and a specified policy/data law, the scalar quantity a baseline seeks can be written

    m_eta(c) = E[f_eta(G) | c].

An unrestricted MSE predictor of that score can represent this conditional expectation. A correctly represented conditional return distribution could recover the same quantity by integrating f_eta against it. This is an idealized comparison of statistical targets, not a claim that the two finite neural procedures coincide. In particular, Q32's finite unsorted midpoint outputs need not form a calibrated distribution, and its arithmetic average of transformed outputs is not an exact integration guarantee. Conditional expectations can exist without the critic context being a sufficient Markov state or containing the policy's entire recurrent history. [S1, strongest null and targets][S1]; [FOUNDATIONS, §§2 and 4][S11].

**The strongest scalar countercase is therefore concrete:** this scalar network may inadequately track a changing conditional W target within 32 batches and 128 updates, while the Q32 procedure happens to produce more useful advantages. A competent scalar score estimator could remove the difference without any need for a full return distribution at execution. A second unchanged pair can test whether the observed package preference survives another training realization; it cannot exclude systematic weakness of this scalar recipe.

One important implementation distinction sharpens that countercase. Q32's baseline explicitly receives the current eta in its output transform, whereas the scalar forward prediction is `b(c)` and must track eta through refitting its targets; eta is not an input to that scalar critic. This is part of the registered package, not new actor-information leakage or an undisclosed protocol violation. It makes moving-threshold adaptation a plausible explanation separate from any claim that distributional representation is intrinsically necessary. Likewise, fitting full G rather than sparse transformed W, different regression losses, output capacity and initialization, imperfect prediction, PPO's nonlinear surrogate and different endogenous trajectories all remain alternatives. The record does not rank their causal contributions. [learner.py, `TailCritic`, `frozen_batch`, `update`][S13]; [S1, baseline table and interpretation][S1].

The new gradient evidence does eliminate one previously plausible specific mechanism. Maximum combined preclip norms are **0.21656954288482666 for SCALAR and 0.1387568861246109 for Q32**, both below .5. Actual clipping-threshold activation therefore cannot explain this pair's advantage. With detached advantages and separate actor/critic networks, it is especially misleading to retain a story in which the critic loss reduced these actor gradients by exhausting the joint clipping threshold. Different losses can still affect critic fitting and later baselines; the observation does not remove those routes, certify critic adequacy or identify representation as the remaining cause. PPO ratio clipping is a different operation and is not ruled out by this norm observation. [S5, gradient norms][S5]; [learner.py, `update`][S13].

The empirical eta is computed from the same finite batch used for the update, the critic is approximate, recurrent replay uses behavior-state chunks, and PPO clips ratios. Accordingly, neither pre-action critic features nor a scalar conditional-expectation argument turns this implementation into an exact or unbiased CVaR-gradient method. Nor does the MARL credit classification prove individual causal-credit identification. The accepted finite CVaR-oriented description is the appropriate one. The intake's attributed A01 primary-paper reading is consistent with this boundary; I did not perform a new paper or novelty search. [S1, common target and exclusions][S1]; [S3, scientific-reading application][S3]; [learner.py, module documentation][S13].
