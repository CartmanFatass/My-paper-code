## Technical conclusion

The complete r03 object is architecturally finite and all nonnumeric data-flow,
information-boundary, comparator, control, analyzer and lifecycle relations can
be constructed. It is **not yet literally construction-bindable without an EM
answer**, because four numerical contracts are not fixed strongly enough to
choose one production implementation without potentially changing the action
law, deterministic control, validity predicate or first-matching result branch:

1. the physical analytic-arithmetic and fixed-effort equality contract;
2. the counter-addressed distribution/inverse-Gamma/action normalization
   contract;
3. the certified global-minimizer and lexicographic-tie contract for
   `ANALYTIC-ONE-STEP`; and
4. the Student critical-quantile and interval-boundary comparison contract.

These are precise preactivity science-bearing questions, not missing-code
findings. Every other missing surface is ordinary CM construction work.

No r03 implementation, native host, candidate loader, registry declaration,
runner, analyzer, checkpoint schema or atomic resume chain currently exists.
The repository's existing
`experiments/candidates/voronoi_quadrature_field_policy/` package is the
superseded `VQFP-B1-MATH-CLOSURE-20260812-04` object. It has a periodic ring,
discrete three-level actions, two learned arms, 12 seeds, 375 updates and a
32-tick serial Python lifecycle. It cannot be promoted, adapted in place or
treated as literal r03 conformance. It is useful only as a repository locator
for isolated Python-oracle patterns.

The shared source-keyed C++ extension/cache and fail-closed production-registry
interfaces are reusable engineering substrate. A later authorized construction
must add a new candidate-local C++17 full host and a new registry identity; it
must not write a serial Python production scaffold. The natural object-supported
lane widths are 32 and 96 during learned collection and 128/256 during
evaluation; width 1 is only a conformance seam. Final worker count must come
from result-blind 1/2/4/8-worker equivalence and resource evidence, not a global
width rule.

With no benchmark and with the analytic-control contract unresolved, the
honest prospective standalone envelope is **45/76/120 experienced
engineer-days** (low/central/high) and, conditionally on a finite certified
analytic solver, **32/142/758 CPU core-hours**. Expected full-panel wall time is
about **6/27/143 hours at eight effective workers** or **3/14/73 hours at
sixteen effective workers**, before host contention. Peak aggregate RSS is
approximately **7/13/25 GiB at eight workers** and **13/25/49 GiB at sixteen**.
Peak scratch is **8/24/64 GiB**, total write/read traffic **15/45/120 GiB**, and
the complete durable result is **3/7/15 GiB**. These are unmeasured planning
estimates, not a lease request. A 30-minute full panel is not supported by any
current evidence; it would require the later benchmark to demonstrate both
the complete recurrent PPO chain and all 1,572,864 certified minimizations at
that aggregate rate.

## Literal comparator and control feasibility

### FERL within FREE

Literal containment is technically realizable with one common actor class and
one scalar arm multiplier. All common tensors, hidden-state equations,
initialization bytes, parameter order, optimizer hyperparameters and input
records are identical. FREE uses multiplier one on `rho`; FERL executes the
same affine residual path and multiplies it by exact zero. The implementation
must ensure FERL residual parameters receive a zero gradient tensor, not
`grad=None`, so matched AdamW slots exist while no nonzero residual gradient or
weight-decay update occurs. With residual weights/output fixed to zero, both
arms must produce the same flattened logits, `pi`, concentration vector,
likelihood, entropy and action for every supplied history and addressed
uniform vector. A nonzero residual bias is a direct strictness witness.

Required later TEST-only proof obligations:

1. tensor/parameter/optimizer schema identity across all three learned arms;
2. residual-zero FERL/FREE bit identity (or the EM-approved numeric identity)
   for hidden state, logits, concentration, likelihood, entropy and action;
3. zero FERL residual gradient and unchanged residual parameters/slots after a
   registered optimizer step;
4. reachable nonzero FREE residual producing a changed conditional law; and
5. equal common initialization bytes within each fixture seed.

### NO_PORT qualification

NO_PORT substitutes `1/N` only at the fixed factor and residual length ports.
The common actor content remains length-free and the common critic still
receives true measure. This is enforceable with separate actor and critic
structs and one audited port mux. Later tests must show that changing true
lengths while holding actor content and `1/N` ports fixed cannot change
NO_PORT evaluation actor output, while changing critic truth during training
can change its value/advantages. It must never be labeled total-measure-free.

### Deterministic controls and reassociation

- EQUAL is a direct native constructor and never calls a policy.
- ANALYTIC is isolated from actor/trainer/future state and returns one current-
  state action plus a certificate. Its finite production realization depends
  on Q3.
- Reassociated lanes use true cells and service but substitute the cyclic
  length association at every actor port. They reuse the corresponding intact
  action-uniform vector and recursively own their own backlog, prior actions
  and GRU state. Tests must reject any tick-after-zero copy from the intact
  lane.

| Array-order independence | Reorder native storage lanes without changing logical address; compare physical records and allocations |
| Effort conservation/nonnegativity | Validate every mode/agent slot and total on boundary and adversarial concentration fixtures |
| RNG identity | Shuffle batch/worker/episode execution order; compare every addressed raw word/distribution output |
