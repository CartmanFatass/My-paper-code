## Current scientific question

Does a verifier-accepted retained receipt bit change an online service action and return relative to
competent reset with an explicit reacquisition path, and does any summary-specific increment survive
an exact same-information primitive-history containing controller?

## Accepted finding

R01 is conclusive only as a deterministic verifier-conditional retained-bit use and
reacquisition-cost lemma.

For every reset-visible state, exact paired content crossing makes either immediate service action
worth zero in expectation. The competent reset oracle therefore uniquely selects `PROBE`, whose
fixed scan and delay costs leave return `1/2`. When authentication, owner lineage, and skill/lease
lineage are all live, the fail-closed rule exposes the retained bit, changes service action under the
paired bit intervention, and returns `1`. The exact live rule-versus-reset advantage is `1/2` in
both the OWNER-labeled and SKILL_LEASE-labeled slices.

Those slices are two gate-coordinate tests of one fully live conjunction, not independent or
additive owner- and lease-value mechanisms. Authentication is fixed live and has no current causal
online-value result.

An exact primitive-history controller receives every verifier input and equal zero-time finite work,
so `pi_raw(H,z)=pi_rule(V(H),z)` reproduces the rule pathwise. No derived-summary, representation,
decoder, learned-abstraction, or dual-lineage algorithm increment survives this containment.

## Strongest support and contradiction

The strongest support is the exact `1` versus `1/2` live contrast against a competent oracle that
cannot fail through inactivity, exploration, optimization, or weak capacity, plus paired bit twins
that force opposite direct actions. The snapshot/content null independently shows that the cloned
final snapshot cannot select immediate service.

The controlling contradiction is that R01 keeps the old receipt bit payoff-correct after either
lineage breaks. An unrestricted return-optimal raw controller can ignore the verifier and return `1`
in a broken cell, while the stipulated fail-closed rule probes and returns `1/2`. Broken cells
therefore establish sensitivity of the programmed acceptance gate, not semantic staleness,
authentication benefit, safety, or optimal rejection. A verifier-emulating raw controller is a
constructive containment witness, not the unrestricted raw optimum.

The strongest surviving simpler explanation is a one-bit cache problem: a hand-written conjunction
controls whether the policy permits a free cache hit, and reset pays a designed reacquisition cost.
The result is useful protocol accounting but not external task or learned-MARL evidence.

## Claim ceiling

In this finite one-decision host, with authentication conditioned live, the specified fail-closed
rule obtains return `1` by using the retained fair bit at the fully live corner, versus the exact
bit-deleted reset optimum `1/2`. Breaking either tested lineage while holding the other live causes
that rule to probe and lowers that rule's return by `1/2`. This establishes gross verifier-
conditional access value for the retained bit under the frozen free-retention/free-verification and
costly-probe law.

It does not show semantic persistence or staleness, optimality of fail-closed rejection, distinct
owner- or lease-lineage value, online authentication value, safety, representation necessity,
learning, MARL, variable membership, variable lifetime, arbitrary-history robustness, UAV value,
cryptographic security, or deployment value.

## Next discriminator

Any successor is a fresh material cycle. The smallest separating object is one matched
live-versus-broken lineage pair with old receipt bit `b_old` and current service bit `b_cur`:
`b_cur=b_old` while the selected lineage remains semantically current, and `b_cur` is conditionally
fresh after the break. `PROBE` reveals `b_cur`. Compare gated retention, equal-content ungated
old-bit use, an unrestricted exact raw-history optimum, and the bit-deleted reset oracle. Only after
that pair identifies semantic currentness should a broader cycle add the full owner-by-lease
factorial, authentication-invalid cells, explicit verification/retention costs, or a separately
measured finite-budget learned comparison.
