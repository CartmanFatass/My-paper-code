### Prospective first comparison — not yet purchased or implemented

**Question and estimand.** With one fixed 256-world training budget, can a consequence-trained
numeric joint scorer N and/or a pretrained typed representation with adapted scorer L-F
select useful complete layouts on independent same-law worlds? Primary package difference
is L-F−N in complete H500 mean C_bh, with each learner's native regret to the finite menu's
best executed alternative and its gain over the training-selected fixed construction.
This is a contextual decision with a closed-loop low executor. There is one high decision
at t0, no learner-dependent subsequent state distribution, no DAgger and no bootstrapped V.
The multi-UAV routing/service coupling remains inside each native consequence.

**Menu constructor, fixed before any future output.** Use `build_candidates` on an isolated
shadow of the reset legal full state, `allow_a2a=True`, private PCG64 seed 0 per world; no
`search_placement`, static evaluator, rollout result or label enters menu selection. Keep
three plain layouts k=4,5,6. For each k=4,5,6 take a relay-subset layout with maximum
`len(served)`; ties use ascending SHA256 of sorted rows serialized as round-trip `.17g`
coordinates. Take a fourth distinct relay layout by the same cardinality/hash rule across
remaining k. Take one flat-subset layout by that rule. De-duplicate exact complete layouts;
fill vacant places from remaining relay, then flat, then plain by the same fixed order,
up to eight. Fewer than eight is represented by a mask, never cloned as extra alternatives.
The construction is a hypothesis for usable menu coverage, not a known competent selector.
No positive-label screening, learned proposal or full-planner winner is inserted.

Each layout is assigned to the actual reset UAV identities once by the existing
min-makespan/min-total-distance permutation routine. Save the six assigned XYZ targets;
those targets, not the display order or a generator role name, are the complete command.
Thus ordinary geometry matching remains an explicit upstream operation; this study does
not learn agent-to-slot matching. Each arm uses identical plans, assignments and low executor.
No static search has been silently amortized away. All geometry/assignment CPU is metered.

**Information and representation.** The canonical record contains initial UAV XYZ (6×3),
user XY (50×2), BS XYZ (3), all assigned plan XYZ (M×6×3), legal mask, and each candidate's
construction slot, kind and k. World/seed IDs, future observations, outcomes, static scores
and source-file paths are excluded. Constants (host law, H500, speed, connection/routing
limits) are the same declared prior for all methods. Use exact round-trip decimal floats
and a lossless parser; N receives the same parsed numbers. Per candidate N concatenates
139 geometry numbers and 14 one-hot metadata values (kind3, k3, construction-slot8), divides
coordinates by 5000, and scores the complete six-UAV layout with a shared
153→256→256→1 GELU MLP (105,473 parameters). Numeric float32 arithmetic versus tokenized
decimal arithmetic is an arm property, not extra observation rights.

L-F receives a deterministic compact table of that entire canonical record. Option strings
are only unique short plan references; all six targets and geometry stay in the state table.
Use `max_len=4096`, `head_max_len=192`, an explicit extension from the root checkpoint's 512
cap, not a claim that its published accuracy transfers. Before labels/fits, a future admitted
technical check must verify the complete table survives tokenization, every option retains
its unique full short reference, and text parses back exactly to the numeric record. Refuse
any truncation/collision/unsupported length; no silent clipping, compression, smaller menu,
quantization or context-cap sweep. This technical uncertainty is still open in B00.
Display order is a fixed hash permutation of the outcome-free canonical record, common to
both arms; retain construction identity when permuting. One reversed-order test read is
predeclared below. No order/renaming generalization claim is bought by this one check.

**Targets, branches and correctness.** For each world and every legal candidate, reset the
same native initial world and execute its assigned targets for all 500 steps. Q_m is mean
C_bh over the complete episode; q=softmax(Q/.02) over legal candidates is a training preference,
not a success probability. Save native contract reward, frontend capacity with path, coverage
series, positions/actions, assignment and identities. There are no stochastic continuation
replicates under this frozen no-shadowing, static law; one full trace is sufficient per
world/candidate. World generation and private k-means RNG are distinct; no fabricated n from
identical suffix repeats. Source/technical verification must confirm no after-reset exogenous
draw has been omitted; if contradicted, return the contract for revision instead of reusing
uncoupled RNG states.

Reconstruction must preserve/reset the full environment state, native RNG, routing/association
caches, counters and target latch, not just positions. Static evaluation always uses a separate
shadow. Neither candidate evaluation nor model extraction may advance the live native branch
or caller's RNG. There is no recurrent learned executor state in this chosen asset. Required
future checks include all-candidate reset identity, candidate-order independence, native target
identity and hold behavior, marker-to-candidate inversion, masked loss, no optimizer/normalizer
updates during evaluation, and weight/feature-cache hash binding. The two learners are not
permitted different hidden fields or candidate masks.

**Training and replication.** Three independent blocks b=1,2,3. Base world seeds
106100000 / 106200000 / 106300000; training offsets 0..255 and test offsets 10000..10127,
no world overlap across blocks/splits. Model/order seeds are base+20001 / base+20002;
N initialization varies by block, L-F starts from the same pinned pretrained scorer in each
block but has its own data and minibatch order. This is three downstream training/world
replications conditional on one pretrained model and one frozen executor, not three
pretraining or skill-bank replications. Host execution has no stochastic tape to replicate.

Both arms use every training candidate label in exactly 64 epochs, batch32, AdamW
(N LR1e-3; L-F scorer LR1e-4; weight decay1e-4), soft CE, final checkpoint only. No model or
temperature search, validation-based selection, data-dependent extension or extra data size.
Each fit has 512 optimizer steps / 16,384 context exposures; six fits total. Frozen Laya
encoder, type embedding, two head layers and act head remain in eval mode. Cache the gathered
M×1024 marker features **after** the frozen two layers, then train only scorer; caching just
the prefix before those layers would change the model. Compare uncached source logits and
the adapter with the original scorer in the paid correctness allowance. Cache use saves
repeated training forwards, not online inference. Initial N/L-F and final N/L-F endpoints
are read on the same test objects, with no extra fit.

**Ordinary comparators and readout.** All receive the same canonical legal information and
candidate plans. Retain (a) uniform choice's exact mean over the executed finite alternatives,
(b) the best construction slot selected only by each block's training mean Q, with fixed
lowest-slot tie rule, (c) same-menu terminal static C_bh with shorter makespan/total-distance
ties, and (d) a fixed travel-aware surrogate
`(1−min(d_max/(30*500),1))*C_static + min(d_max/(30*500),1)*C_initial`, same tie rule.
This surrogate assumes a simple transition shape; it is not a native label. Static C_bh and
the initial state cost M+1 native static queries/world, shared by (c,d) and charged. No outcome
label or trained model is used online by these two rules. Their actual complete outcome comes
from the corresponding already-executed candidate trace. A full 2×3000 planner with the
same host/information/executor is a separate test-only scale/cost reference, not a theorem or
required beating gate. The menu winner is a hindsight reference, never a deployed comparator.

Because the initial choice determines the whole deterministic controller, the saved complete
candidate episodes give exact selected-policy outcome readings. Do not pay duplicate identical
episodes merely to call this closed-loop. Budget a separate 16 complete-episode identity audit
for selected-plan reinsertion and branch/ordering checks. Reverse the candidate display order
once on all 384 test worlds for both models; reuse the same native traces and report output
changes, selected native losses and cost separately, without tuning on this read.

Primary reporting: per-block native L-F−N and each learner's regret, own initial-to-final
change, gain over train-selected fixed slot, static/travel rules, plus all block means and
world-level adverse outcomes. Report native contract-reward/coverage tradeoffs, menu family
counts, candidate duplicates, selected-class concentration, training fit and independent-test
regret. Give paired world uncertainty within each block and the three block effects separately;
n=384 does not replace n=3 fits. No confirmatory claim, significance threshold or result-selected
subgroup is planned.

### 2026-10-01 — Focused review clarifications (same proposed comparison, still zero runs)

The following specifies the draft above where it was incomplete; it adds no fit, native
episode, data budget or scientific arm. Root and its existing ResearchCritic read the actual
343-line draft, rather than only a favorable summary.

**Eligible fixed-rule comparator.** Each fixed construction-slot policy requests its slot;
if that slot is absent after de-duplication, it executes the smallest legal construction slot.
Compute its training mean over **every** training world using this same complete fallback
policy. Select the largest training mean, ties by the requested slot number, and deploy that
unchanged rule on every test world. Never average only worlds where a slot happened to exist,
drop a world, or select the fallback after reading test outcomes. The menu's layout hash and
de-duplication use canonically sorted XYZ rows; sort before ordinary matching so row-order
aliases do not buy duplicate plans. Metadata records each resulting construction slot.

**Full-planner identity and extra query.** On each of the 384 test worlds call the unchanged
`menus.compute_menu(world, area_size=5000, budget=3000)`: flat search with A2A disabled and
private PCG64(world), then relay search with A2A enabled, a fresh PCG64(world), and the flat
result as the `flat_result_incumbent`. Always execute the returned relay placement using the
saved reset positions and its ordinary min-makespan assignment, once for H500. There is no
hindsight choice between flat/relay outcomes, raw menus or test panels. Its source ranks the
contract reward, so it is a declared scale reference; the primary matched-menu comparator
ranks static C_bh to match the learned target. `compute_menu` also calls `static_evaluate`
once after searching for routing metadata. Therefore pay **384 additional static queries**:
full reference ≤2,304,384, and together with the ≤10,368 same-menu queries,
**≤2,314,752 static calls**. Native steps remain ≤4,808,000. Native resets, k-means/range
computations, matching, record serialization and all wall/process costs are metered; those
are not silently equated with the primitive-step count or excluded from the CPU ceiling.

**Reader boundary and additional scorer bill.** The 1,552 full Laya representation passes
already include the ≤16 correctness passes; there are **zero additional full Laya forwards
and zero fit replays purchased for the complete reader**. It independently parses the raw
native series, re-forms every Q and soft target, checks split/order/source identities, and
reconstructs decisions and losses from stored initial/final weights plus cached post-head
marker features (L-F) or canonical numeric inputs (N). In addition to the runner's endpoint
scoring already listed, budget the reader **2,688 context scorer evaluations per arm**:
768 training contexts × initial/final =1,536, plus384 test contexts × initial/final/reversed
final =1,152. Thus **5,376 extra scorer evaluations**, no native steps. Also read the full
512-update chain per fit, minibatch exposure manifests, loss/gradient/parameter-change
records, endpoint optimizer state and frozen-component hashes. These checks reconstruct
saved learning evidence; they do not independently replay Adam or reproduce every frozen
representation. Upstream representation correctness relies on pinned source/checkpoint,
input/cache hashes and the explicitly priced adapter/source agreement checks. That reliance
is a limitation, not a claim of independently repeating all model computation. Any later
request for full replay would need its real extra bill.

Use **float32** marker caches without additional storage quantization, so their ceiling is
**50,855,936 bytes (about50.9MB)** at 1,552×8×1024×4; this supersedes the25.5MB forecast above.
