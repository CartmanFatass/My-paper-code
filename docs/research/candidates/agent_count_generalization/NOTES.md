#### 1. 最强异议：原生 R、适配器 r 和报告 J 现在没有被正确区分

这里存在可以沿源码逐步核对的事实，不只是一般性的“注意 reward scaling”：

`scenario1._compute_reward` 产生团队原生奖励 `R = .7*C + .3*Q - P`，其中 `P = .1*normalized_height`；`MultiUAVEnv.step` 给每个成员的是 `R/N`；`ParallelToArrayAdapter.step` 对成员奖励再取均值，因此返回的 scalar 是 **r = R/N**。S1 子类的 `step` 只补充信息，没有把它恢复为 R。故笔记“adapter returns the shared global reward”若指上述原生公式的单位，是错误的；正确说法是“共享给学习器的 scalar，其数值为原生团队奖励除以 N”。[S1 reward/step][ac-s1]；[原环境 step][ac-env]；[数组适配器 step][ac-adapter]。

B01 的复用代码已经区分两者：`collect_training` 原样存入 scalar，并明确不把报告因子乘进 learner；`evaluate_panel` 则用 `shared.N_UAVS * returns / horizon` 得到 native J。因此，不能只复制它的 evaluator，再把 `shared.N_UAVS` 留成训练数量 6。[B01 collect_training / evaluate_panel][ac-b01]。

**我建议的最小修改是保留继承的训练数值路径，同时纠正新实验的定义和报告：** N=6 训练时，两臂外在学习奖励都明确为 `r_train = R/6`，H6 的内在奖励系数另行明确保留；测试主指标定义为

\[
J_{a,s,n}=\frac{1}{500}\sum_{t=1}^{500}R_t
=\frac{n}{500}\sum_{t=1}^{500}r_t
=.7\bar C+.3\bar Q-\bar P.
\]

这里 n 必须来自该测试环境的实际 roster，P 已包含 .1，不能再乘一次 .1。用同一条轨迹上的 scalar 与原生分量核对这个恒等式即可，不需要额外性能实验。`reward_info` 用来计分，不因此变成 actor 输入。

直接平均 adapter scalar，会把各 N 的包效应变成 `Delta_n/n`；再平均 N=4/8 就改变了 unseen summary 的权重。错误地统一乘 6，则 N=4 被放大到真实 J 的 1.5 倍，N=8 缩小到 .75 倍。虽然同一 N 内简单正比例变换不改效应符号，量级、分量核对、跨 N 汇总与实用判断都被改了。

不要以“修复单位”为名悄悄把训练奖励乘回 6：它会改变 H6 内在/外在奖励比例及有限优化条件，不是原学习过程的无害重命名。DM 可以事先选择以 R 训练两臂，但那必须成为明确的新配置，而不是声称沿用 B01 的相同数值语义。背景 topic 4 对“固定策略排序不变”和“有限训练不变”的区分，正适用于这里。[背景 topic 4][ac-bg]。

#### 3. SET 的必要竞争力：不把 mean/max 先验判弱，也不把同信息说成同表示

按提案，SET 不是旧 CF 的 N=6 巨型展平输入，也不是只看局部观测的弱 flat：每个实际 joint-observation 行先经非线性共享编码，再做 mean/max，附 count 和 ego 信息，另保留声明的全局状态内容及每步自身观测，最后由共享 GRU/PPO 学动作。**这可以是有竞争力的普通首要对照；目前没有已经实现的 SET 或学习结果，足以证明它存在必须换成 attention 的实质缺陷。** mean/max 是有限表示压缩，不是自动充分；“具备普通合理结构”也不等于已经验证训练合格。[方案][ac-q]；[背景 topics 3/4][ac-bg]。

最强的可操作异议是：H6 的每成员查询、保留的有序 token 和 AR 前缀，可以针对不同 UAV 选择不同关系；SET 若在接收 ego 条件前把所有关系压进同一短摘要，可能使有限训练更难区分“我的位置与哪些成员/用户形成服务冲突”。非线性编码前就平均原始坐标、丢掉 count、没有当前/快照 ego 的对应关系，或者根本不给这个编码器梯度，都是应直接修正的可避免弱化；但提案已经包含非线性行编码、count 和 ego，不能把上述弱化当成已经发生的事实。

**同一信息权限内，我认为最有力、改动仍相对小的普通替代是 ego-query attention 的共享 recurrent PPO**：在十步刷新时，用对应 ego 的观测/位置查询实际 joint-observation token 和声明的状态表示，产生每个 ego 的连续摘要；其余步只使用 held 摘要与当前局部观测。没有 discovery、技能选择或新信息来源，参数维度不依赖 N。它比单一全队池化摘要更直接地表达接收者相关关系，但也改变容量和优化工作，不能宣称未经测量就经验上最强。

若进一步要匹配 H6 的联合随机选择能力，普通 AR 联合动作/消息策略也是强参照；不过保留现有十步中央信息边界、逐步动作接口并实现其联合概率回放，会多出另一套优化契约。**本次是完整包购买，不是 AR/相关探索的组件识别，因此我不建议为了形式对称同时加入它。** 从共享信息生成不同成员的确定性动作，并不必然要求 AR；SET 的分解动作噪声和 H6 的有序离散相关选择有差别，但这个差别可以诚实留在包定义中。[SkillCoordinator/SkillDecoder][ac-net]；[Comparators][ac-sci]。

我的具体选择是先保留提议的 SET，不加架构扫描；确保 ego 能合法对应到自己的 held 行，汇聚确实作用于逐行非线性特征，且 actor 编码器在学。若实现检查发现不可恢复的对应关系丢失，先修对应关系；若原生结果与可复现的表示诊断共同指向 receiver-specific 关系压缩，再把上述 attention 作为一个有新预测、另计曝光的改版，而不是事后挑最好 baseline。

最终可读作“在同一外生信息权利、训练 N、team-step 曝光和声明资源设置下，H6 包相对 SET 包的服务得失”。不能读作层次结构、技能数、AR、count 编码任一组件的因果效果，更不能称计算量精确匹配。H6 通过技能传给低层，SET 得到连续 held 中央特征；256 hidden 只匹配一个宽度，不匹配总参数、带宽、优化器次数或搜索工作。[方案][ac-q]；[constitution §8][ac-gov]。

#### 4. 最小 N 适配成立的具体条件：改执行边界，不建通用框架

**共享 state-set 表示、共享高层 agent value head、每个 N 单独的固定规模 runtime，是可辩护的最小方案。** 源码低层参数共享可复用，真正固定 N 的部分包括 state 线性投影、`ModuleList[N]` value heads、旧 CF 的 `state_dim+N*obs_dim+N` 输入，以及 runtime/buffer 数组。没有理由为了只在 N=6 训练就预先改成混合 N replay。[networks][ac-net]；[agent 构造与中央快照][ac-agent]；[RolloutBuffer][ac-buffer]。

**身份、count 和 padding。** 实际 `uav_i`、联合观测行、动作行、技能行和 GRU 行必须一直指向同一个回合内成员；局部 SINR 排序的 peer/user slot 不是这个身份。不要从 `state/info` 给 114 维局部观测补真值 mask 或持久 ID。实际 roster 数量与中央状态存储的 validity 是合法接口事实，不是环境结果泄漏；但只有 N=6 的训练不能识别任意 count-response 函数。即使 count 明示，N=4/8 的响应仍是待测外推，不是已学会计数泛化的证明。[原生 state/observation][ac-env]；[背景 topic 3][ac-bg]。

固定容量 8 可以只用于原始状态存储。不要把补齐后的 UAV slot 和 mask 原样展平接入带逐槽权重的全连接层，再称它为共享 set。先用共享权重处理真实 UAV，mean 的分母是实际 N，max 排除无效项；只把 pad 置零并不够，因为 `phi(0)` 可以有 bias，且零会压过负的真实特征。跨实体的统计或 attention 也不能让 pad 参与。检查改变无效存储值、无效位置不影响输出；有真实成员位置为零时不能误屏蔽。count 用固定的已声明尺度（例如 N/8），不能在测试 N 重估统计；尤其不要沿用训练时永远为 padding 的第七/八槽 running mean/variance。

**尺度与信息内容。** 用实际 S1 环境参数进行 x/y 与用户位置除以 area_size、z 减下界后除高度跨度；时间已有归一化。114 维中的相对坐标、自身坐标及 SINR 已按原生方式处理，不能把 SINR 当“距离”再缩放，也不能把已归一化局部坐标再除一次 area_size。`Config` 的通用环境默认值不等于 `_make_envs` 构造的 S1 实值。全 50 用户位置保持原声明；不因为 UAV set 适配顺手改变用户信息或增加服务结果字段。[S1 constructor][ac-s1]；[observation 实现][ac-env]；[配置][ac-cfg]；[E0 _make_envs][ac-e0]。

**H6 的共享 head 和顺序外推。** 一个真实共享的 `nn.Module` 应覆盖 `get_value`、`assign_and_value_batch`、`evaluate_training_batch` 等实际 off 路径；不要仅在 acting 改 head，而训练仍索引旧列表，也不要用长度随 N 改变的 ModuleList 别名伪装参数共享。当前高层有固定正弦位置编码，AR 参数本身可随运行长度复用；但 N=8 的新增位置、较长前缀和注意力归一化分布未在 N=6 学习中见过。保留它是可测试的包选择，不是 permutation-invariant 结论。state-set 子模块的排列不变性与完整有序 H6 的性质应分别检查，不能要求整个旧 AR 包通过它本不承诺的无序等价测试。[SkillCoordinator/SkillDecoder][ac-net]。

**新增编码器必须被真正训练。** `HMASDAgent.__init__` 构造模块后建立 Adam；`SkillDiscoverer.actor_update_parameters()`/`critic_update_parameters()` 明确枚举已有模块。后来挂上一个 set encoder，并不保证这些优化器包含它。将每个角色的编码器注册到正确模块/参数列表，核对梯度、实际 optimizer membership、step 和相对初始化的运动；不能以全模型某个参数变了，代替 SET actor set encoder 或 H6 state encoder 在学的证据。角色间、两臂间是架构/特征契约共用，不是训练权重共用。[agent 构造][ac-agent]；[SkillDiscoverer 参数枚举][ac-net]。

**held snapshot 和回放。** 储存实际读取的原始十步快照及 ego 对应关系，在 PPO 中由当前可学习编码器重算特征；别只存 detached feature，导致中央编码器永远没有策略梯度，也别用当前或未来联合观测替代当时 held 输入。acting/replay/eval 必须同一缩放、同一快照年龄。`apply_algorithm_config('mappo')` 会把 k 改成 rollout_length+1，而既有 B01 已明确改回 `FLAT_K=10`，因为 k 还控制 recurrent chunk length。复用这一修正；把恒定技能、十步信息刷新、十步 BPTT 的语义分别说清，不把 MAPPO 的默认长 k 偷带进 SET。[baseline switch][ac-base]；[B01 make_config][ac-b01]；[agent snapshot 存储/回放][ac-agent]；[RolloutBuffer][ac-buffer]。

**runtime、终止和测试隔离。** N=4/6/8 使用真实 N 行，不补不存在的 policy/action/loss 行；加载同一拟合模型全部所需权重，严格核对参数 keys/shapes，不用 `strict=False` 悄悄跳过 N 不兼容项或给 N=8 新建随机 head。不要把训练 buffer 或 N=6 的 per-agent hidden 搬到新 runtime；重置 episode 的 actor/critic GRU、技能、timer、snapshot，并冻结训练得到的 normalizer。十步重选不等于清空回合内 GRU。当前 `evaluate_sequence` 已将 transition done 移一行用于 RNN entry mask，应保留这一正确语义；终止转移先存原 terminal next state/obs，再 reset，不能把新回合初值当 terminal 后继。该 S1 把 500 步终点标为 termination，复用 B01 完整回合的零 bootstrap，不悄悄改成 time-limit bootstrap。测试保持零 optimizer/normalizer 更新，独立 runtime 构造与评估不消耗训练 RNG。[evaluate_sequence][ac-net]；[原环境 step][ac-env]；[B01 collector][ac-b01]；[E0 Evaluator][ac-e0]。

这些是本次改动对应的定点检查，不是一套新认证阶梯；没有要求先出现正性能。它们若能在 experimental package 中通过小的 wrapper/模块替换实现，就不值得改 shared core 或重建通用 evaluator。若实际依赖迫使更改多条共享学习语义、无法可靠追踪 encoder 梯度和快照，工程成本才会成为拒绝本次购买的具体理由。已有独立 Reviewer 和实际节点准入照常适用，不添加 adviser 许可。[engineering 的 Core versus experimental、Checks][ac-eng]。

#### 5. 购买建议：默认六 fit；两 fit 是降低问题目标的替代，不是必经门槛

**我建议保留 H6 的 914201/914307/914413 与 SET 的 915201/915307/915413，各 360k team steps，六 fit 一次预写为探索性比较。** 理由不是已有正效应值得确认，而是题目明确购买独立训练差异；每臂一次训练无法回答它。适配器的共同实现成本也不会因只跑一次/臂而消失。三次/臂给出有限的训练结果分散性，不自动达到精确估计或确认性证据。[方案成本][ac-q]；[constitution §§3、8][ac-gov]；[Statistics/Cost][ac-sci]。

| 方案 | 训练 team steps | 评估 team steps | 合计 | 实际购买到什么 |
| --- | ---: | ---: | ---: | --- |
| 6 fits，3/臂，360k/fit | 2,160,000 | 576,000 | 2,736,000 | 首张具有独立训练分散性的 N=4/6/8 服务表 |
| 2 fits，1/臂，360k/fit | 720,000 | 192,000 | 912,000 | 单次实现/学习轨迹、成本和失效筛查；不能估训练变异 |

上表按原提案四个 panel、三个 N、16 worlds、500 steps 计算，包含初始化评估；差额四 fits 为 1,824,000 team steps。team steps 不等于 agent rows、优化器工作或 wall。H6 还有高层编码/AR、discriminator 和不同样本组织；应明确实际 `coordinator_batch_size`、PPO epochs/minibatches、低层 chunk、判别器训练安排及全部优化器工作，而不是从旧 D1280 名称或“相同 256”推断计算匹配。具体 batch/配置绑定在原有 prospective note 中即可，不增加扫描。[Config][ac-cfg]；[agent update 路径][ac-agent]；[Cost][ac-sci]。

**360k 是所选有限资源终点，不是已证充分的技能训练时长。** 保留初始化、120k、240k、360k 的曲线、完整原生分量和 module movement；只在最终 checkpoint 作主比较，不按最佳 checkpoint 排名。初始化 native service 或绝对 floor 不是学习证据；相反，技术有效、确有参数更新而最终不占优，可以是不利的有限预算包证据，即使曲线仍未收敛。不得看分数后把这批悄悄延长。

真实 wall、内存和优化成本现在仍未知，不能引用历史 FSD wall 当本次测量。若普通实现检查或实际节点条件表明六 fit 的代价明显不值得，我接受改选两 fit：H6=914201、SET=915201、同样完整 360k horizon、其余评估不变，且在执行前改写其目的为原生探索性筛查。它最多支持“这两次训练发生了什么、成本是否可接受、是否发现具体失效”，不能支持稳定排名、训练总体增益或等价。之后买更多训练，需要一个新的 prospective 投资理由并保留此前选择曝光；不是自动补四次，也不是强制重跑两次后才能进入六次。[constitution §3][ac-gov]；[Explore/Cost][ac-sci]。

执行安排继续优先 `wsl_4070`、CPU FP32 按实际节点资源选择声明的拓扑；以前 SSH 可达不等于现在已准入或预留资源。这里只是成本建议，不启动任何 fit，不更改暂停/冻结对象。[当前 owner 指令][ac-bg]。

统计上，先给出每个 `(arm, training seed, N)` 的最终 J/分量/status，再在每个 N 汇总三个独立 fits。可报告基于 fit 均值的训练分散性及明确假设的小样本不确定性；仅按 fits 计算的误差是对所用有限世界面板条件化的，不能把 16 worlds 当作 16 个新训练实例。要描述世界抽样不确定性，另外保留跨臂共用世界的结构。计算 unseen summary 时，先在同一 fit 内取 `(J_4+J_8)/2`，再跨 fits 作臂差，保留同一训练实例跨 N 的相关性；不能把三个 N 当成更多独立训练样本。缺失/失败 fit 不填零、不静默替换，相关比较标明不完整。无显著性不是等价；三次训练也不保证窄区间。四个 fresh panel 的不同世界不能冒称逐世界配对的初始化到终点进步。[背景 topic 6][ac-bg]；[Statistics][ac-sci]。

#### 6. 结果改变哪一项决定，而不是自动续跑

| 可见观察 | 判断变化与有用分支 |
| --- | --- |
| 两个 unseen N 均有同向、有实际服务意义的优势，N=6 服务未见重要代价，且不是由单 fit/少数世界独占 | **retain** 这个有界包及其完整成本；支持为具体用途另行选择下一比较，不认领层次结构因果效果或普遍 N 定理。 |
| 仅 N=6 占优，N=4/8 无有用增量或不利 | 削弱本次包的 count-transfer 理由。只在有具体可改链接和不同预测时 **revise**；不能靠训练内增益包装成迁移成功。 |
| unseen 增益伴随 N=6 重要损失，或 N=4/8 效应相反 | 明示取舍，保留逐 N 表；默认等权 U 不能替使用需求消除损失。不因汇总正值自动 retain。 |
| 两臂真正学习、SET 原生服务正常，而 H6 在声明预算下没有值得成本的增量 | 优先保留普通 SET，**stop 所测 H6 配方的当前投入**。这是包/资源条件的判断，不是否定全部技能、历史信息或 N 研究。 |
| 编码器不更新、错误奖励换算、checkpoint 部分加载、snapshot 泄漏、终止/重置损坏，或缺失 fit | 技术缺陷或不完整比较；隔离依赖的主张，报告成本与可保留事实。具体修复由 DM 判断，不把失败当科学阴性，也不自动重跑。 |
| 原生适配实际需要不成比例的重写，或实测完整成本使下一观察不值得 | **stop 依赖的实现/运行投资**；可另选更直接的普通 shared/set 学习问题或更小技能包，但它是改变问题，不是完成了原 H6 对照，也不以 toy 替代 S1 证据。 |

因此，当前被**加强**的是“单训练 N 的原生包比较可有明确含义，且没有必要先建混合 N 框架”；被**削弱/纠正**的是“奖励单位已完整核实”以及“接口 shape 成立即等于学习/迁移契约成立”。**仍未决**的是 SET 与 H6 的实际学习能力、unseen/retention 得失、三 fits 的分散性与精度、真实接口工程负担及训练/评估 wall；源码不能回答这些经验问题。
