## Goal, value and completion meaning

Construct the one exact native-first TBCFV package and measure the complete
engineering chain well enough to decide, in a later and separate Portfolio
action, whether an empirical panel merits identities, coordinates and a
heavy-compute lease. The construction is valuable because the frozen assay can
separate target-bound common-persistent value from a competent strict-containing
controller and can narrow any value to churn specificity, physical
fragmentation, commonality and persistence. The repository currently lacks the
exact native host, loader, ABI, supported-width contract and target-specific
measurements needed to price or admit that later panel.

Completion means a same-direction CM has technically accepted the constructed
surfaces, their native/reference and model/package conformance, the atomic
lifecycle, and a result-blind full-chain benchmark with a measured projection
of remaining complete-panel cost. Completion is not a successful scientific
outcome, an empirical admission, a run identity, a coordinate freeze or a
lease request.

## Authorized construction scope

### 1. Target-specific native host

Build a new candidate-local C++ batched reset/step/terminal host implementing
the exact r04 physical law. It must cover roster expansion and contraction,
physical-survivor state continuity, newcomer state, epoch offsets, beacon and
demand motion, simultaneous claims, deterministic movement, service
accumulation, terminal behavior and malformed lifecycle calls. It must expose
only the state needed by the frozen public observation and diagnostics; an
internal physical-agent key may maintain survivor continuity but must never
become an actor-visible ID or fixed roster slot.

### 2. Deterministic TEST-only Python reference oracle

Build a deterministic Python reference oracle solely for hand-written fixtures,
native/reference equivalence and benchmark validation. Python is never a
production environment, implicit fallback or alternate runtime. Unknown or
unavailable native components must fail closed. Fixture inputs must be fixed,
non-scientific and result-blind; they must not draw, execute or inspect a future
science-level initial position, roster event, epoch offset, latent/noise bank,
training scenario, evaluation scenario, initialization or coordinate.

### 3. Loader, ABI and fail-closed shared declaration

Freeze and implement a source-keyed candidate loader and cache identity; an
exact ABI/size/dtype/layout/lifecycle contract; malformed-input and unsupported-
width behavior; cold-load, warm-load and warm-reuse behavior; and explicit
source/version invalidation. Operational Root must separately assign the
shared registry declaration and fail-closed policy tests to the proper shared
component owner. The direction CM owns the candidate-local host and integration,
not the shared registry scope.

The shared declaration must name a new exact capability. It may not alias,
reinterpret or silently extend `continuous_roster.toy`, which remains a
different partial hot path. No implicit `python_reference` component is
permitted.

### 4. Batch widths and equivalence

Measure widths `1`, `8` and `32` wherever the accepted ABI supports them. A
width may be declared unsupported only with a fail-closed contract and concrete
technical evidence; do not substitute scalar Python or silently change the
natural 64-episode update block. Native/reference equality or a prospectively
justified exact tolerance must cover reset, every step, event ordering,
terminal state, physical observables and batched-vs-scalar-order behavior.

### 5. Five learned package conformance

Construct the shared maximum model surface and all five exact packages:

- `C1P1-COMMON-PERSISTENT`;
- `FLEX-REKEY`;
- `C1P0-COMMON-REFRESH`;
- `C0P1-PRIVATE-PERSISTENT`; and

Conformance must establish exactly 26,161 learned scalars per arm; shared
set-encoder and pointer behavior across roster sizes; the stopped Normal plan
sample, score-density path, actor path and deterministic FLEX-head gradient
and detach boundaries; unused-draw no-path behavior; and the frozen draw-tying
and renewal laws. C0P1 must transport a private plan only with its physical
survivor and give a newcomer the registered entry draw without exposing a
successor ID.

The containment fixture must show exact treatment/FLEX policy identity when
both FLEX final event-update layers are zero. A separate output-connected
strict-extension fixture must use a nonzero common update and unequal
agent-specific updates for distinct physical features to change at least one
FLEX six-way claim distribution while the treatment distribution is unchanged.
Deterministic fixture tensors are permitted; they are not scientific
initializations, learned models or checkpoints and must not be used for
selection.
