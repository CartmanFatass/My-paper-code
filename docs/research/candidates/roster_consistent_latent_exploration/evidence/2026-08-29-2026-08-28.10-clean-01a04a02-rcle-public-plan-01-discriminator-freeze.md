## Total public state and clock law

The current roster is an unordered set of physical entities. An internal
entity key exists only to evolve a survivor's physical position, previous
claim, displacement, and RNG tape. It is never a policy, manager, critic,
scripted-objective, or inference feature.

At every claim clock, before observation construction, every current entity is
assigned one fresh public tie mark `rho in (0,1)`. Marks are independent across
entities and claim clocks, paired across packages on a common scenario, and
discarded after that claim. Public angular order is the lexicographic order of
`(current sector,rho)`. This is total almost surely, reconstructible by every
agent from the public current set, and cannot carry a persistent roster label.

The complete current-agent public element is:

```text
(sin(position), cos(position),
 previous-claim sin, previous-claim cos,
 newcomer flag, 2*rho-1).
```

The previous-claim vector is `(0,0)` at episode start and for a newcomer at its
first claim. Otherwise it is the unit-circle encoding of that survivor's claim
from the preceding claim clock. It is public action history available
identically to learned and scripted packages. The own-agent features are own
position, public angular rank, previous physical displacement, newcomer flag,
own previous-claim vector, and own tie mark.

At `t=20`, the exact order is:

1. in a churn cell, apply the exogenous departure/arrival mutation; in a
   static cell, make no roster mutation;
2. set newcomer previous displacement and previous claim to zero; remove all
   departed state; retain survivor position, displacement, and previous claim;
3. set `roster_event=1` only for a churn cell at this claim and zero otherwise;
   set `post_boundary=1` at and after `t=20` in every cell;
4. draw the fresh current-roster public tie marks and construct the public
   state;
5. only in a churn cell, apply the package's authorized plan-event law;
6. sample or compute claims for the current roster;
7. move every current entity once, then compute service and diagnostics.

`FLEX-EVENT` never applies an event update in a static cell. No pulse is
visible before `t=20`; the event pulse is zero again after the `t=20` claim.

## Exact maximum learned architecture

Both learned arms allocate the same 26,545-scalar `float64` tensor inventory.
Every hidden activation is `tanh`; every affine layer has a bias.

- A six-feature public agent element is encoded by `6-32-32` and mean pooled.
- A beacon element `(sin(q),cos(q),d_j/3)` is encoded separately by
  `3-32-32` and mean pooled.
- The 64 pooled features concatenate with `(N/10,t/56,roster_event,
  post_boundary)` to a 68-feature public summary.
- The manager is `68-64-64`, followed by separate `64-4` affine Normal mean
  and raw-scale heads. `log_scale=-2+2*sigmoid(raw_scale)`.
- The four-beacon pointer applies one shared `84-64-64-1` score MLP to each
  candidate. Its 84 inputs are the 64 pooled features; eight own physical
  features; normalized `N`, time, event and post-boundary flags; candidate
  beacon sine/cosine, demand and signed circular distance; and the
  four-dimensional plan.
- The common event update is `72-32-4` over old plan plus public summary. The
  agent update is `84-32-4` over old plan, public summary, eight own physical
  features, and four-dimensional fresh standard-Normal event noise.

Every affine weight, including manager mean/raw-scale heads and the pointer
output, is independently initialized by

```text
Uniform[-sqrt(6/(fan_in+fan_out)), +sqrt(6/(fan_in+fan_out))].
```

except that the two event-update output matrices are exactly zero. Every
affine bias, including both event-update output biases, is exactly zero. The
complete common initial tensor is copied across KEEP and FLEX within a root.
The event hidden layers are live, and a non-result fixture must prove both
exact zero-head containment and an output-changing, gradient-connected strict
extension.

Every input encoding is exact. Sector position `x` uses
`(sin(2*pi*x/80),cos(2*pi*x/80))`. Previous claim `j` uses
`(sin(2*pi*j/4),cos(2*pi*j/4))`; the no-previous-claim sentinel is `(0,0)`.
Newcomer/event/post-boundary flags are `0` or `1`. The public tie feature is
`2*rho-1`. Angular rank is divided by `max(N-1,1)`. Signed previous physical
displacement is clockwise-positive in `[-3,3]` and divided by three. `N` is
divided by ten and `t` by 56. Candidate demand is divided by three. Candidate
signed circular distance is the shortest clockwise-positive displacement in
`[-40,40]`, with an exact 40-sector tie set to `+40`, and is divided by 40.

## Exact learned laws

`KEEP-COMMON` draws one four-dimensional plan from the episode-start public
manager, broadcasts it, and carries it unchanged through churn to survivors
and newcomers. `FLEX-EVENT` uses the same pre-event law and, only at churn,
forms

```text
z_i^+ = z + Delta_common(z,g_event)
          + Delta_agent(z,g_event,o_i,eta_i).
```

Plans are stopped actor inputs. A Normal plan draw trains only through its
registered log density. Event noise has no learned density term; FLEX updates
train through downstream claim log probabilities.

Each arm/root receives 256 update blocks. A block contains 32 complete
episodes, exactly eight from each training cell. For episode `b`, let

```text
ell_z(b) = mean log density over every used plan draw
ell_a(b) = mean log probability over every active-agent claim
ell(b) = ell_z(b) + ell_a(b)
L = -(1/32) * sum_b stop(Y_b - beta_(arm,cell(b))) * ell(b).
```

Every cell baseline begins at zero. Only after the joint parameter update,

```text
beta_(arm,cell) <- 0.95*beta_(arm,cell)
                   + 0.05*mean_cell(Y).
```

For the complete allocated tensor,

```text
g_update = 0                         if ||g_raw||_2 = 0
g_update = 0.05*g_raw/||g_raw||_2   otherwise
theta <- theta - 0.01*g_update.
```

Thus every nonzero whole-tensor update has norm `0.0005`. There is no critic,
entropy term, shaping, latent agreement, reconstruction, pathwise plan
gradient, momentum, weight decay, clipping, replay, curriculum, early stop,
restart, seed replacement, sweep, or checkpoint choice. The only checkpoint
is block 256.

Training and evaluation actions are sampled by inverse CDF from the registered
categorical distribution. Evaluation is not argmax. Common scenario variables,
initial common tensors, manager uniforms, and action uniforms are paired where
their semantic physical entity/tick/candidate meanings align; different
conditional probabilities may map the common uniform to different actions.

## Scripted stage and physical-hysteresis discriminator

At a claim clock, expand demand into ordered beacon service slots. For each
current entity and candidate beacon, simulate the common decoder for the four
physical ticks governed by that claim and count the number of ticks the entity
would remain outside service radius two. This public four-tick service-delay
cost is the horizon-aware matching cost.

`CARRY-COHERENT` and `REPLAN-COHERENT` are identical before the `t=20`
boundary. At the boundary, they receive cloned, byte-equal public physical
state, previous claims, future beacon/demand law, and tie marks.

- `CARRY-COHERENT` chooses a complete exact-demand assignment by minimizing,
  in order: number of survivor claim changes; total four-tick service-delay
  cost; the lexicographic service-slot vector under current public angular
  order.
- `REPLAN-COHERENT` chooses from the same assignments by minimizing, in order:
  total four-tick service-delay cost; number of survivor claim changes; the
  same lexicographic vector.

Both laws repeat their priority order at later claims. A newcomer and an
episode-start entity have zero change cost. Both use only common public state,
maintain exact claim counts, use the same decoder, and can choose the same
assignment. Their difference is whether prior public assignment convention has
priority after conditioning on current physical state and the known short
horizon.

`FRAGMENTED` is identical to CARRY before the event. At the claims at `t=20`
and `t=24` in a churn cell, it first computes CARRY and then moves the first
public-order claimant of beacon 1 to beacon 0 and the first claimant of beacon
3 to beacon 2. It therefore creates two claim shortfalls and two excesses when
every beacon has positive demand. At all other claims it uses CARRY.

`NEAREST` independently claims the nearest current beacon, breaking an exact
distance tie by lower beacon index and ignoring demand and other agents.

Every scripted package is evaluated on all four held-out cells for 512 paired
scenarios per root. The event-state bytes immediately before the CARRY/REPLAN
fork must hash identically. Scripted policies are never trained.

## Evaluation-only event clamp

the block-256 FLEX checkpoint on the two held-out churn cells and the same

- natural FLEX versus clamped FLEX localizes harm from applying the learned

## Simultaneous inference

For every registered root quantity `x` over sixteen independent roots,

```text
x_bar = (1/16)*sum_s x_s
s_x^2 = (1/15)*sum_s (x_s-x_bar)^2
L(x) = x_bar - 3.89747369134303*s_x/4
U(x) = x_bar + 3.89747369134303*s_x/4.
```
