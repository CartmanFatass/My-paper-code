## 3. 建议新增：可选择的有限方向任务包

这是一项**未来授权形式的建议**。需要适当 authority 正式采用，并由 Portfolio
在确有投资问题时选择是否给该方向任务包；本稿不授予 MGTAP 任何新任务包。

任务包只需在原有投资决定里写明：被接受的机制/问题族、可用证据类与 claim ceiling、
允许的宿主和比较范围、最多结果性 invocation/独立训练单位、分臂与完整总 cap、
适用期限或明确终止事件。数值由真实投资决定给出；未知单位成本继续写 UNKNOWN。
这不是每次启动新增一张通用审批表，也不要求先做成本实验。

在这一有限授权内，建议明确授予 DM：

1. 自己定义并选择对象级 A/B、安排已包含的训练单位、选择未绑定且未筛选的 master，
   按对象风险完成工程、收集、intake 和下一 rung；不必让 Portfolio 逐次重复购买。
2. 根据每个结果决定少做、停止某个 arm、结束任务包内某项对象，或使用授权明确允许
   的剩余额度。保持全部不利结果；不能“跑到正值”为止，不能把单 pair 写成稳定优势。
3. 将必要的实现、检查、review、staging、monitor、intake、整合、保留和 cleanup
   一次计入同一授权的完整成本。不得把有限/零 learner 工作自动视为免费，或把支出
   隐藏为另一个不计费的前置 A。实际测不到的部分保留 UNKNOWN，不反推历史合规。
4. 自主维护一两个当前有依据的候选问题和反对理由；这只是研究准备，不自动赋予
   execution budget，也不需要每个草稿再问一次 Pro。

超过任务包总 cap、数量、机制或明确禁止的维度，才产生一次新的投资/方向问题。
若 authority 仍选择 one-pair grant，则 DM 必须尊重 one-pair 边界。8231 就是
已结束的 one-pair grant；本建议不能给它增加一次科学 retry 或重启历史额度。

该方案的收益是减少重复节点调用和等待，使责任落在能读取代码与 primary 的同一 DM。
主要风险是 DM 把范围解释过宽或把消耗分散到多个对象；以原投资决定中有限、可核对的
范围和总数控制，不新增一个逐次报批层。冻结语义、高风险独立 review、fresh admission、
immutable evidence 和 owner 异步干预均保留。

## 4. 避免高频空请求

发起新请求前，DM 只需在已有 card/intake 中讲清：**当前要改变哪项尚未被决定的动作，
与上一完整决定相比新增了什么事实或具体提议，以及哪个 node 有该动作的权限。**
这应是实际内容的几句话，不是新的打分器、阈值、验证器或形式化证明。

- 有现成授权且已就绪：直接干，不发送“是否可以继续”的请求。
- 有完整 Pro 答案：先 intake 并执行其合规部分；短 receipt 或 strict ID 缺失不是
  再问一次的理由。重复通知复用已 intake 的 request/response。
- 同样的输入、选项和后果：复用现有决定。换题名、换日期或将“继续考虑”改叫
  “支持非默认路径”，都不能自动产生新的决策价值。
- 有新且具体的研究动作：DM 可独立形成问题并直接发给正确 node。后果可以是具体
  的研究开发选择，不要求已有部署客户；一个可信 B 信号或有理由的负结果都可支持
  有界后续。不要把 MGTAP 当前的具体缺口推广成全库“先有工作负载/先正向”的条件。
- 找不到这样的动作：一次记录已比较选项、缺失事实及回访条件，发送 ACTIVE-idle
  event 后 native wait。无变化的 timeout 不再读一遍同一记录，不自动追加研究调用、
  审计请求或 PARK 提案。真实的 capacity/lifecycle 问题仍可独立发给 Portfolio。

四方向并行是执行安排，不是每个方向必须持续制造 Pro 请求或训练的配额。研究准备、
工程修复、等待已接受结果和 ACTIVE-idle 应如实区分；只有正式 disposition 才释放槽位。

## 5. 一次性审计回报

复用现有 card → execution/result → intake 和 audit/owner surfaces，不再建立控制服务。
每个完成、实质冲突或 ACTIVE-idle 的**变化事件**由 DM 向 Root 发一次 native action
message：assignment、结果/所选 tier、证据与 commit、实际外部效果、下一动作或依赖。
相同 assignment 和 evidence revision 的 message/final 作为同一事件去重，不等待 ACK。
新的实质变化可发新事件；“一次”不表示以后不能报告真正改变的状态。

Monitor 和 Transport 各自直接向 DM 返回其事实。Root 不转发原始 receipt，不重复 DM
已完成的 tests 或 intake；Root 做 main 整合与共享依赖协调。对象选择按现有 ledger
记录，方向/Portfolio 决定、close-call 等仍用现有 P1/P2 owner item；普通技术事实
不额外制造一条 owner 待批事项。DM 的授权内下一步不因 Root 尚未整合或回复而暂停。
