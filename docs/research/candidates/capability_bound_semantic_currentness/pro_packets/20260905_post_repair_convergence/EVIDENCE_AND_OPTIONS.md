primitive history for both policies -> SERVE, REFRESH or SAFE_FALLBACK -> actual
PPO exposure -> native held-out return. A statistic being decodable is not the

structured rule; the question is a finite-budget parameterization benefit.

active SAFE returns 0.20. Public input remains 136 primitive binary channels

oracle actions and future facts never enter policy observations.

protocol value over 6,144 worlds and 36,864 arm rows. Strongest contradiction to

## Recommended minimal B proposal

The following is concrete input for Pro selection, not local execution authority.

- Treatment: STRUCT-CURRENTNESS-GRU. Comparator: RAW-GRU, same complete public
  history, common recurrent network and training configuration. PI and DERANGED
  are omitted from this small performance question, so a positive result cannot
  establish semantic specificity or exclude recency/generic-conditioning causes.
- One fresh training seed, 21203, proposed prospectively. The listed B0/B1/B2
  evidence does not use it. Use new models and optimizer state, never old
  checkpoints, failed-output selection or a synthetic learner. This is one
  paired training sample, not two independent samples because there are two arms.
- Both arms retain CPU FP32, one Torch compute thread, 121,349 parameters, the
  existing 168->128->GRU128->actor4/value architecture and PPO configuration.
  Each arm uses 48 rollouts of eight complete episodes, four epochs and four
  two-episode minibatches: 384 episodes, 58,368 transitions, 9,216 decisions and
  768 actual Adam steps. Preserve gamma=1, delayed settlement, recurrence reset,
  optimizer order, masks and adapter semantics. No tuning or early checkpoint selection.
- Retain paired exogenous histories, initialization and action-uniform addresses
  across arms. Existing addressing supports only named B0/B1/B2 namespaces:
  reuse B1_RUN solely as the documented RNG namespace with fresh seed 21203 and
  distinct outer object/run metadata. This is not the old three-seed B1.
  If that separation cannot be represented honestly by existing APIs, return
  the concrete metadata dependency; do not silently rename or alter RNG bytes.
- Evaluate at updates 0, 12, 24 and 48 using 32 stochastic episodes in the
  existing EVAL_STOCHASTIC split, held apart from TRAIN. No motifs are required
  by this stochastic-return claim. Evaluation is greedy/adaptation-free and
  resets recurrent state for every episode. Primary observable: at update 48,
  mean paired STRUCT-minus-RAW undiscounted native episode return across the
  fixed 32 episodes. Intermediate checkpoints are disclosed curves, not
  candidates for selecting a best endpoint.
- Save per-episode return and 24 chosen actions at each checkpoint, same-tape
  ALWAYS_REFRESH/ALWAYS_SAFE context, per-update actual work/loss records,
  configuration, source version, seed/RNG namespace, checkpoint state and
  initial/final parameter movement. Primary return is built from the actual
  chosen-action native ledger on the same in-memory tape used for evaluation,
  then written/read back. Do not manufacture a full historical truth census.
  Existing exact Fraction reward arithmetic may be retained because it is
  already the native ledger; no new extreme output tolerance follows.
- Proposed MEI: 0.25 native return per episode, about 1.04% of the maximum 24
  units, a small practical signal for buying independent-seed follow-up.
  It is a planning reason, not a significance claim. Above it suggests one or
  two fresh paired seeds of the same comparison; within it suggests checking
  whether a specific budget/comparator limitation warrants one next B;
  opposite sign preserves the adverse native observation. No sign guarantees
  follow-up and no seed must be positive. Later work is selected at intake.
- RAW relative to simple refresh/safe policies and its action distribution is
  reported as competence context. Poor RAW limits the comparison's meaning;
  it does not automatically erase direct native-return facts or trigger the
  old 80%-support/full-table predicate. A one-seed observation has no
  training-seed population uncertainty estimate and cannot establish stable superiority.

Together the two arms have 116,736 training and 38,912 evaluation transitions,
155,648 total. Only one independent training-seed pair is proposed. The published
curves, all evaluations, failures and native losses are retained.
