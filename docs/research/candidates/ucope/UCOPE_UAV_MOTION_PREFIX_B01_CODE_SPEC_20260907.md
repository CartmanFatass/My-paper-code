## 2. Model and information boundaries

The real factory imports the two named base/adapter classes only when real execution is explicitly called. Pass the card's exact constructor values, including `max_steps=256`, `max_observed_users=20`, `max_observed_uavs=10`, `channel_backend="vectorized"`, `step_path_loss_cache=True`, `bandwidth=20e6`, `ground_bs_tx_power=30`, and the declared reset seed. The base constructor already performs one internal reset. Count and time it; it is not one of the 512 training or 32 final evaluation episodes. Use one base/adapter instance per learned arm, reset explicitly for every scored episode, and reuse G's instance for H. There are two constructors per pair. Preserve base agent order `uav_0` through `uav_4` and fixed membership.

Adapter reset returns `(obs[5,104], info)` with `info['state'][116]`; step returns `(next_obs, scalar, terminated, truncated, info)` with `info['next_state']`, `info['rewards_dict']` and `info['infos_dict']`. The scalar is the base team reward divided by five. The primary and learner instead use the sum of the five returned per-agent rewards, without another division or recomputing reward from channel state. Collect 256 real steps per episode; an unexpected earlier boundary is an incomplete episode/affected primary, not padding or a silent reset. At the prescribed boundary, no value bootstrap is added regardless of the API's termination/truncation field.

At each pre-action time, actor i receives `[own base obs (104), own last command (3), own remaining hold / 4 (1)]`, FP32, in that order. The last command is the normalized velocity actually passed to base step (physical commanded velocity divided by 30); it is not a new sensor for unclipped displacement. At reset it and the remaining hold are zero. Keep all base observation values and their existing normalization. Do not add an ID embedding, actor normalization statistics, global state, observation of another agent, service/channel diagnostics, critic features or reward history. Separate agent histories arise from their observations and last actions, not a shared hidden state.

The critic sees one FP32 team vector per primitive time: normalized current base state (116), then five groups `[last command x,y,z, remaining/4]` in agent order (20), for 136 values. In the base state, reshape the first 15 entries to five xyz positions: x,y / 1000 and (z−50) / 100. Divide the next 100 user xy entries by 1000; the last time value is already t/256. Do not normalize it again. Critic input is assembled **before** any decisions at that time; it can contain earlier commitments, but not current sampled velocity or duration. Critic weights/representations never feed actor output or hidden state.

Common actor architecture: Linear(108,64), tanh, one biased GRU(64,64), Linear(64,3) mean, and a three-element learned log-standard-deviation vector initialized to zero. No LayerNorm, dropout or extra encoder. Use log std clamped to [−5,2] in the distribution. GRU has one hidden state per agent, initialized to all zeros at reset and advanced on every observation, including during holds. T additionally has Linear(64,2) duration logits; all its weights and biases are zero initially, giving probability one-half for d=1 and d=4. Duration logits use the same current recurrent output as velocity and are sampled only at t=0.

Common critic: Linear(136,128), tanh, Linear(128,128), tanh, Linear(128,1), a scalar team value. Use Torch's installed default initialization for common Linear/GRU parameters. Build the common actor and then critic template under the initialization stream in §5, retain copies of its initial parameters, and start each arm from a separate copy. G need not be instantiated until its timed arm starts. Create T's duration head without advancing or shifting common initialization/sampling streams. All learner tensors and optimizer state are CPU FP32; preserve the environment's own internal dtype.

Planning parameter counts, recomputed from these dimensions: common actor 32,134; critic 34,177; G total **66,311**; T total **66,441** including 130 duration parameters. These counts describe the exact selected architecture, not an executed learner.

## 3. Sampling and the opening hold

For active velocity decisions, draw `u = mean + exp(log_std) * randn` with the explicit CPU velocity generator, in stable agent order and three coordinate dimensions; send `a=tanh(u)` to the environment. Store sampled u and its old log density. Evaluate density at this stored u, summing the three Normal log densities minus the stable tanh log Jacobian `2*(log(2) - u - softplus(-2*u))`. Do not invert a rounded/saturated action, resample for PPO, or replace sampled final evaluation by means/argmax. Use `torch.multinomial(softmax(logits), 1, generator=duration_generator)` for each T t=0 duration, in agent order.

At pre-action t, first assemble the actor/critic inputs from the previous step, advance every actor GRU, and compute the current value. An agent with remaining=0 samples a fresh velocity. At t=0, T also samples d and sets its remaining count to d; G and all later ordinary feedback decisions use one-step execution. A holding agent sends the already stored velocity, with no new velocity/duration sample. Execute the joint action once, then update every last command to the sent command and decrement any positive remaining count by one. Thus d=4 samples once at t=0, holds at t=1,2,3, and samples normally at t=4; d=1 samples normally from t=1. Never re-open duration decisions later in the episode.

Store true decision masks separately from environment-step and recurrent-observation counts. Old/new joint log probability for time t is the sum of only the actually sampled velocity terms across active agents, plus the actually sampled t=0 duration terms. No held command contributes another likelihood or independent sample. If all agents hold, the time has zero actor log-probability terms and no actor loss gradient, while the critic and recurrent observation sequence still participate. No 2^5 duration enumeration, candidate evaluation or shadow trajectory is permitted.

The entropy regularizer is explicitly the **analytic pre-tanh Normal entropy**, summed over coordinates and active agents, plus categorical duration entropy for t=0 decisions. This conventional regularizer is chosen identically for both arms; it is not claimed to be exact tanh-distribution entropy. Held/inactive heads add zero entropy, and no extra entropy-estimation draws consume the sampling streams.

## 4. Primitive returns and recurrent PPO

Collect two complete episodes per rollout without changing parameters during their collection: 512 team primitive steps and 2,560 agent observation frames. Store episode boundaries, 108-component actor inputs, collected pre-observation hidden states, 136-component critic inputs, actual pre-tanh samples/durations and masks, old joint log probabilities, old values and actual team rewards. Detach collected tensors from any collection graph. Collection and sampled evaluation run under no-grad.

For each episode compute the unnormalized finite reward-to-go `Y_t=sum(k=t..255, R_k)` with gamma=1 and zero terminal value. Set raw advantage to `Y_t-old_value_t`, detached. Normalize these 512 advantages once over the full rollout by subtracting their mean and dividing by population standard deviation plus 1e-8. Do not divide reward, target or advantage by duration, use GAE, discount by decision count, clip/normalize rewards, or carry return across episode boundaries.

Run exactly four full-rollout optimization epochs. For each epoch reconstruct the current actor log densities through 32-step recurrent chunks, using each chunk's **collected pre-observation initial hidden state**, detached, and its contiguous observations. There are 16 team chunks / 80 agent sequences of length 32 per rollout; process all of them, with no shuffled time steps, omitted tail or new data. Recompute hidden evolution inside each chunk under current parameters for that epoch. Episode starts have zero state. Do not reset hidden at a hold boundary or silently carry gradients across chunks. Ordinary in-process batching of these fixed sequences is allowed.

Regroup the actual action log densities into one joint team log probability per time. Let `r_t=exp(new_joint_logp_t-old_joint_logp_t)`. Policy loss is `-mean(min(r_t*A_t, clamp(r_t,.8,1.2)*A_t))` over the 512 team times. It is one joint ratio and clipping operation per time, not separately clipped agent ratios. All-held times contribute a parameter-independent constant. Value loss is mean squared error of the scalar critic against Y over all 512 times, no value clipping. Entropy is the mean over 512 times of the actual-decision sum in §3. Total loss is policy loss + .5*value loss − .01*entropy.

Each epoch performs one zero_grad/backward, one global grad-norm clip at .5 over that arm's actor and critic, then **one** joint Adam step. Use lr=3e-4, betas=(.9,.999), eps=1e-8, weight_decay=0, amsgrad=False, foreach=False, fused=False; one fresh optimizer per arm, no scheduler, target-KL early stopping, actor/critic split updates or early epoch exit. Exactly 256 rollouts × four epochs = 1,024 optimizer calls per fit. A nonfinite learner is recorded and stops further scientific work under card §5; it does not become a native negative.
