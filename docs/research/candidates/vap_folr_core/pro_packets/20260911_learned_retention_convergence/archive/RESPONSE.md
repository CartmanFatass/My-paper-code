The fixed-half recipe remains paused. No implementation, B card, experiment, numerical allowance or future cap is allocated by this decision. Its decision value is a direct comparison of an explicitly event-bound, trainable state transformation with the **already adaptive** recurrent baseline—not a purported information advantage. The new observation could determine whether this particular added computation has enough native-return value to remain a candidate after finite training. That is a different purchase from another observation of fixed .5, but it is not evidence that learned attenuation will help. The strongest alternative remains ordinary event-aware RETAIN without any added operation or new experiment. [Candidate, §§3–5][candidate]; [model.py, `Actor.__init__` and `Actor.forward`][model].

## Exact eligible operation and its information boundary

Let `x_it` be the existing `x3` at the current controller position, `c_it` the true-continuation bit, and `e_t` the public event produced by the preceding completed native transition. Let `hbar_it = c_it * h_i,t-1`. The candidate remains exactly:

`g_it = sigmoid(w_x · x_it + w_h · hbar_it + b)`

`h_in_it = g_it * hbar_it` when `c_it and e_t`, and `hbar_it` otherwise;

then `GRUCell(x_it, h_in_it)`, followed by the existing entity mask and Q head. The 64 input weights, 64 history weights and one bias are shared across agents and time. They are not a separate model per agent, an event classifier, a new recurrent channel or a vector-valued selective-memory mechanism. The initial zero weights and `log(99)` bias specify one untuned near-retention starting point. [Candidate, §2][candidate]; [FACTS, `candidate`][facts].

The source supports a concrete insertion point. `Actor.forward` obtains masked attention output, appends the public event and own-birth features, and applies the 130-to-64 `fc2` and ReLU to obtain `x3`. Its recurrent loop first enforces continuation, applies the existing optional state law, then calls the ordinary GRU. `EntityAttentionLayer.forward` masks attention logits with the supplied observation mask and masks inactive outputs. The proposed gate uses that existing local input and the continuing trip's own prior hidden state; it must not read the unmasked entity collection, future observations, another actor's private hidden state or the mixer's global training inputs. This is an assessed information path, not an independent audit of unlisted native-mask or mixer implementations. [model.py, `Actor.forward`][model]; [attention.py, `EntityAttentionLayer.forward`][attention].

Physical identity, not slot continuity alone, controls carry. `LifecycleEnv.step` clears the transition's birth/departure records, performs the native step, and defines continuation as `before & after & ~departure & ~birth`. Its event is the completed transition's `any(departure | birth)`. The hooks retain native removal/addition calls while recording real lifetime changes. `observation` masks previous-action features by continuation. A same-slot replacement consequently receives neither the previous trip's hidden state nor its action feature. At episode reset continuation is false; inactive states are masked after recurrence. [environment.py, `reset`, `_remove_car`, `_add_car`, `step` and `observation`][environment].

A later implementation must form `hbar` before it becomes a gate input and preserve these lifetime cuts. The prohibition on gradients crossing different trips means no recurrent-state derivative through a departed owner's slot history; it does not prohibit learning shared actor parameters from many trips or centralized training gradients through the accepted mixer. Current information can still create a fresh nonzero hidden state for an entrant. A terminal controller pass remains a computational position without another native action or terminal bootstrap. These are distinctions in the specified mechanism, not additional scientific work commissioned now. [Candidate, §§2–3][candidate]; [model.py, recurrence][model]; [collection.py, `collect`][collection]; [learner.py, `update`][learner].

## Why the existing GRU is the decisive null

RETAIN is not a constant-memory controller. It carries the prior hidden vector into a learned GRU that already receives current local input, event and birth information. Its recurrent gates already depend on input and history. A physical arrival or departure need not make a continuing car's history obsolete, and some relevant information may already be reobserved. The candidate adds neither observations nor a demonstrated representational capability unavailable to RETAIN. This is the strongest source-grounded objection to opening. [Candidate, §3][candidate]; [model.py, `Actor.__init__` and `Actor.forward`][model].

The proposed extra scalar can be redundant, can attenuate useful coordinates together with unwanted ones, or can interact poorly with the ordinary GRU and joint optimizer. It cannot distinguish useful and stale components by coordinate. Its near-.99 sigmoid initialization may make subsequent gate learning weak; alternatively the learned feature and recurrent representations may compensate for the scale. The gate can remain nearly constant, approach near-carry behavior, or become harmful. None of those outcomes has been observed, and no exact safe fallback to RETAIN is guaranteed: .99 is not 1, and small hidden-state changes need not preserve greedy action selection. [Candidate, §§2–3][candidate]; [FOUNDATIONS, §§2–4][foundations].

Nevertheless, identical information does not imply identical finite-learning behavior. This candidate makes the additional pre-GRU attenuation depend on a current local feature and continuing-trip history, rather than imposing the same fixed .5 at every event. It provides a dedicated event-bound transformation through which the existing training objective can influence the incoming state. That is a specific, falsifiable inductive-bias hypothesis: **under the stated finite recipe, adding this trainable transformation may produce a useful final native-return gain over the already event-aware RETAIN package.** It is not a prediction of optimal retention, architectural necessity or recovery of the fixed-half loss. The source alone proves neither universal redundancy nor strict containment between the resulting finite-parameter policy classes. [Candidate, §§2–5][candidate]; [model.py][model]; [FOUNDATIONS, §4][foundations].

I judge that narrow performance question worth making eligible because it can distinguish an additional usable package from an unnecessary one using the existing native comparison path. Its value is not the count of 129 coefficients by itself, a promise that implementation is cheap, or an argument that mixed old signs demand another architecture. No-new-investment remains reasonable: it keeps an attained competent null and avoids a substantial new training comparison. My preference for opening is a close qualitative judgment about this one next observation; no expected gain, probability of success or value-per-second estimate is supported by the record.

Classification follows the actual change. The host, public information protocol, physical lifetime semantics, native objective, generic comparator and survivor-state-control question stay intact. The new object changes a fixed event operation into a learned conditional operation within that same programme. I therefore select **narrow OPEN / in-family extension, not RECAST**. This does not reopen fixed .5, authorize a third half pair, or create a sequence of replacement constants after each adverse result. The old pause was not a theorem against all retention changes, and the new opening is not a retrospective correction of that pause. [Prior response, paused unit and re-entry][pause-response]; [accepted pause intake, §§2,6][pause-intake]; [AGENTS, §2][agents].

## Source feasibility is not implementation acceptance

The six inspected source files give a plausible route, but contain no learned-scalar implementation. `Actor` currently defines the common attention/fc2/GRU/Q chain and the existing state laws. The runner's arm choices contain RETAIN, EVENT, RANDOM and HALF_EVENT only. Adding an arm label alone would not establish that the gate exists, participates in learning or is correctly published. No source was changed or executed in this review. [model.py, `Actor`][model]; [runner, argument parsing and `main`][runner].

**Initialization and RNG.** `Learner.__init__` constructs the actor before the mixer. Adding an ordinarily initialized layer can consume draws and shift later common actor or mixer parameters even if its values are subsequently overwritten with zeros. Appending it after the old actor layers would not, by itself, protect the later mixer. The proposed comparison therefore needs common initial actor/mixer values and isolation of all added constructor draws, while disclosing the gate's extra parameters and near-RETAIN initial policy. Existing Python/NumPy/Torch seeding, traffic/replay sampling and action-selector RNG consumers remain as specified. Equal seed labels alone do not establish that parameter matching was preserved. This is a concrete integration requirement exposed by the source, not a verified property of unimplemented code. [learner.py, `Learner.__init__`][learner]; [runner, construction and seeding][runner]; [candidate, §3][candidate].

**Acting and recurrent replay.** Collection carries hidden state step by step under `torch.no_grad()` and stores complete episodes. Learning calls the online and target actors on those episodes, each reconstructing its own hidden history from zero. A learned gate must be recomputed within each network's forward recurrence from that network's current parameters and reconstructed history. Consistent law does not mean numerically identical acting-time, online and target gates: the weights and histories can differ. Treating old acting-time scalars as fixed replay masks would instead freeze the proposed trainable transformation and alter its gradient path. The existing stochastic RANDOM mask protocol is not the correct substitute for this deterministic learned function. [collection.py, `collect` and `sample`][collection]; [model.py, `Actor.forward`][model]; [learner.py, `update`][learner].

**Learning, target copies and saved state.** The gate belongs in the online actor's differentiable recurrent computation, not in a detached auxiliary decision. The source builds RMSprop from registered actor and mixer parameters, applies one combined clipped update, deep-copies the target actor, periodically copies complete state dictionaries, and saves both networks and optimizer state. A future registered gate must participate consistently in those paths before optimizer/target construction. The target forward remains under no-gradient target computation, while ordinary online history gradients remain available within the same physical trip. Equal update counts would still not imply equal gradient norms, displacement or effective optimization. [learner.py, `__init__`, `update` and `save`][learner].

**Output and work boundaries.** The existing counters explicitly recognize full EVENT resets and fixed HALF attenuations; a new learned arm cannot silently inherit misleading zero or fixed-half intervention labels. Likewise, the existing runner contains a historical 1,800-second timeout interpretation. Neither its present labels nor its hard-coded cap prices or authorizes the new candidate. Faithful arm identity, primary output and any necessary intervention-exposure description belong to later scoped engineering, without a new telemetry framework or a state-content census. The present source assessment accepts none of those future consumers at runtime. [environment.py, `count_transition`][environment]; [collection.py, counter updates][collection]; [runner, summary initialization, publication and timeout handling][runner].

These observations define the relevant future correctness dependencies. They do not commission a fixture, test, implementation diff, profiling run or new approval layer. Any later authorized high-risk recurrent/RNG/gradient change remains subject to the existing proportionate review and source/test boundaries; unchanged coverage should be reused. No extra numerical validation or causal diagnosis is required to form this direction decision. [Engineering Scope Spec, §§4–5,7.1–7.3][engineering]; [empirical specification, §§11.4,11.8.6–11.8.8][spec].
