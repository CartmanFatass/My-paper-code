## P1 accepted: current-only must also erase unseen carried state

The initial proposal said to zero the branch's incoming hidden argument every step.
That was incomplete as a specification: in the inspected source, `where(visible,
candidate,h)` would retain old unseen `h` if only the GRU argument were changed.
This is a prospective specification defect, not an implemented successor defect or
a reason to invalidate B03. DM replaces that ambiguous proposal with this state law.

For observer i and subject j, let v mean currently visible and both live, c_i/c_j
mean continuation of the same live lifetimes, and e be the embedded, sanitized legal
current input. With zero episode initialization:

```
persistent:
    carried = c_i * c_j * previous_entity_state
    entity_state = GRU16(e, carried) if v else carried
current-only:
    entity_state = GRU16(e, zero) if v else zero
```

Both arms clear entity state at episode boundaries and observer/subject replacement,
and keep inactive rows zero. The current-only result never uses its previous output;
detaching a previous tensor is not sufficient. No unseen physical value or last-visible
learned value is synthesized for that control. Both arms use the same live/seen readout
masks, labels, truthful visibility/seen/age metadata and current-physical bypass. An
unseen control token can therefore contain legal bookkeeping while its learned entity
state is exactly zero. This control retains other lawful historical information.
