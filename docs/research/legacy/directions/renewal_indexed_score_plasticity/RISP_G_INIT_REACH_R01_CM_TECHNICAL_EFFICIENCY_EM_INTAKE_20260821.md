## Exact meaning of the Python 32.35-hour baseline

The `32.35 h` figure is a result-blind engineering projection for the current
serial Python reference chain on one CPU thread. It is assembled from a
width-16 TEST observation of about seven seconds per update, projected across
`32 * 512` training updates (`31.86 h`), TEST-only evaluation timings projected
across 320 units (`0.49 h`), and about nineteen seconds of cold-import and
frontier write/scan overhead. It totals approximately `116,478 s` before
ordinary runtime variance and final analysis overhead.

It is not:

- an execution of the complete R01 panel;
- a scientific runtime estimand, treatment/comparator observation or branch
  input;
- evidence about either arm, any lower bound or `Psi`;
- a production-coordinate event, lease fact or accepted production benchmark;
  or
- a wall-time cap, stop rule, reason to reduce the panel, or Portfolio decision.

The reference-path projection is nevertheless material engineering evidence:
it exceeds the prior prospective `18–26 h` range by `6.35 h` above its upper
endpoint, approximately 24%, and shows that the unoptimized serial Python path
cannot support the earlier runtime estimate. That path is not the proposed
accepted production implementation. Because no native full-host candidate,
semantic-equivalence result or optimized end-to-end measurement yet exists,
the accepted production runtime and cost class remain unknown. The current
record therefore establishes a bounded efficiency discrepancy and cost-class
uncertainty, not a confirmed production cost-class expansion.

The separately owned CM must construct and technically accept the native
full-host boundary; the direction CM must then establish native-versus-reference
