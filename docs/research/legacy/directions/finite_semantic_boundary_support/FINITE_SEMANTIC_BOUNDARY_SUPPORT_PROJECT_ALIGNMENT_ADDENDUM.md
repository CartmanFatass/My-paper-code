# FSBS B1 project-alignment addendum

Owner: `direction:finite-semantic-boundary-support` Explorer Manager

Treatment: `FSBS-B1-AUTHENTIC-ASSOCIATION-v1`

## Conclusion

FSBS B1 is weakly aligned with the project objective as an upstream finite
association assay, but the existing treatment cannot materially choose,
delete, or modify a credible shared variable-`N` or variable-`k` MARL
algorithm family. This is a scientific limitation of the registered contrast,
not an implementation limitation. Constructing the host exactly as specified
would not add the absent axis or downstream causal edge.

The strongest credible alignment is a variable-`N` family in which one shared,
permutation-compatible UAV policy uses an authenticated carrier to choose one
of two sealed peer records under a binding one-read/one-service cap. The exact
vulnerability would be that fleet-size change alters contention and peer
composition, so a wrong capped selection withholds action-relevant peer
information from the team policy. The proposed causal chain is:

`authentic carrier-record association -> correct capped record selection ->`
`relevant peer information enters a shared policy -> coordinated action ->`
`team return or robustness under changed N`.

FSBS B1 identifies only the first arrow and its immediate one-agent record
value. It fixes cardinality, has one contextual-bandit learner, has no partner
or parameter sharing, never changes `N` or `k`, and observes no cooperative
return. Its held-out `(issuer_class, route_mode)` cell is not a held-out roster
size. Therefore no B1 outcome observes or separates the edge from selected
record to variable-`N` coordination.

## Exact prospective audit

- **Varying axis:** none in B1. The only credible project bridge would use
  exogenously varied roster size `N`, with one shared parameterization across
  training sizes and at least one held-out size.
- **Algorithm component:** B1's authenticated, resource-capped local
  carrier-conditioned record selector placed before a shared set/graph MARL
  policy.
- **Matched comparator for that future family:** the same shared architecture,
  roster schedule, worlds, peer records, validation-success marginals,
  communication, read/service cap, samples, compute and physical time, but with
  whole valid carriers reassociated within matched roster/role/interface
  strata. A bit-blind selector is the strongest simpler alternative when
  separately resource-matched.
- **Toy-to-UAV bridge:** agents are UAVs; sealed records are peer track,
  route-reservation, relay, or task-allocation packets; the carrier identifies
  which slot contains the packet relevant to the receiver; one payload decode
  and one service opportunity model a fixed boundary bandwidth/compute budget;
  wrong selection causes stale coordination, missed coverage, or deconfliction
  loss. Correct-record rate is a mediator, while mission/team return and
  robustness at held-out fleet size are endpoints.
- **Strongest alternative:** ordinary learning of a sufficient binary cue on a
  one-step host. B1's controls can exclude stable nonsemantic codebooks and
  label-polarity bias, but cannot make the learned cue a multi-agent
  coordination mechanism or show that authentication rather than an equally
  predictive resource-matched feature is needed downstream.

## Outcome map and claim ceiling

- A clean `NATURAL` positive with passing `MASKED` and `RELABEL` controls
  supports carrying the local selector into a later variable-`N` test. It does
  not select the shared MARL family or support scaling, coordination, UAV, or
  variable-axis claims.
- A `COVERAGE`-only positive says that supplied action exposure makes this
  association creditable. It may motivate an exploration change to this local
  selector, but does not establish that such a change benefits a shared MARL
  family.
- With adequate exposure, wrong value margins can reject the exact linear
  learner-and-budget realization; correct margins with wrong choices can reject
  its action extraction. Neither deletes the carrier-aware MARL family.
- A null, incomplete gate, cap breach, or unresolved low-coverage result is
  non-deleting under B1's existing claim ceiling.
- An advantage surviving `MASKED`, or one confined to or reversed by label
  polarity, rejects semantic transfer from this assay because the intended
  association is not identified.

The maximum project-relevant claim from B1 remains one-sided and local: a clean
positive may admit this exact finite carrier-selector primitive to an
axis-bearing discriminator. No possible B1 result establishes variable-`N` or
variable-`k` robustness, multi-agent coordination, shared-policy benefit, or
UAV value, and no nonpositive result deletes the broader carrier-aware family.

## Concrete reconsideration trigger

Reconsider project investment only when a registered matched churn/roster toy
uses one shared parameterization across at least two training roster sizes and
one held-out `N`, keeps the one-read/one-service cap, compares authentic versus
within-stratum reassociated carriers, and measures both per-agent correct-record
selection and cooperative return. Its outcome must separate the downstream
edge:

- a held-out-`N` team benefit mediated by correct selection retains the family
  for a second surface and UAV simulator;
- preserved correct selection with no team benefit deletes the proposed
  selection-to-coordination edge for that task;
- a selection loss specifically as `N` changes requires modifying the shared
  set interface or multi-agent credit mechanism before further investment.

That is a new axis-bearing treatment, not a clarification or construction of
FSBS B1.

## Routing consequence

Do not route the current FSBS B1 card to CM as a project-aligned algorithm
discriminator. Root may retain it only as a one-sided precursor assay if the
