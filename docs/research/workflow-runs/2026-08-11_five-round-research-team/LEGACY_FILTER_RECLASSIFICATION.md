# Legacy portfolio-filter reclassification

This audit preserves every historical observation but supersedes the meaning of
the unqualified words `FILTERED`, `ABSENT`, `CLOSED`, and `PARKED`. Repository
absence and loop allocation are not scientific evidence.

## Correct reading

| Historical events | Recorded basis | Object-level reading now |
|---|---|---|
| 017, 018, 020, 038, 055, 065, 075, 076, 096, 100, 118 | no co-located/native host, event source, lifecycle hook, DTO, world, or adapter | The claim that the predecessor already contains the object is closed. A freshly constructed treatment is `PROSPECTIVE_SUCCESSOR_UNEVALUATED`, not failed. It needs an EM specification and, if valuable, CM feasibility. |
| 036, 067, 120 | no loop allocation, no implementation, or deferred portfolio slot | `PARKED_BY_PRIORITY_WITH_TRIGGER` only. Where no falsifiable trigger or CM cost receipt was recorded, the park is unaudited and must not be treated as scientific rejection. |
| 073 | required Python/dependency environment absent | Technical environment work only; no hypothesis, treatment, or direction disposition follows. |
| 167 | B9 technical invalid binding with zero admissible result activity | `RUN_TECHNICAL_TERMINAL_NO_SCIENCE`. The consumed run did not answer the treatment; prospective EOCIV constructions remain a separate portfolio question. |
| 185 | predecessor B5 invalid/no-result followed by fresh B5R1 | The old run is terminal; it did not block construction. B5R1 was correctly built and evaluated under a fresh identity. |
| 186 | RECCT-X1 active-port/alignment/crossing conditions confound a generic Adam interpretation | A treatment-level identifiability objection. This is a scientific filter for that frozen comparison, not evidence that RECCT or the broader mechanism family failed. |
| 226 | valid VSP02 B5R1 result | Empirical treatment/formulation evidence within its finite panel and claim ceiling. The direction is retained and parked, not retired. |

Batch events that combine several candidates do not supply candidate-level
scientific dispositions. Root must disaggregate them before allocating an EM or
CM and must not inherit a batch-level `FILTERED` literal as a conclusion.

## Portfolio consequence

The absence-only candidates return to the idea pool as untested prospective
objects. Root first ranks their scientific value, estimand, comparator,
discriminator and claim ceiling. High-value survivors go to a direction EM and
then to an early CM feasibility/cost check even when all implementation paths
are fresh. Low-priority survivors may remain parked only with an explicit
revisit trigger. No entry in this audit is `DIRECTION_RETIRED`.
