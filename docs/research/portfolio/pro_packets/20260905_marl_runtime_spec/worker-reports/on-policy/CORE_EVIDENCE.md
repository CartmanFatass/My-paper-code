## 1. 端到端调用链（OBS）

```text
scripts/train/{train_smac,train_mpe}.py
  -> make_train_env (Dummy 或 Pipe subprocess vector)
  -> shared/separated Runner(config).run()
  -> warmup
  -> 每个 episode: T × [collect -> envs.step -> insert]
  -> compute (bootstrap/GAE) -> train (PPO epochs/minibatches)
  -> after_update -> save/log/eval
```

- MPE 入口先建训练/评估环境、确定 `num_agents`，再按 `share_policy` 选择 shared 或 separated runner，并调用 `run()`（[`train_mpe.py#L138-L164`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_mpe.py#L138-L164)）。SMAC 对应路径还从地图读取 agent 数量，并在 [`train_smac.py#L210-L243`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_smac.py#L210-L243) 选择 runner。
- shared SMAC 的实际循环在 [`runner/shared/smac_runner.py#L16-L46`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/smac_runner.py#L16-L46)：`episodes=floor(num_env_steps/(T·R))`，每个 episode 顺序执行 T 次 `collect → envs.step → insert`，之后一次 `compute` 和一次 `train`。shared MPE/Football 采用同一总体形状；Football 的间隔判断有单独差异（见第 5 节）。
- shared 基类在 [`runner/shared/base_runner.py#L120-L141`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/base_runner.py#L120-L141) 把最后时刻的 critic 值送回 NumPy buffer 计算 return，再调用 trainer；separated 基类逐 agent 计算 bootstrap（[`runner/separated/base_runner.py#L125-L141`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/separated/base_runner.py#L125-L141)）。

## 2. 环境向量化与 subprocess（OBS；吞吐结论见 INF）

- 训练入口在 `R=1` 时使用 dummy，在 `R>1` 时使用 Pipe-backed vector：MPE 的 [`train_mpe.py#L16-L31`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_mpe.py#L16-L31) 使用 `DummyVecEnv/SubprocVecEnv`；SMAC 的 [`train_smac.py#L50-L76`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_smac.py#L50-L76) 使用 `ShareDummyVecEnv/ShareSubprocVecEnv`。
- 普通 worker 在 [`env_wrappers.py#L140-L174`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/env_wrappers.py#L140-L174) 中从 Pipe 收 `step/reset`，调用环境；done 后 worker 立即 reset 并把 reset 后 observation 与原 done 一起发回。`SubprocVecEnv` 为每个 env 建一个 `multiprocessing.Process`，daemon=True；`step_async` 先向所有 Pipe 发送 action，`step_wait` 再按 remote 顺序 `recv` 并 `np.stack`（[`env_wrappers.py#L235-L290`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/env_wrappers.py#L235-L290)）。
- shared worker 额外发送/接收 `share_obs` 和 `available_actions`；`ShareSubprocVecEnv` 的返回实际是 `(obs, share_obs, reward, done, infos, available_actions)`（[`env_wrappers.py#L300-L396`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/env_wrappers.py#L300-L396)）。`DummyVecEnv/ShareDummyVecEnv` 则在主进程的列表推导中顺序调用每个环境（[`env_wrappers.py#L660-L740`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/env_wrappers.py#L660-L740)）。
- SMAC 环境实例在 [`StarCraft2_Env.py#L330-L355`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/starcraft2/StarCraft2_Env.py#L330-L355) 调用 pysc2 `run_config.start()` 并持有 `_sc2_proc.controller`；一次 step 发送 action、推进游戏并 observe（[`StarCraft2_Env.py#L455-L490`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/envs/starcraft2/StarCraft2_Env.py#L455-L490)）。因此代码可确认每个 vector worker 内有一个 SMAC wrapper/controller 进程对象；pysc2 是否再派生更底层进程由外部库决定，本报告没有实测。

**INF 性能含义：** 所有 Pipe 都先发 action、再统一收结果；`step_wait` 对 remote 顺序阻塞，所以 rollout 是“各 env worker 可并行，主线程每步等待全部 env 的 barrier”，最慢环境会决定该步返回时间。Pipe pickle/`np.stack` 也位于每个环境步的路径上。这个判断来自控制流，未测 wall time、CPU 占用或并行效率。

## 3. Shared 与 separated 的真实 batch 语义

### Shared policy（OBS）

- 基类只构造一个 policy、一个 trainer 和一个 `SharedReplayBuffer`（[`runner/shared/base_runner.py#L66-L99`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/base_runner.py#L66-L99)）。默认 `share_policy=True` 也写在 README（官方页面第 187 行）。
- shared SMAC/MPE `collect` 把 `buffer[step]` 的第一维拼接：`np.concatenate([R,A,...]) → [R·A,...]`，一次 `policy.get_actions` 同时调用 actor 和 critic，再把输出 split 回 `[R,A,...]`（SMAC [`shared/smac_runner.py#L110-L127`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/smac_runner.py#L110-L127)；MPE [`shared/mpe_runner.py#L95-L123`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/mpe_runner.py#L95-L123)）。这是一时刻的 `R·A` 样本并行，不是 T 个环境时刻并行；T 仍由 runner 的 for-loop 顺序推进。
- shared buffer 的原始布局是 `share_obs/obs:[T+1,R,A,...]`、RNN state 同样含 A、value/return `[T+1,R,A,1]`、action/reward `[T,R,A,...]`（[`shared_buffer.py#L54-L86`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/shared_buffer.py#L54-L86)）。普通 feed-forward generator 的 batch size 是 `R·T·A`，并 reshape 成扁平样本（[`shared_buffer.py#L340-L400`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/shared_buffer.py#L340-L400)）。
- RNN chunk generator 令 `C=floor(R·T·A/L)`，`mini_batch_size=floor(C/B)`，随机抽 C 个 chunk；每个 chunk 保持 L 个连续时刻，之后 flatten 为 `L·mini_batch_size`（[`shared_buffer.py#L499-L512`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/shared_buffer.py#L499-L512)；[`shared_buffer.py#L552-L608`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/shared_buffer.py#L552-L608)）。由整数除法可推得当 `R·T·A` 不能被 `L·B` 整除时，尾部数据没有进入 sampler；这是代码推断，未在运行中验证。

### Separated policy（OBS）

- separated 基类为每个 agent 建立独立 policy、trainer、buffer（[`runner/separated/base_runner.py#L85-L112`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/separated/base_runner.py#L85-L112)）。每个 `SeparatedReplayBuffer` 没有 agent 轴，布局是 `[T+1,R,...]`，action/reward 是 `[T,R,...]`（[`separated_buffer.py#L34-L60`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/separated_buffer.py#L34-L60)）。
- separated SMAC 的 `collect` 对 `agent_id` 做 Python for-loop；每次只把该 agent 的 `[R,...]` 输入一套网络，最后 transpose 成 `[R,A,...]`（[`separated/smac_runner.py#L110-L138`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/separated/smac_runner.py#L110-L138)）。因此同一 device 上没有 shared 的单次 `R·A` forward，而是 A 次 `R` forward。
- separated feed-forward batch 是每个 agent 的 `R·T`（[`separated_buffer.py#L169-L227`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/separated_buffer.py#L169-L227)）；RNN chunk 数是 `floor(R·T/L)`（[`separated_buffer.py#L311-L424`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/separated_buffer.py#L311-L424)）。
- separated `base_runner.train` 还在每个 agent 更新前后各一次对整段 buffer 的 actor `evaluate_actions`，并维护 `factor`（[`separated/base_runner.py#L135-L183`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/separated/base_runner.py#L135-L183)）。`SeparatedReplayBuffer` 会把 factor 作为第 13 项 yield（[`separated_buffer.py#L197-L227`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/utils/separated_buffer.py#L197-L227)），而 `R_MAPPO.ppo_update` 对 13 项 sample 用 `_` 丢弃它（[`r_mappo.py#L104-L127`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/r_mappo.py#L104-L127)）。**OBS：** 对 separated 的 RMAPPO/MAPPO trainer，这条 factor 结果没有进入 PPO loss；**INF：** 旧/新 logprob 全量重算及 factor 维护可能是额外序列瓶颈，必须通过计时/剖析确认，不能仅凭源码宣称加速幅度。

## 4. RNN、PPO minibatch 与 Torch device（OBS；拷贝成本判断见 INF）

- `R_MAPPO.train` 先用 returns 与 value 形成并标准化 advantage，然后每个 PPO epoch 重新建立 generator；每个 sample 调 `ppo_update`，总更新数为 `ppo_epoch·B`（[`r_mappo.py#L171-L224`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/r_mappo.py#L171-L224)）。`ppo_update` 对一整个 sample 调一次 `policy.evaluate_actions`，随后顺序 actor backward/step 与 critic backward/step（[`r_mappo.py#L119-L169`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/r_mappo.py#L119-L169)）。
- policy 明确把 actor 输入设为 local `obs`，critic 输入设为 centralized `cent_obs`（[`rMAPPOPolicy.py#L48-L86`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/algorithm/rMAPPOPolicy.py#L48-L86)）。MPE shared runner 在 warmup/insert 中将每个环境所有 agent obs flatten，再复制给 A 个 critic slot（[`shared/mpe_runner.py#L81-L93`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/mpe_runner.py#L81-L93)；[`shared/mpe_runner.py#L125-L139`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/mpe_runner.py#L125-L139)）。
- actor/critic 初始化时 `.to(device)`；forward 先 `check(...).to(dtype=torch.float32, device=device)`（actor [`r_actor_critic.py#L44-L71`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/algorithm/r_actor_critic.py#L44-L71)，critic [`r_actor_critic.py#L156-L175`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/r_mappo/algorithm/r_actor_critic.py#L156-L175)）。`check` 对 NumPy 使用 `torch.from_numpy`（[`algorithms/utils/util.py#L16-L18`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/utils/util.py#L16-L18)）；buffer 本身始终是 NumPy。
- collection 输出在 runner 的 `_t2n(x)=x.detach().cpu().numpy()` 中回到 host（[`shared/base_runner.py#L8-L10`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/base_runner.py#L8-L10)；separated 同样在 [`separated/base_runner.py#L13-L15`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/separated/base_runner.py#L13-L15)）。
- RNN 的单步收集路径在 `x.size(0)==hxs.size(0)` 时只推进一步；训练的 flattened sequence 则重塑为 `(T,N,feature)`，按 mask 中的 zero 边界分段调用 GRU，再 flatten 回去（[`algorithms/utils/rnn.py#L24-L80`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/algorithms/utils/rnn.py#L24-L80)）。

**INF 性能含义：** GPU 运行时每个 collection step 至少有 NumPy/CPU view→`.to(cuda)` 的输入路径和 GPU→`.cpu().numpy()` 的输出路径；每个 PPO minibatch 又从 NumPy 重建/搬运输入。源码没有 pinned memory、`non_blocking=True` 或 device-resident buffer。GRU 的时间维仍是递推；mask 边界还会触发 Python 分段循环。这里没有安装依赖、没有跑 CUDA，也没有量化同步或拷贝占比。

## 5. 训练、保存、日志与评估频率（OBS）

- `config.py` 默认 `R=32`、`n_eval_rollout_threads=1`、`T=200`、`num_env_steps=10e6`、`ppo_epoch=15`、`B=1`（[`config.py#L160-L177`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/config.py#L160-L177)，[`config.py#L241-L284`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/config.py#L241-L284)）。入口按算法覆盖 recurrent 开关：RMAPPO 打开 recurrent，MAPPO 关闭（SMAC [`train_smac.py#L132-L149`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_smac.py#L132-L149)；MPE [`train_mpe.py#L68-L80`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train/train_mpe.py#L68-L80)）。
- SMAC/MPE shared runner 用 `episode % save_interval/log_interval/eval_interval`；默认 save=1、log=5、eval=25，而且 `episode=0` 就满足 eval 条件（SMAC [`shared/smac_runner.py#L47-L96`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/smac_runner.py#L47-L96)）。SMAC eval 循环到完成 `eval_episodes` 个 episode，并使用 deterministic action（[`shared/smac_runner.py#L161-L223`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/smac_runner.py#L161-L223)）。
- shared Football 不是 episode modulo，而是 `total_num_steps % interval`，并且 eval 还有 `step < episode_length` 上限（[`shared/football_runner.py#L23-L77`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/runner/shared/football_runner.py#L23-L77)）。因此同一个参数名在 SMAC/MPE 与 Football 的单位不同。
- 代表性脚本把 SMAC 设为 `R=8,T=400,B=1,ppo_epoch=15`（[`train_smac_3m.sh`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train_smac_scripts/train_smac_3m.sh)），MPE 设为 `R=128,T=25,B=1,ppo_epoch=10`（[`train_mpe_spread.sh`](https://github.com/marlbenchmark/on-policy/blob/de66d7a4b23fac2513f56f96f73b3f5cb96695ac/onpolicy/scripts/train_mpe_scripts/train_mpe_spread.sh)）。例如 MPE shared recurrent 若 `A=3,L=10`，静态 batch 为 `R·T·A=9600`、`C=960`；separated 每 agent 为 `R·T=3200`、`C=320`。这只是整除公式的工程算术，不是速度结果。

## 6. 适用限制与可复核结论

- **OBS 结论：** shared 是每个环境时刻一次 `R·A` policy forward；separated 是 A 次 `R` policy forward；两者都在 T 维由 runner 顺序推进。shared replay 含 agent 轴，separated 每 agent 一份 buffer。RMAPPO PPO 每个 epoch 重建 generator，actor/critic step 顺序执行。
- **INF 结论：** barrier 收集、Pipe 序列化、GPU↔CPU 往返、NumPy minibatch 重搬运、separated 的额外 logprob/factor 路径，以及 recurrent mask 分段，都属于潜在序列/吞吐瓶颈；本次没有性能实测，不能给出加速比例、toy45min 或 UAV12h 的跨任务速度保证。
- **LIMIT：** 本调查没有安装依赖、启动 StarCraft/Football/Hanabi、训练、benchmark 或采集硬件计时。结论限定于固定 SHA 的源码；SMAC/MPE 的 shared/separated 路径最完整。固定树中没有 `runner/separated/football_runner.py` 或 `runner/separated/hanabi_runner_forward.py`，且 `train_smac.py` 的 `env_name=SMAC` 分支引用了树中未出现的 `onpolicy.envs.starcraft2.SMAC`，所以不能把上述对照无条件推广到这些入口。
