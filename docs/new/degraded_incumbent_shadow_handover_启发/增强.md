## Insight 与数学支撑

现有 `REAL-SHAM` 同时改变 owner、actuator mapping 与 recurrent promotion，无法唯一归因于 shadow preparation。`SCRIPTED-RECOVERY-WITNESS` 又可在不 transfer 时靠较好命令击败 learned NEVER，因此原 opportunity 指标没有直接识别 `TRANSFER-RETAIN` 因果效应。

`FLEX(h;0,1,0,0)=STRUCTURED(h)` 只证明函数类包含。独立初始化和有限预算下 STRUCTURED 胜 FLEX 只能是有限优化/归纳偏置，不能叫 expressivity 必要性。

## 可增强方向

在同一 first application-valid checkpoint 和未来 tape 上做三路克隆：

- `RETAIN`：不转移；
- `TRANSFER-COPY`：同一合法 CAS/owner/actuator transfer，使用 incumbent state；
- `TRANSFER-SHADOW`：完全相同 transfer，使用预热 shadow state。

定义 `Δtransfer=Y_COPY-Y_RETAIN` 与 `Δshadow=Y_SHADOW-Y_COPY`。服务/尾部恢复为主端点，continuity、separation、slew、energy、bytes、latency 与 invalid commit 为 nonharm。若 competent same-information replay 在 deadline 内重建 shadow，或 `Δshadow` 非材料性，则关闭 shadow-specific 对象；仅 `Δtransfer>0` 时收窄为通用原子换机。

## Wave-3 新 insight：推断律比 sidecar 更上游

现行 24-block bootstrap max-t 存在精确有限样本反例。令一个合法的 `SHADOW-COPY MEAN`
block contrast 以 `24/25` 概率取 `0.04`、以 `1/25` 概率取 `-1`，则总体均值为
`-1/625`，但 24 个 block 全为 `0.04` 的概率为
`(24/25)^24=0.375413246727102`。在该事件上现有 zero-SE 规则返回点区间
`[0.04,0.04]`，错误越过 `0.03` material margin。99,999 次 bootstrap 无法发现经验样本
之外的稀有负尾；增加 resamples 或只改 zero-SE 不能修复。

因此当前新增 `PROSPECTIVE_INFERENCE_HOLD`。这不是 shadow 无价值的证据，而是说明在生成
24 个昂贵 checkpoint 之前，必须先决定：

- 降格为一次固定 24-root panel 的精确描述，不再声称总体置信或 promotion-grade VALUE；或
- 明确 block/master superpopulation、独立性、范围和 ratio denominator floor，换成有有限样本
  simultaneous validity 的方法，并先做 margin 对应的功效/资源设计。

## Wave-3 新 insight：两条 estimand 必须分别处置

`COPY-RETAIN` 与 `SHADOW-COPY` 的 support 不能先做全局 AND。任一轴未识别，不应抹掉另一轴
已经识别的效应。未来 reducer 应先分别产生 `identified/value/no-material/imprecise/harm`，
再组合。`GENERIC_TRANSFER_ONLY` 只有在 shadow 轴已识别且 no-material 时才成立；否则应报告
partial identification。

同理，same-information replay 仍然执行 transfer，因此它最多吸收 `Δshadow` 的独特信息/
预热必要性，不能抢占 `Δtransfer`。合法结果应允许组合表达，例如
`SHADOW_ABSORBED + GENERIC_TRANSFER_VALUE`。完整 replay ledger 还必须绑定 initial owner 与逐 tick
owner/CAS/promotion history，并覆盖所有进入 endpoint 的 triggered rows，而不只是 separation
witness。

## Wave-3 已实现增强

本轮没有继续购买完整 production，而是完成了最小可复用 TEST oracle：

- 独立 versioned phased sidecar：`begin_tick -> snapshot bridge -> clone_prepared`；
- handoff 绑定 owner/epoch/sequence/k/intent/snapshot/readiness/lineage，并拒绝 lane swap、stale、
  非有限、越界或修改错误 recurrent copy；
- 两 owner、RETAIN/COPY/SHADOW 的完整 native 54/58 vectors 与独立 Python causal oracle 完全一致；
- actor/snapshot/critic 各自逐维 masked Welford；`t*` 不进入 rollout-start `W^u`，forward 后才
  更新 `W^{u+1}`；
- live 与 typed replay 使用独立执行路径，显式消费 owner history 和 fragment-initial hidden，
  hidden/logits/old log-prob 完全一致，首次 optimizer mutation 前 ratio 精确为 1。

完整 DISH R06 方向测试由 DM 独立观察为 `48 passed in 5.16s`。其中 row 54 额外覆盖了
common SOURCE/lineage 以及 current/stale/absent 正负记录；read-only preflight 在 source-key
竞争下固定已加载句柄，不会回退编译。新鲜 V2 TEST preflight 的
oracle 通过，但总结果仍为 `passed=false,status=NOT_READY,production_mode_reachable=false`，并保留
两项 scientific hold；没有创建 master、checkpoint、coordinate 或 result。
