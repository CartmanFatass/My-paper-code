# RL/MARL 实证：比较对象与结论边界

## 先分清在比较什么

任务定义 reward 和允许的信息、动作及环境分布；算法与实现定义数据如何生成和使用；一次训练产生具体策略；评价协议规定怎样观察其表现。这几层可以分别成为比较对象。端到端结果不能自动归因于某个网络组件，而一个组件消融也不等于所有任务上的算法排名。

训练 return 来自正在探索或更新的行为过程；固定策略的评价 return 描述另一种执行条件。学习曲线、指定终点、验证集选取的 checkpoint 和事后最大值回答不同问题，应按实际协议命名。本资料不预先规定当前研究必须采用哪一个终点统计量。[Henderson 等，2018](https://ojs.aaai.org/index.php/AAAI/article/view/11694)

## 随机性有层级

环境交互步数是数据量；训练实例是一次完整生成与学习过程；评价 episode 是给定策略下的执行观测；checkpoint 是同一学习过程中的一个状态。多个 episode 可以更准确估计该策略的条件表现，不能自动变成多个独立训练实例。

Seed 只是随机性标签。独立性取决于生成过程，共同随机数和配对关系也取决于实际设计；相同编号不自动意味着正确配对，不同编号不自动证明独立。估计均值、分位数或其他统计量时，应让不确定性对应所要描述的层级。

跨任务聚合还涉及任务集合、权重和归一化。IQM、分布图、区间估计等是可选择的工具，不能脱离目标和数据结构作为统一规定。[Agarwal 等，2021](https://arxiv.org/abs/2108.13264)

## 完整方法比较与机制归因

完整方法可以包括网络、训练目标、经验使用和优化安排；比较应准确描述这套方法及条件。若要解释某个机制的作用，则需要能区分该机制与替代解释的比较。控制应服务于所问的问题，无需把所有可能因素列成每个实验的启动清单。

PPO/TRPO 的研究表明，具体实现选择可能实质影响结果；MAPPO 论文也讨论训练安排、critic 输入和若干实现因素。这些是有明确任务范围的经验发现，不能扩大成每个 UAV 实验必然发生相同效应。[Engstrom 等，2020](https://arxiv.org/abs/2005.12729)；[Yu 等，2022](https://arxiv.org/abs/2103.01955)

成熟库能减少重复实现并提供清楚的参考。是否正确接入当前任务，仍涉及 observation/action 接口、reward、终止处理和训练/评价模式等实际语义。这里只说明哪些差异可能改变含义，不创设额外审批程序。[MAPPO 官方实现](https://github.com/marlbenchmark/on-policy)

## return 和开销的地位

在同一任务目标下，return 描述策略获得的累计 reward。改变覆盖率、总吞吐、QoE 或公平性 reward，就是改变或扩展了任务目标；数值尺度不同的 return 不能直接跨目标判胜负。

正比例 reward 缩放在固定任务条件下保持固定策略排序，但会影响实际训练。这个不变性不要求无限时域或精确优化；一般 clipping 和 shaping 则需另行分析。数学边界见 [RL 专题](01_RL.md)。

样本效率、计算效率、执行时延和部署约束也可以成为研究目标；如何比较由当前问题、卡和适用规范决定。原讨论的局部排序选择另存于 [会话选择记录](../SESSION_CHOICES.md)，不构成其他方向的要求。

## 证据的力度随主张变化

一次探索可以支持“在这些条件和这个训练实例中观察到了该现象”，帮助发现错误、形成假设或排除解释。稳定优势、跨任务泛化、样本效率和机制因果作用需要各自匹配的证据；不存在从基础 RL 知识直接推出的统一 seed 数、显著性阈值或所有样本阳性要求。

结果可以支持、削弱或暂时无法区分一个机制解释。负结果不必然否定全部思路，也不能被任意改写目标掩盖。具体投入策略属于决策问题，不能写成文献已经证明的定理。
