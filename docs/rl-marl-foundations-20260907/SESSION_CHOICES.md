## 用户已明确选择的范围

- 保留现有环境与通信复杂度；本次执行期信息假设允许及时、可靠的团队摘要，同信息对照采用相同边界，业务通信原有复杂性继续保留。
- 先研究固定策略参数面对用户移动、暂时故障与恢复时的执行期适应。记忆、信念、技能状态及动作仍可随输入更新；固定参数不等于冻结所有状态。成员加入、跨团队规模泛化和参数在线更新留作后续问题。
- 以成熟 MAPPO 实现为主要对照，循环策略与集中 critic 的方向已经同意。
- 从覆盖率、总吞吐等简单目标开始，之后按问题需要设计 QoE、公平性等 reward；不同目标的 return 不能直接合成同一胜负排名。
- 本次比较以 RL return 为准，记录训练与执行开销但不把开销纳入本次排序。该局部偏好不撤销资源 cap、admission 或现行 Portfolio 的成本与投资规则，也不适用于其他方向的既有排序。
- 保留异步技能框架；历史方向可共享资料或组合，不要求全部成为最终算法部件。

## 可替换、可否定的机制假设

原讨论的共同问题是：环境或团队变化时，保留仍有用的合作，调整需要变化的部分，减少服务损失。学习可复用交互结构是一个待检验的机制假设；它可能支持技能选择、持续与局部调整，不能据名称认定有效。更少切换、更多角色或更清楚的可视化不能单独替代任务后果。

“继续投入应对应明确未决问题，而不只是不断换设置寻找正值”是原讨论采用的研究策略，不是教材定理或新实验准入条件。合作结构承载什么信息、如何改变执行、为何可能比循环 MAPPO 更容易学到有用行为，仍需推理和实证回答。
