## 量级：不是尾部事件

开发拓扑 8 集 × 1500 步：33.62% 的步、33.33% 的检查边界带重复持有，8/8 集全中。

更要紧的是它**吸收**：每集恰好一次起始，且每集 `dup_steps == 1500 - onset` 分毫不差。
若曾清除过，这个数会严格更小。它从不更小。所以不是三分之一的集偶发，而是**每一集在
后半程进入该状态且再不离开**。

## 我在同一个问题上连错两次机制

观测从未动摇，动摇的是我的解释。

1. 「LEAVE 重匹配不检查单射所以修不好」——**假**。`locked_duties` 为空时它弹出全部
   未锁任务再带 `pool.remove(best)` 贪心重排，本身就是单射，理应修好。
2. 「起始之后不再有 LEAVE」——**假**。每集起始后有 3 到 24 次 LEAVE。

两次都是**读代码去解释测量**，而不是去测量解释。第三次才先测后写：在 LEAVE 相与
REJOIN 相**之间**检查单射，覆盖 8 集全部 249 个同步步：

```text
dup_in   dup_after_leaves   dup_out      n
True     False              True       241
False    False              True         8
```

`dup_after_leaves` 全 249 步为 False，`dup_out` 全 249 步为 True。**LEAVE 相每次都把
映射修成单射，REJOIN 相每次都把它重新打破。**重复不是没人修的滞留状态，而是每个同步
过渡**被重新制造一次**。LEAVE 分支根本不需要改。

这条直接给第 8 轮定位了修复面，也解释了之前那个误导性的 `repaired_by_leave=0`：那个
计数器比的是整个 `step_once` 前后，修复早已被同一步的 REJOIN 撤销。**它测的是净效果，
不是相。**

## Pro 驳倒了我问题里的一条承重断言

我写「该缺陷只经由实际飞出的动作到达结果」。**假。**已在源码核实：

- `_stable_candidates_at`（`:2627`）遍历原始 `(d, u)` 对，双持机因此**两次**成为
  稳定认证候选；
- `_flex_survivors_at`（`:2663`）以 `survivors[u]` 按机号写入，两条记录**塌缩成一条**。

所以它同时改变**条件集与焦点动作身份**，遮蔽焦点测量一并受影响。

**错法比错误本身值得留。** 我查了 `extract_step_metrics` 与 `step_once`，确认二者不读
duty_map，然后就断言了关于**所有**登记量的事。查了一个消费者，推广到全部消费者；而我
用的 grep（`covered|coverage`）根本不可能命中 `_stable_candidates_at`——那个函数读映射
时一个词都没用上。**检索词从断言里来，就永远证伪不了那条断言。**

这正是 A3 的失败上移一层：A3 断言单射，再用一个只生成单射映射的生成器去「验证」它。
我在记录 A3 这个毛病的同一份文档里，犯了它的小号版本。
