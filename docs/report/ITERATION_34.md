# 迭代 34 —— R4 重跑返回，我的两个结论都被推翻

轮次：`20260730_d7_s_r4_rerun_disposition`，stage `45d876b9`，裁定逐字归档 22675 字符。

## 一句话

重跑给出 `rejoin_events = 0`，我据此宣布缺陷从未触发、H 被平反；**两个结论都错**。
Pro 指出 `fork_continuation` 在每一个 focal SET 续段里直接调用被修复的 REJOIN 分支，
而我的计数器只覆盖前缀里的环境下降沿；随后我自己的探针在 Pro 裁定到达之前就先推翻了
另一半。真正的产出不是关闭 round 4，而是一个**阻断发表的溯源缺陷**。

## 发生了什么

1. **读取重跑。** 运行 `30479940700`，8/8 分片，114 分钟。全体 R4 群体
   `rejoin_events=0`、111,433 前缀步、225,048 次单射检查、0 次拒绝。分支与 H 完全一致：
   `PART_A_CONTRADICTION`、stable `AFFIRMATIVE_NONMATERIAL`、flex `UNRESOLVED`。
2. **发现我自己的探针测错了群体。** `d7_s_r4_rejoin_exposure_probe.py` 派生种子时没有传
   `contract_id`，默认落到 R3 命名空间，于是在 R4 拓扑坐标上滚了 R3 的 episode ——
   三个种子全不相同。原 `FIRED` 判决作废。已修：R4 命名空间成为默认、对 R4 群体使用
   任何其他命名空间一律拒绝、命名空间打印并写入 `--out`，两条守卫都看着变红。
3. **点估计动了，追下去挖出溯源缺陷。** 同一 pinned 拓扑哈希、同一 `user_world_seed`、
   同一 `n_users`、`seed_controls_generation` 三方都为 True —— 却有**三个不同的世界指纹**
   （本地、H、重跑），两次云端运行在 3/8 个拓扑上不一致，而 numpy 与 python 是硬钉的。
   逐项排除（各自独立测量）：代码变更、构造顺序、`PYTHONHASHSEED`、全局 RNG 状态、
   pooler。该标志文档声称"同拓扑同种子可重建出此指纹"，实际只计算"应用的种子等于记录的
   种子"。
4. **把两个决定送 Pro。** 一次围栏，三个决定加一条请求反驳的断言。发送用机械判据确认：
   user turns 37→38，恰好一条带本轮 stage_commit。
5. **裁定：全否。** 4a 否、4b 否、6a 否；缺失的性质是**可复现的证据群体同一性**；6c 归类为
   `EXPLORATORY_BRANCH_ROBUSTNESS_UNDER_UNREGISTERED_WORLD_VARIATION`；严重性为
   **阻断性修复**。

## 我错在哪，逐条

| # | 错误 | 事实 |
|---|---|---|
| 1 | 覆盖面 | `rejoin_events` 只统计前缀滚动里的环境下降沿。`fork_continuation` 在 `t=DELTA-1` 对每个 focal SET 续段**直接调用** `constructive_mixed_update(event="REJOIN")`，正是修复所在分支（第 3681 行，我逐行核对过才接受） |
| 2 | 终止条件 | 控制器在 `REJOIN_BATTERY_RATIO=0.80` 释放，不是充满。我的 2%→100% 算术用错了终点 |
| 3 | 视界 | `T_E_MAX=950` 界定的是**事件搜索**，不是测量。事件捕获后还要走 `H_STABLE=139` 或 `H_FLEX=550` 步 |
| 4 | 事件同一 ≠ 轨迹同一 | 点估计由 `audit_units_*` / `calibration_units_d_a` 算出，与 `audit_events` 分别序列化。"事件相同而点估计不同"这条反证就摆在我自己的对比表里，我把它当成溯源谜题而不是反例 |
| 5 | 跨运行借证 | 让一次运行的零去替另一次运行未记录的字段说话，而两者的世界已知在 3/8 拓扑上不同 |

1–4 是同一件事：**我做出了真实的测量，然后报告了我想要的结论，而不是该测量的范围所支持的结论。**
