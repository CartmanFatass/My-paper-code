# 迭代 25:指纹完整性阻塞关闭;并在核验它时界定了它证明什么

日期:2026-07-27 · 分支 `untied-k` · 本迭代为支撑性工作,不消耗结论性迭代额度
(授权余量维持 17)。

## 发生了什么

1. **Stage B 阻塞关闭。** `full_state_fingerprint` 原本只分派三种形状且**没有
   `else` 分支**,dict、嵌套 list、set、自定义对象一律静默落空;它的 docstring
   却声称覆盖这些。改为递归规范编码器 `_encode_fingerprint_value`,无规则即抛
   `FingerprintCoverageError`——**"沉默"不再是第三个选项**。`EventSnapshot`
   把 `duty_positions_at_te` / `service_centroids_at_te` 改为必需参数,缺口无法
   由遗漏重开。提交 `96c0d02d`。

2. **修复中自带的缺陷,在送审前自己找到。** dict 分支最初按 `repr(key)` 排序;
   对未定义 `__repr__` 的键类,它 repr 成 `<Foo object at 0x...>`,排序**依赖
   内存地址**,同一状态在不同进程摘要不同——对池化分片是致命的,而在单进程内
   不可见。改为按编码后的键排序。这是阻塞本身的形状在下一层的重演。

3. **另外六个不可能失败的守卫。** 外审在连续两轮里找到两个,说明是写法习惯而非
   两次巧合,于是自查而不等第三轮。每一条都附一个"能让测试套保持全绿的生产代码
   变异",配对反例逐条观察过 RED→修复→GREEN。其中三条能移动结果分支;最危险的
   是自举确定性被写成 `f(x) == f(x)`,一个忽略种子的实现会通过它,同时塌缩一个
   方差分量并让 `LCB95(U*)` 过窄。

4. **一处环境缺陷。** `env.uav_leaves_count` 在 episode 尚未步进时就是 6。
   `regenerate_user_world()` 比对了两个成对不相交的用户世界,把整个外出服务簇记为
   离开。`t_e` 处的服务集状态正是指纹覆盖的对象。提取
   `_reset_connection_baseline()` 并在重建前调用;`reset()` 行为逐位不变。

5. **核验重写后的指纹时,发现它证明的东西比名字窄。** 相同 `episode_seed`、
   坐标、`coord_hash`、`user_world_seed` 的两次 `build_pinned_env`,
   `full_state_fingerprint` **不同**,4 次构造 4 个值,20 步后仍不收敛。机制:
   step 5 在 `reset()` 之后才覆盖充电站坐标,而 `reset()` 已用构造期(OS 熵,
   `scenario_base.py:328`)布局算完站点相关后勤量;实测
   `uav_return_threshold_ratios` 为 `0.56` vs `0.27`。第一步重算全部六项,永久
   残留的只有一个被污染的势差进入 `episode_graph_pbrs_sum`。

   **它够不到任何结论**,四条独立理由:`compute_G` 由分量字段计算且明确不复用
   `safety_reward_before_pbrs`;两个结论性调用点都每 episode 建一个 env、所有
   limb 从它克隆,偏移在 `SET − KEEP` 中抵消;`episode_world_fingerprint` 只摘
   九个用户/簇数组,实测完全一致;pooler 不做跨分片指纹相等断言,审计中唯一的
   跨构造比较断言的是窄哈希,其七个键均未被污染。

   被界定的是**含义**:R3 §C 所称"完整状态身份面"是进程内身份,不是跨调用可
   复现。两条配对测试从两侧锁住,各自对着自己的变异观察到 RED。证据笔记
   `20260727_D7_S_PINNED_ENV_IDENTITY_IS_WITHIN_PROCESS_ONLY.md`。

6. **`--workers` 判定通过并接线。** 云端 `30270540138` 在 `527ffd26`(指纹重写的
   后代)上两臂产物逐字节相同,由独立 SHA-256 复核而非采信作业自带的比较步骤。
   `--workers 4` 已进入审计分片,核数是测出来的:`nproc --all=4`——日志里的
   `nproc=1` 是 coreutils 遵从 `OMP_NUM_THREADS=1`,不是核数。池工作进程跑
   `_compute_audit_episode`,内部调 `run_audit_event`,并行覆盖主导的续演成本。

7. **成本:一个看似的跃迁被第三个样本判为抖动。** 三次云端测量同一量:
   `0.0864 / 0.0923 / 0.0784 s/step`,±9% 散布。`0.0923 > 0.0864` 曾像是指纹重写
   的代价;第三个样本低于两者。当时拒绝归因是对的——两个样本分不开原因和硬币。

8. **Stage B 第二轮发出并裁定:`ALIGNED`,零阻塞,审计放行。** 轮次
   `20260727_d7_s_stage_b_fingerprint_closure`,fence 在 `8cb5a232`,推理
   12m 56s。上一轮牵涉的七个实现缺陷全部失效;裁定明确这**不使**先前的
   `MISMATCH` 变成错的——被牵涉的那份实现已经被替换掉了。

   - **Q2 按我们的读法裁定**:R3 §C 冻结的是具体事件状态的**身份**,不是从
     注册种子重构该状态。我们"够不到任何结论"的四条理由被原样采纳。
   - **站点后勤重排现在不许做**:它会改变 step-0 状态与其后每条轨迹,裁定拒绝
     让它混进冻结运行。列为**搁置**的环境更正,附四条重启触发条件。
   - **成本天花板被降级**为运行调度风险而非科学阻塞,并明确成本投影是信息,
     不是缩减科学谓词的授权。

   传输两次踩坑,两次都是被检查而不是被运气拦下:标签页楔死两次(按程序换页);
   抓取前两次抓错——一次因缺焦点根本没触发(剪贴板里还是 fence),一次因页面
   虚拟化只渲染了首个回答的操作行,抓成了**上一轮**的裁定。由此立的规矩:一份
   抓取在断言它带有本轮 `stage_commit` 之前不得归档;长度和非空什么都不证明。
