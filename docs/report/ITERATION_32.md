```text

     实测：--population r4 --topology-seeds 20260734 20260734 ... -> 身份获批；
```

**B-1 是 D' 自己开的洞。** 它替换掉的推断式路径 `r4_artifact_identity` 拒绝同一个
列表（实测 `None`）。修复一个溯源缺口时，引入了一个比它替换的代码更宽的入口——
制品不是缺少种群证明，而是**携带了一份通过的、关于它并不具备的种群的证明**。

由此产生的常设约束：**被否决的闸门，其修复本身也要过闸门。** PM 自己核验不是同一
项检查，作者是拿自己造的东西去对自己持有的意图，找不到这一类。

## 险些成为事故的两处

**一、`launch_and_watch_run.ps1` 对一个已以退出码 3 结束的进程报告 `LAUNCH_VERIFIED`。**
检查的是 stdout **是否存在**而不是**是否有内容**——`Start-Process` 立刻创建重定向目标。
这个工具复现了它自己被写出来要检测的孤儿签名。

**二、配对负例工具的残留检查会"喊狼来了"。** 它检查变异后的文本**是否出现在文件任何
位置**，于是当替换文本恰是文件里合法的子串时，对一个已正确还原的文件报警。守卫的对象
是"别把变异过的生产代码留在树上"，而一个乱报警的守卫会在最需要它的时刻被忽略。已改为
与备份逐字节比对。
