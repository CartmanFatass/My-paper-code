   driver 触发)、逐 episode stderr 进度输出、按拓扑分片的无损序列化与汇总

2. **smoke #2 被用户裁定为无价值并关闭**(4 小时以上、4 个审计 episode,

   n_eval=8,每事件约 48 次 fork)投影 2–4 天墙钟。8 分片全部终止,部分产物
   删除。合同本身仍冻结;其副本量的科学必要性成为下一轮 Pro 问题。
4. **工作流整体重构**(用户逐条裁定,参照 HMASD-new 项目移植):
   - 八步环:pro科学决策 → 代码决策 → pro关键决策审阅(无exp)→ 收敛执行
     计划 → 实施 → review与测试 → exp → pro科学决策;
   - 两段式触发审计(Stage A 设计断言 / Stage B 代码-科学一致性 diff),
     `review_stack=false`,例行实现前审查废止;griller/reviewer/verifier
     降为按需(须书面指名错误主张风险);
   - `EVIDENCE_COMPLEXITY_POLICY.md`:非正式 ≤20 分钟、正式迭代投影 ≤8
     小时、预启动零计算成本上界必填、超限 = `NON_EXECUTABLE_EVIDENCE_DESIGN`
     (零迭代成本,仅用户可授命名例外);
   - `ALGORITHM_PRINCIPLES.md`(原为孤儿文件)同步至参照版本并接入
     AGENTS.md/CLAUDE.md 读取路径;
   - Pro 轮次只载决策、不载检验劳动;问题数量不限;
   - 每份迭代报告以时间分布表收尾,科研推进占比 <50% 记为事故。
