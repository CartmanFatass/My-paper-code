## 1. 科学问题与决定

**问题**：在一个"确实包含异质更新紧迫性"的源上，学习型保持（learned-keep）载体
能否形成不同的更新行为？这是 D7 的第二个阶段（D7.2B），是一个**阳性对照**——
它不检验算法优劣，只检验"载体在紧迫性确实存在时能否表达它"。

**决定**：`two_timescale_role_free_actions` **退休**，不再作为 D7 的阳性对照。
理由是它允许一个**从不保持承诺**的最优解，因此在它上面得到的阴性结果对载体
不构成任何信息。

这是一次 **benchmark-comparator pair** 的退休（`AGENTS.md`，*Result
interpretation* 中"基准不提供访问、或无法区分候选"那一行），**不退休载体、不退休
估计量、不退休 P1–P4 组合**。

三次运行，全部非正式：

| 运行 | 预算 | 结果 |
|---|---|---|
| 无状态访问对照 | 200 更新 × 1 epoch，lr 1e-4 | 首 20 更新 `0.442187` → 末 20 `0.475195`，随机水平 |
| 直接状态筛选 | 200 更新 × 1 epoch，lr 1e-4 | `0.443164` → `0.449414`，平坦 |
| **能力运行** | **1000 更新 × 3 epoch，lr 1e-3** | 更新 100 达 `0.984375`，更新 218 达 `1.000000`，末 20 更新全部为 `1.0` |

**预算是这次最重要的工程教训**。前两次运行给高层策略的优化步数只有 **200 步**，
学习率 1e-4；在更新 150 时 `keep_prob` 仍为 `0.599`（初值 0.6），技能分布熵
`1.096`（最大值 `ln 3 = 1.0986`）——策略根本没有离开初始化，而梯度范数在
`0.26–0.48` 之间非零。**非零梯度加行为不变**，正是本项目在 G20 上学会不信任的
签名。把它读成"信用分配失败"会是一个错误的科学结论；真相是 200 步优化不够。

同样的陷阱就摆在先验证据里：该 toy 上唯一的历史记录 `EXP-20260715-r39-native-hmasd-toy-credit`
报告 `VALID_FAIL_..._CREDIT_ANCHOR`，`match = 0.455`——但它的归档契约显示只跑了
**20 次外层更新、12,800 步**，是本次筛选预算的十分之一。那是"20 次更新内没学会"
的证据，不是"学不会"的证据。

## 3. 证据闭合

**能力达成（条件 A）**：`slow_match = 1.0`，`fast_match = 1.0`。这是该源上**第一次**
由任何配置达到能力门槛。

**但在能力状态下，策略从不使用 KEEP**。两个智能体在每一次检查都 SET，彼此反相，
`skill_age` 在每次检查都是 5：

```text
c1  a0 inc=2(y) SET->1(x)     a1 inc=1(x) SET->3(y)
c2  a0 inc=1(x) SET->2(y)     a1 inc=3(y) SET->1(x)
c3  a0 inc=2(y) SET->1(x)     a1 inc=1(x) SET->3(y)
```

**机制是结构性的，不是这个 checkpoint 的偶然**。团队奖励取两种分配中较好者，所以
任何"一个体持有正确 x 技能、另一个体持有正确 y 技能"的配对都得 `1.0`。从
`(A = x+, B = y+)` 出发，当快目标翻转到 `y-`，所需集合 `{x+, y-}` 有两条到达路径：

| 路径 | A | B | token |
|---|---|---|---|
| 保持 | 保持 `x+` | `y+ -> y-` | KEEP, SET |
| **交换** | `x+ -> y-` | `y+ -> x+` | **SET, SET** |

交换永远可用：SET 只屏蔽**在位技能**，而交换中两个体都移动到自己当前不持有的技能。
于是存在**两个不同的最优解，其中一个从不保持**，每个承诺的实现寿命被钉死在恰好
一个检查间隔。

满功率 ledger（384 行 / 24 回合）给出推导的两个预测，无一例外：

```text
token_kind   全表只有一个取值：SET —— KEEP 一次都没有出现
skill_age    第一次检查之后恒为 5 —— 每个承诺恰好活一个检查间隔
```

**阳性对照必须使目标行为成为"必要"，而不只是"允许"。** 这个源让它成为可选，
所以阴性结果什么也不说明。

## 4. 注册结果

对**最终 checkpoint** 的满功率审计（24 回合 × 4 复制，336 对，0 丢弃）。审计对象在
训练仍在进行、任何审计都还没跑过时就已在契约中声明为"该次运行的最终 checkpoint"，
中间 checkpoint 只能作为训练轨迹注记。

```text
分支  NONFORMAL_NO_URGENCY_SEPARATION_D7_2B
      act_sequence 分支 = learned_keep（更新紧迫性只在这一支可观测）
```

归一化常数在审计之前由两个源对照测得（构造性最优 − 无更新零假设）：

| | 构造性 | 零假设 | `B_H` | 窗口数 |
|---|---|---|---|---|
| `H = 30` | 30.000 | 20.000 | **10.000** | 72 |
| `H = 5` | 5.000 | 3.125 | **1.875** | 192 |

| 条件 | 量 | 均值 | LCB95 | UCB95 | 门槛 | 判定 |
|---|---|---:|---:|---:|---|---|
| **A** 能力 | `slow_match` | 1.0000 | 1.0000 | — | ≥ 0.75 | **通过** |
| | `fast_match` | 1.0000 | 1.0000 | — | ≥ 0.75 | **通过** |
| **B** 干预分离 | `U~_flex` | 0.43006 | 0.40828 | — | LCB ≥ 0.10 | 通过 |
| | `U~_stable` | 0.25186 | — | 0.27496 | UCB ≤ 0.05 | **失败** |
| | 差 | 0.17820 | 0.15908 | — | LCB ≥ 0.20 | **失败** |
| | `U~_opp,flex`（分半） | 0.43006 | 0.40828 | — | — | — |
| **C** 自然对齐 | `P(SET \| flex)` | 1.0000 | 1.0000 | — | LCB ≥ 0.75 | 通过 |
| | `P(KEEP \| stable)` | 0.0000 | 0.0000 | — | LCB ≥ 0.75 | **失败** |
| | 差 | 0.0000 | 0.0000 | — | LCB ≥ 0.50 | **失败** |
| | 全同步 SET（混合紧迫） | 1.0000 | — | 1.0000 | UCB ≤ 0.25 | **失败** |

同标签更新记为 `NOT_APPLICABLE_STRUCTURALLY_EXCLUDED`——learned-keep 下在位技能被
从 SET 分布中屏蔽，报告零是同义反复而非证据。

**三点需要读进去的细节。**

其一，`U~_stable = 0.252` 是**关键数字**，不是 `U~_flex` 的大小。低紧迫职责的持有者
更新一次，价值仍达到全部更新余量的四分之一——这正是交换解的签名：在交换协调下
**两个体的更新都是承载性的**，强制低紧迫的一方 KEEP 会打断其伙伴已学会预期的协调。
B 失败于两处：`U~_stable` 是天花板的五倍，且差值 `0.178` 未达 `0.20`。

其二，早先 2 回合的机器校验给出 `flex 0.214 / stable 0.232 / 差 −0.018`，看起来是
"完全没有分离"。满功率下差值其实为正（`0.430` 对 `0.252`），只是不足。**小样本的
负号是伪影**；这就是为什么审计对象与功率必须在看到结果之前定好，也是为什么机器校验
的数字不能当结果用。

其三，`U~_opp,flex` 与 `U~_pi,flex` 在五位小数上完全相同（`0.43006`）。分半样本在
非在位技能上取最大，得到的正是策略自己的选择——在一个确定性最优策略上这是应有的
一致性，也说明估计量实现正确。

C 的三项全部是**精确的 0 或 1，24 个回合零方差**：策略在每次检查都对两个体 SET。

## 5. 对猜想的影响

**不改变任何猜想的状态。** 一个退化的源无法支持关于载体的任何断言，无论正面还是
反面。P1–P4 组合、C-EHC、C-COORD 全部按原样保留。

一个**新登记的开放观察**（不是结论）：两个最优解得分相同，而策略走向了不保持的
那一个，并且载体自身的初始化使那条路径更便宜——`keep_head.weight` 是零初始化的，
所以 `keep_logit` 起始与状态无关；交换只需要一个标量偏置下移加上本就依赖状态的
技能头，而保持需要 `keep_head` 学出**依赖状态的权重**。

事件 ledger 证实了这一点而不只是提示：能力状态下 `keep_prob` 在
`0.000416 – 0.009945` 之间均匀塌缩，且不携带 regime 信息——

```text
flex     n=14   mean 0.002853   std 0.00267
stable   n=14   mean 0.003998   std 0.00305
regime 间差 0.00115  <  regime 内 std 约 0.003
```

`keep_head` 从未获得状态依赖性，它只是把偏置降下去然后停住。整个 toy 是靠技能头
解决的，而这条研究线要研究的那个更新决定**退化且未被使用**。这条观察是在发送前的
对抗性检查中被找出来的，当时我自己的处置意见正在把它压掉。

## 6. 被排除的结论

必须明确**不能**说的话：

- 不能说"载体无法表达更新紧迫性"——源退化，阴性无信息量；
- 不能说"信用分配失败"——那是 200 步优化的产物，能力在 3000 步下达成；
- 不能说"该 toy 在信用上不可学"——先验记录只有十分之一预算；
- 不能说"直接状态访问没有帮助"——无状态对照末段 `0.475` 略高于直接状态筛选的
  `0.449`，但两者都在随机水平，差异是噪声，且两个策略都没有离开初始化；
- 不能说"载体偏好全同步更新"——那是第 5 节的开放观察，需要在一个**非退化**的源上
  预先注册后才能测量，不能事后宣称。
