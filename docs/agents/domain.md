# Domain documentation

HMASD uses a single project context.

Before planning or implementation, read `CONTEXT.md` and any relevant ADR under
`docs/adr/`. If an expected document does not exist, continue without creating
one merely to satisfy the layout.

Use the exact project vocabulary in specs, tickets, task prompts, tests, and
code. If a needed term is ambiguous or missing, surface that gap rather than
silently inventing a synonym. Explicitly flag any proposal that conflicts with
an existing ADR.
