This is a new, independent UAV boundary after the toy-domain chain. It does
not reopen G33, reinterpret G51, or consume a conclusion-bearing iteration.
The user has explicitly authorized this transport. The purpose is to ask
External Pro to freeze the smallest executable G0 contract for testing whether
the registered UAV service task is physically feasible and whether its outcome
causally requires roster-triggered reallocation.

The audit must remain design-sized and zero-compute. It must not authorize
training, formal evaluation, checkpoint production, code acceptance, or a
paper-level robustness claim. The existing closed G1 temporary-loss source is
background only and cannot be relabeled as evidence for G0.

The proposed G0 boundary is deliberately narrow: compare an oracle or
constructive reallocation controller, a same-information constructive
controller if admissible, and a ledger-blind/no-reallocation control under
identical physical and disturbance randomness; freeze the observability,
ownership, feasibility, access and causal-necessity predicates before any
learned algorithm is introduced.

External Pro must decide whether this is the correct next boundary, provide
the smallest frozen contract if so, and state the exact result-sensitive gates
that would permit or reject a later G0 execution.
