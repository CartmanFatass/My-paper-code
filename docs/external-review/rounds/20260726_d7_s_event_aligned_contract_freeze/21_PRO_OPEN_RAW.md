# Cluster 1 — Flex-event machinery

## Q-E1 — Event anchor and (H_{\mathrm{flex}})

### Ruling: anchor at the first registered LEAVE boundary, not at `battery == 0.25`

Define (t_e) as:

> The first shared pre-action/check boundary in an episode at which a UAV has undergone a planned, capture-based transition from `ACTIVE` to `CHARGE_ABSENT` under the registered G2 constructive charge-rotation controller.

This is the point at which a duty is actually vacated under the registered service-lifecycle semantics. G2 keeps a UAV active during ordinary return transit and enters `CHARGE_ABSENT` only at charging capture or cutoff; it records exact LEAVE and REJOIN boundaries.

The former `0.25` trigger is a harness policy choice:

```text
return_reserve_ratio + 0.15
```

It is not registered in the G2 source contract and should not become a scientific event definition merely because the superseded harness used it. The environment itself distinguishes:

* reserve ratio `0.10`;
* minimum return threshold `0.25`;
* emergency threshold `0.05`;
* service cutoff `0.02`.

These are different semantics, not interchangeable candidate event anchors.

### Repository-fact correction

The question’s statement that `uav_target_stations` is set only inside capture range is too narrow. On a normal active UAV, a policy dock request sets both `uav_dock_requests` and `uav_target_stations` before capture; capture additionally requires a dock request, sufficiently low speed and distance within the capture radius. Both fields are reset each step, however, so they do not constitute persistent transit state.

The binding event is therefore the service-lifecycle LEAVE transition. Its conformance record should contain:

* pre/post service status;
* `last_charging_arrival` or the corresponding capture edge;
* `uav_charging`;
* `uav_dock_requests`;
* `uav_target_stations`;
* battery ratio;
* return-energy margin;
* UAV and station positions;
* station occupancy and queue length;
* and the source-control schedule identity.

`uav_dock_requests` and target station help explain the event; they do not replace the LEAVE edge.

### Planned-event eligibility

The primary flex event excludes:

* emergency cutoff/depletion-driven absence;
* an occupied station or nonzero queue at the selected station;
* temporary failure;
* and a LEAVE not generated by the registered constructive charge schedule.

These may be separate later strata. The first source gate should identify ordinary energy-driven handoff without mixing in queue and catastrophe mechanisms.

### (H_{\mathrm{flex}})

Register:

[
\boxed{H_{\mathrm{flex}}=550\ \text{steps}}
]

from the LEAVE boundary.

The conservative derivation uses:

* service cutoff (0.02);
* rejoin ratio (0.80);
* battery capacity (160) Wh;
* charging power (1000) W;
* hover consumption (P_0+P_i=168.49) W;
* next-check alignment at (\Delta=10).

Thus the worst planned, nondepleted charge duration is approximately

[
\frac{(0.80-0.02)\cdot160\cdot3600}
{1000-168.49}
\approx 540.3\ \text{steps},
]

which rounds to the next shared check at 550.

The horizon does not include the outbound trip: the event begins at capture/LEAVE, after that trip. It also does not include a post-charge return leg, because G2 schedules service REJOIN when the inactive UAV reaches (0.80), at the next pre-action boundary.

If the audit later admits queued LEAVEs or cutoff/depleted captures, this (H) no longer has the stated guarantee and the event class must be separately registered.

### Dependency

This ruling changes:

* the censoring deadline from step 1050 to step **950**;
* the energy profile needed for event support;
* the event certification;
* and the compute envelope.

# Cluster 2 — Controllers and estimands

## Q-C1 — `constructive_mixed`

### Binding reference

Yes: G2’s `CONSTRUCTIVE_CHARGE_ROTATION` is the binding semantic reference. It:

* forward-plans energy;
* schedules latest safe station arrival;
* charges to (0.80);
* and recomputes survivor targets at LEAVE/REJOIN.

### Operational definition

`constructive_mixed` must:

1. Run the registered deterministic charging schedule.
2. Preserve every active stable incumbent’s target between lifecycle events.
3. At a LEAVE:

   * remove the absent UAV from the airborne duty map;
   * preserve feasible stable targets and their incumbents;
   * recompute flexible service targets for the current airborne fleet;
   * reassign the vacated service capacity to the best legal survivor;
   * never deliberately leave the vacancy unserved when legal survivor coverage exists.
4. At REJOIN:

   * restore the UAV to the airborne set;
   * recompute flexible survivor/rejoin targets;
   * preserve feasible stable incumbents.
5. Between LEAVE and REJOIN, do not perform full-sync role permutation at every check.

The word “vacated duty” does not require preserving the old centroid as an immutable named role. Covering the vacancy may be realized through re-clustering the remaining service targets. What is required is reoptimization of service coverage after the fleet loses one active member.

### Null

`null` begins from the identical event prefix but freezes the pre-event duty ownership/map for the entire mechanism horizon:

* the charging UAV physically leaves under unchanged energy physics;
* its former duty receives no proactive replacement;
* survivors retain their prior targets;
* a later REJOIN does not trigger proactive target reoptimization within the audited window.

This is the event-aligned realization of `NO_PROACTIVE_ROTATION`.

### Consequence for (B_{\mathrm{flex}})

[
B_{\mathrm{flex}}
=================

## G(\text{constructive_mixed})

G(\text{null})
]

is therefore the value of reallocating service after the vacancy, under the registered safety objective.

## Q-C3 — Legal SET alternatives

### Event-time duty map

At (t_e), snapshot:

1. the pre-LEAVE incumbent duty map;
2. the post-LEAVE `constructive_mixed` survivor target map;
3. the physical target vacated by the leaving UAV.

For the one-(\Delta) intervention, the legal target set is:

[
\mathcal Z(h)
=============

{\text{post-LEAVE relay and service targets}}
\cup
{\text{vacated pre-LEAVE target}},
]

deduplicated geometrically.

The target set is held fixed for the focal intervention’s ten steps. At (t_e+\Delta), the common constructive continuation may recompute it.

### Exclusions

Exclude only:

* the focal incumbent target;
* targets outside the physical source/action domain;
* assignments requiring the focal UAV to be absent, charging, failed or otherwise non-acting;
* assignments violating hard safety/action support.

Do **not** exclude a target merely because it cannot be reached within (\Delta). Transit cost is part of the causal consequence of SET and must be evaluated by the dynamics rather than removed from support.

### Airborne support

Only active airborne UAVs may be selected as focal or non-focal service owners.

Duties themselves are not restricted to “airborne duties”; they are physical relay/service targets to be assigned among the airborne fleet.

### Cross-duty assignments

A service focal may take a relay target, and a relay focal may take a service target. Fixed role-class restrictions would reintroduce supplied semantics and could exclude the best legal SET alternative.

### Vacated target

Yes, the vacated pre-LEAVE target is explicitly included. If the post-LEAVE oracle’s re-clustering makes it redundant, the maximization will simply select another target.

### Joint continuation

For every focal candidate (z), all other airborne assignments are reoptimized one-to-one under the same `constructive_mixed` rules. If there are more target candidates than airborne survivors, the continuation chooses which target is uncovered by maximizing (G).

### Event latches

Use **window-local event latching** for the D7.S event-conditioned audit.

* record the current cutoff/depletion masks;

* environment episode-latched counts;
* analyzer window-latched counts.

# PM-handled items

## Topology pinning

The proposed mechanism is **not sufficient as written unless one ordering detail is added**.

Scenario 7 calls `_init_charging_stations()` during every `reset`. Thus:

1. construct a topology template under the topology seed;
2. record BS/station coordinates and their hash;
3. create a fresh environment for each arm/replicate;
4. reset it with the episode seed to initialize users and dynamic state;
5. **after that reset**, restore the recorded BS/station coordinates without consuming the episode RNG;
6. rebuild channel/routing state;
7. assert the coordinate hash before prefix replay.

Calling the explicit topology initializers before a later episode reset is insufficient because that reset can replace the station coordinates.

The conformance derivation must prove:

* same topology seed yields the same coordinate hash;
* episode seeds do not alter the pinned topology;
* different topology seeds yield the registered population;
* every paired arm carries the same hash.

## Standing provenance rule

Confirmed. Auditing prior Scenario-7 results only when they are reused as causal comparators or paper-level premises is the correct scope. It need not reopen unrelated closed work.
