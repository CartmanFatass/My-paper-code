# Benchmark Identifiability and Ordinary Access — Contract Design

## Purpose

The accepted opportunity-audit disposition permanently stops the exact
Generic-SHORT supplied-executor F1 toy and selects one independent evidence
class: `BENCHMARK_IDENTIFIABILITY_AND_ORDINARY_ACCESS_G0`.

Before implementation, this round must produce a code-ready scientific
contract for a minimal anonymous dynamic-team task that is structurally
reachable, resistant to calendar/static pre-positioning, externally harmed by
a shared-renewal or common-lifetime restriction, and accessible to an ordinary
recurrent controller.

The two blind open reviewers propose and attack a plural portfolio of benchmark
designs. The controller reconciles facts without ranking. Convergent Pro selects
one exact contract or stops. Nothing in this round authorizes code or compute.

## Required objects in one frozen result

- **H:** legal-authority constrained non-causal hindsight ceiling.
- **C:** capacity, exposure, communication and control-frequency matched
  calendar/static recurrent null.
- **S:** full-future shared-renewal or common-lifetime hindsight ceiling using
  the same primitive behavior support as H.
- **D:** causal ordinary recurrent learner with current anonymous process
  evidence and a declared permutation-safe active-set summary.

The final contract must specify exact task dynamics, observations, primitive
actions, external reward, membership schedule distribution, online demand,
train/held-out distributions, H/C/S/D information boundaries, model, budget,
seeds, checkpoint choice, absolute floors, material margins, confidence rules,
validity checks and mutually exclusive terminal branches.

## Scientific boundaries

1. This is a new independent task, not a Generic-SHORT rescue or parameter
   change.
2. No hierarchy, skill labels, high tokens, KEEP/SET actor, supplied executor,
   intrinsic reward, posterior, graph, field, slot, hazard, team latent, new
   critic or task-shaped input.
3. Do not manufacture D failure by truncating BPTT, freezing hidden state,
   shrinking the model, withholding causal information or making intervals
   arbitrarily exceed a chosen memory.
4. Anonymous JOIN/temporary LEAVE/REJOIN/genuine JOIN/terminal LEAVE and
   survivor continuity are mandatory.
5. Optimal member commitment lengths must differ for causal online reasons,
   and the common-lifetime restriction must cause external loss rather than a
   diagnostic score change.
6. Hindsight proves structural authority only. D must establish ordinary
   learnability before any later abstraction comparison is interpretable.
7. Prefer a small CPU/CUDA-friendly task and reuse active-set/recurrent runtime
   structure where semantics match. Do not stack modules to make the task hard.

## Open design question

Which two to four concrete task contracts best separate:

- calendar/static scheduling K;
- ordinary recurrence D;
- persistent event abstraction R;
- true heterogeneous-lifetime pressure;
- mere task or model inaccessibility?

Open reviewers must not select one final contract. They must provide concrete
numbers and strongest failure modes so the convergent reviewer can select a
single executable design rather than leaving scientific choices to the Code
Implementation Manager.
