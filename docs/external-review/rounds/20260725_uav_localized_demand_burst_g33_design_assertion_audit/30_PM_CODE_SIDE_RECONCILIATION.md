## Exact implementation-alignment gap

The six control names are closed, but three result-bearing controller decisions
remain non-unique in code:

1. `exact current relaxed end-to-end service potential` does not state which
   physical quantities are recomputed at a hypothetical target layout, which
   are frozen from the current snapshot, or the exact scalar aggregated across
   users and time.
2. `FULL_LEDGER_REACHABILITY_ORACLE` may use the complete remaining ledger, but
   no exact future-horizon objective or legal target-selection procedure says
   how that ledger chooses one candidate layout at each pre-action boundary.
3. `STATIC_FULL_LEDGER_PREPOSITION` may preposition before onset, but its exact
   target-selection time, objective and action path are not uniquely fixed.

Those choices can change full-ledger reachability, current-only access and the
static counterexample. They are scientific control semantics, not tensor
packing or vectorization. PM therefore will not select them locally.

The raw deliberately leaves universal N1 coverage unresolved. The code also
needs an exact certificate interface or an explicit instruction that no source
runner may set `static_upper_bound_complete=true` from the finite layout
library alone.
