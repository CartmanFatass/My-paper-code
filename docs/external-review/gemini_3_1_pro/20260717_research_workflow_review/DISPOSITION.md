## Accepted

1. Operational serialization and epistemic singularity were conflated. The
   project should keep several competing causal explanations while running at
   most one evidence source at a time.
2. Repeated bespoke toys displaced the final target. A candidate that omits
   both membership change and heterogeneous skill lifetime must justify its
   information gain rather than merely expose another learnable substrate.
3. Several rounds changed environment, representation and learning target
   together, weakening cross-round causal accumulation.
4. R55 must pause before testing. Its fixed-membership, fixed-horizon edge toy
   does not currently distinguish the live explanations for the joint
   variable-`N` plus variable-lifetime problem.
5. The strongest ordinary reduction is a fixed-capacity policy with inactive
   masks/dummy agents and synchronous padded skill persistence. It belongs in
   the hypothesis portfolio, not only in a final objection paragraph.

## Modified

1. The response overstates implementation artifacts as a general explanation.
   Most recent terminal gates passed their registered M0 checks. Their exact
   contracts remain valid failures; what remains open is how those failures
   update broader architecture hypotheses.
2. `Global Autoregressive Skill-Sequence`, `Continuous-Time Anonymous Graph`
   and `Decentralized Event-Driven Option-Critic` are provisional architecture
   families, not authorized implementations. Each still has unresolved
   probability, credit, HMASD-semantic and scaling contracts.
3. The proposed shared-testbed experiment is not yet launch-exact and risks
   becoming another bespoke environment. Existing R41--R54 evidence and the
   curated literature must first be mapped against the portfolio.
4. R55 does not have literally zero information value: it could test a narrow
   direct-edge representation claim. It is paused because that claim is not a
   current discriminator of the final architecture hypotheses.

## Live hypothesis portfolio

1. **H0 — ordinary masked/padded MARL.** Fixed maximum roster, inactive masks
   or dummy agents, synchronous checks and repeated skills. This is the
   complexity-reduction baseline that can falsify the need for a new
   architecture.
2. **H1 — autoregressive event-token coordinator.** Retain ordered HMASD/MAT
   coordination and represent join, leave, KEEP, SET and termination as
   variable-length policy events with duration-correct credit.
3. **H2 — anonymous dynamic relational coordinator.** Replace global set
   summaries with local member/entity relations on a dynamic graph or field,
   while retaining an exact joint probability and event ledger.
4. **H3 — decentralized termination with invariant active-skill context.** Let
   agents request or terminate skills independently and coordinate through an
   anonymous active-skill summary; test whether the lost autoregressive
   bandwidth is material.

These are competing explanations, not four implementation tasks. Their current
relative support remains unidentified.
