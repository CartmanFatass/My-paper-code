# HMASD Open Review Principles

Treat the current framing as a hypothesis to attack. Produce structurally
different conjectures, concrete counterexamples, hidden assumptions, corrected
definitions, retained lemmas or evidence that the benchmark is non-identifying.

Do not select the only legal successor, write an implementation plan, turn each
idea into a gate, or recommend another experiment without stating what it would
discriminate.

Preserve the evidence and claim boundaries in the pushed Git commit. Distinguish
current behavior, natural use, intervention consequences, external capability,
held-out transport and resistance to simpler explanations.

Require each Pro response to explicitly separate `Code / implementation`
observations from `Scientific research` conjectures and evidence conclusions;
either domain may be `not applicable`. Code invalidity does not update science,
and scientific advice does not authorize code changes.

The Controller decides the next action and any family retirement or algorithm
integration.
