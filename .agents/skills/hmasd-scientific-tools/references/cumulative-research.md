# Cumulative research: optional reasoning examples

This is a reference for `hmasd-scientific-tools`, not a new policy, required checklist,
record type or pre-experiment gate. The DM uses the existing NOTES entry and the relevant
source evidence. No model, dataset, simulation or fit is commissioned by reading this page.

## What an explanation update looks like

A useful entry connects a prior judgment to evidence and a subsequent choice. It can be short:

> We expected retained entity history to reduce errors after replacement. The complete package
> lost; the available summary has no event-local behavior. This weakens reliance on the package,
> but does not separate stale history from optimization burden. Inspect the retained trajectory
> fields first. If they are absent, record that limit; a new measurement needs its own declared
> scope. We have not diagnosed stale memory or earned another automatic fit.

Use observations, conditional inference and new conjecture as distinct kinds of statement.
"Nothing here discriminates the live explanations" is acceptable. Do not invent numeric
posterior confidence, causal labels, an optimal information-value calculation or an insight
simply because a reflection heading exists. The changed explanation belongs to the DM; adviser
agreement, a successful test suite and process completion are not empirical replication.

For a targeted repair, state an intermediate and a native-outcome prediction. If the return
improves without the intermediate change, retain the performance result but reconsider its
explanation. If the intermediate changes without useful return, the proxy-to-control link is
weakened on that test, not automatically every use of the representation.

## Simple-model prototypes: examples, not a ladder

**Switching/termination.** In a bandit with a hidden reward regime and explicit switching cost,
compare switch versus hold under a declared continuation law. Distinguish value difference from
policy probability difference. Under the *additional* Boltzmann assumption
`pi(a|h) proportional to exp(Q(h,a)/tau)`, the log-probability gap is the Q gap divided by tau.
That identity does not assert that the learned HMASD coordinator satisfies the assumption.
[Option-Critic, termination-gradient discussion](https://arxiv.org/html/1609.05140v2)
is a source for value-linked termination, not evidence for a particular policy-gap heuristic.
The MARL bridge must restore coupled team commitments, decentralized information and endogenous
teammate learning before making a multi-agent claim.

**History ownership and drift.** In an independent Bernoulli entity-bandit construction,
a Beta prior plus successes/failures provides entity-indexed sufficient statistics. Temporary
absence, replacement in the same slot, and drift within the same identity are different events.
This is our proposed elementary model, not a result about the project.
[Bayesian online changepoint detection](https://arxiv.org/abs/0710.3742)
offers run-length uncertainty for changing generators. Its assumptions need not hold when the
"generator" is another co-adapting learner. Show exactly which history, action and observation
rights survive the simplification; do not grant hidden identity or change labels to a policy.

**Relevant interaction versus distractors.** A contextual bandit with set-valued input and
irrelevant entities can separate relational representation from sequential credit. A small
joint-action game can then expose coordination that the bandit removed.
[OPT, Sections IV-A/IV-B](https://arxiv.org/html/2207.03902v4)
motivates sparse, diverse interaction prototypes and their recombination inside MARL value
learning. Borrow the mechanism question, not an assumption that attention explains causality
or that an interaction prototype is a controllable skill.

A prototype can be an equation, counterexample, existing benchmark or bounded experiment.
Choose it only when it changes a disputed judgment. Success does not establish UAV benefit;
failure constrains only genuinely shared assumptions. No complete oracle, exhaustive census,
literature sweep or favorable toy result is required before useful direct exploration.

## Selective lessons from research-agent projects

Primary sources were consulted for the owner-requested 2026-09-19 revision. These are external
design precedents, not validation that the local workflow improves discovery.

| Source | Borrow | Do not import |
| --- | --- | --- |
| [AI co-scientist, Section 3.3.6](https://arxiv.org/html/2502.18864v1) | Feed recurring, evidence-grounded criticisms into subsequent reasoning, rather than restarting from a fresh idea list | Model voting/tournament rank as empirical truth; a new standing meta-review role; repeated debate as replication |
| [AI Scientist-v2, Section 3.2](https://arxiv.org/html/2504.08066v1) | Preserve parent-child links among debugging, revision, tuning, ablation and replication; distinguish their questions | Mandatory stage progression, spent-budget progression, or best endpoint as the sole criterion for useful research |
| [Kosmos, Section 2.1](https://arxiv.org/html/2511.02824v2) | Maintain source-linked research state that both analysis and literature work can consume | A knowledge-graph service, permanent ontology or new documentation system for this personal project |

Here, source-linked state is ordinary prose and links in NOTES. The DM owns it. Scout supplies
primary passages and labelled conditional mappings; Scientific Reviewer (ResearchCritic) owns
independent evidence reconstruction, diagnosis and direction-correction recommendations;
Implementer/engineering Reviewer preserve executable semantics. Portfolio considers the remaining
reasons for hope and the cost of the next information when the owner actually triggers a review.
DM retains innovation and synthesis. Apply constitution section 2's independent-review and
material-disagreement responsibilities at the actual decision, without a per-batch agent chain.

## Reasoning cases for author/reviewer inspection

These examples test the *intended reading* of the method. They are not automated certification,
mandatory run checks, or claims about how a live model will behave.

| Situation | Appropriate response |
| --- | --- |
| Intervention never activated | Record nonactivation; do not count it as an adverse active-mechanism trial |
| One positive discovery followed by an adverse independent run | Weaken stable package preference; retain both, consider recurrence or a discriminating explanation without a fixed two-failure stop |
| Prediction metric improves, native return does not | Reconsider this proxy/control connection and its cost; do not promote representation quality to control benefit |
| Result has a small point estimate and wide uncertainty | State unresolved magnitude/direction; no equivalence and no forced new diagnosis |
| A different package succeeds | Preserve its selection history; success does not retrospectively repair the prior failed mechanism |
| A read-only source analogy fails to map information rights | State where it fails and whether a narrower derivation helps; do not change actor rights to rescue it |
| Direction is idle and no actionable work has changed | Do not dispatch another DM solely because a slot is empty; unchanged idle is not a dependency |
| Control revision is published while a fit or Send is in flight | Apply at a safe boundary to future work; preserve exact inputs/handles, do not relaunch or resend |

The practical question is whether the proposed next action inherits the evidence. If the same
action would be selected after every possible result, explain its independent purpose rather
than pretending it was learned from this run. Conversely, an unchanged replication can be the
right next action when recurrence genuinely changes the use or investment decision.
