# HMASD CDC Research Principles

Role contracts are normative. Resolve authority from `AGENTS.md` and
`.agents/roles/`; this reference grants none. Scientific principles are
normative in `docs/project/ALGORITHM_PRINCIPLES.md`.

The scientific outer loop is Conjecture -> Derivation -> Counterexample or
Disproof -> Correction.

## Research objects

- Maintain several live explanations when evidence permits them. Scheduling one
  action never makes other explanations illegal.
- State each conjecture as a conditional mechanism -> behavior -> capability
  claim, with scope, strongest simpler explanation and observable consequences.
- Derive intervention, natural-execution and held-out consequences before
  selecting an evidence action. Add an exclusion consequence when a simpler
  recurrent, capacity or information-path explanation is material.
- Seek a construction that satisfies the surface metric without the claimed
  semantics before implementing a new mechanism.
- Record the smallest retained lemma and smallest refuted unit after every
  result. A result may refute implementation, measurement,
  benchmark-control pair, conjecture scope or, only with strong independent
  evidence, a mechanism family.

## Action selection

Select a scheduled action by information gain, cost and reversibility, using
this default order: derivation, counterexample, reanalysis of accepted evidence,
constructive toy, bounded prototype, formal experiment. An action is a resource
decision, not an epistemic declaration. Unscheduled ideas retain explicit
reactivation conditions. The active Project Manager role contract determines
who performs this selection.

Create an implementation assignment only when implementation is the cheapest
necessary action and its required authority already exists. Role contracts,
not this reference, determine who selects, authorizes, or executes it.

## Evidence discipline

Freeze evidence, not theory. Before observing a result, freeze provenance,
primary estimand, comparator information and resource boundaries, probability
and credit authority, reward semantics, leakage boundaries and
conclusion-bearing metrics. Preserve observations and original meaning while
allowing conjecture, definition, scope, benchmark or architecture correction.

Keep outcomes orthogonal: engineering failure has no scientific update; invalid
implementation updates implementation; invalid estimand updates measurement;
benchmark no-access updates that comparator pair; an identified counterexample
updates the implicated conjecture or scope.

Ordinary recurrent MARL is a matched comparator and access diagnostic, never a
universal admission gate. A gate answers one local question; it is not the
algorithm objective and does not automatically select a successor.
