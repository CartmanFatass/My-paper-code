# Fixed Pro question authoring

## Inputs and authority

Need the selected question, actual author/return parent, allowed preparation or Send scope,
request ID, proper node, directions, full input SHA, fixed references, deliverable and
claim ceiling. A preparation-only task stops at the ready handoff. Portfolio dispatch
requires owner-triggered review. Never regenerate READY, accepted or uncertain packets
for wording changes; reconcile their same request. This method chooses no investment.

## Normal publication

Use `scripts/render_packet.py` with ordinary caller input and github_delivery scope.
Supply caller_role=em or portfolio, workflow_node, request_id, source_thread_id,
parent_thread_id, direction_ids, repository URL/full commit_or_ref, scientific_question,
deliverable, claim_ceiling, reference_files (path, purpose, provenance), constraints and
optional discussion_urls. github_delivery supplies existing non-main branch, full
base_sha, scoped response_path and same-repo issue_url. Missing scope is a missing input,
not a silent attachment fallback. Inspect actual current branch/remote before rendering.
Reuse the direction authoring branch, not a branch per round. A special isolation branch
needs purpose/retirement. Preserve other writers and accepted delivery bindings.

For authorized dispatch the author creates/reuses its minimal-context native Transport
first (Codex Luna/high); source_thread_id=parent_thread_id=actual author, operator_thread_id
is that child. New requests use REUSE_DM_TRANSPORT, not a singleton app task. Generate
TASK and unpublished HANDOFF; commit/push TASK, bind its full SHA with --bind-task-sha,
then commit/push HANDOFF. Return request ID, full HANDOFF commit and fixed TASK URL.
Dispatch exactly to the bound child with followup_task and wait natively within runtime
limits. The child returns directly to the author; Root receives the operational mapping.
Serialize each conversation, including portfolio:cross_direction. Native recovery routes
are separate from frozen historical IDs. Uncertain dispatch requires reconciliation.

Bindings remain em:<direction>:innovator, em:<direction>:convergence and
portfolio:cross_direction. Exact renderer fields and GitHub partial-success handling are
in [github-delivery.md](references/github-delivery.md), read for actual publication only.
The request permits only the named response file and delivery comment; no Pro main write,
code/PR merge, training or unlisted scope. Inspect current delivery HEAD and preserve
unrelated descendants. A matching delivered file/comment is reused, never blindly retried.

## Method and evidence bindings

Pro inherits neither local skills nor role TOMLs. New TASK must inline applicable brief
constraints or explicitly adopt named method sections from
`.agents/skills/hmasd-scientific-tools/SKILL.md` (engineering method when relevant) at a
full fixed Git SHA. Pin current methods separately from frozen science. Include only
relevant explanatory foundation/primary passages. No recursive index or local skill
invocation is required of Pro. Each reference commit_sha is full; omission inherits full
commit_or_ref. Verify path existence and reachability from an observed published remote
ref before publication, without claiming that this proves Pro actually accessed it.

State decision, smallest sufficient evidence class, claim ceiling, strongest alternative,
discriminator, known dominant workload and unknowns. Use machine-generated exposure;
zero new exposure can cite existing records. A sweep includes per-arm cost projection.
No exact-max/search-before-learning/proof ritual for ordinary performance exploration;
finite or native work is not necessarily cheap. Existing source/invocation restrictions
remain explicit. New methods do not alter an already accepted object or request.

## Complete response and exception handling

Read full immutable Git response bytes or the paired downloadable Markdown fallback.
Check actual scope, owner constraints, frozen meaning, class and allowance. Apply a
complete conforming proper-node decision; preserve/cite concrete conflicts and return
them to that node before dependent execution. Independent work continues. Wrong evidence
burden is a methodology conflict, not a scientific negative. No new approval layer.

If scoped GitHub delivery is unavailable after actual-state readback, the same accepted
turn attaches its entire RESPONSE.md. Transport archives exact bytes/hash/size as
<archive_id>__02_RESPONSE.md and repository archive/CHAT_FALLBACK_RESPONSE.md, never
synthesizes archive/RESPONSE.md or claims Git commit/comment delivery. This is not a new
Send. Explicit new archive_attachment input fallback requires nonempty fallback_reason
and [attachment-delivery.md](references/attachment-delivery.md); accepted inputs never
switch mode. Return archive/source, decision/conformance, actual application and remaining
gap. A duplicate receipt reuses intake rather than repeating science or writes.
