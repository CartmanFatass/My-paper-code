# Parallel direction research

Directions may proceed independently when their named resources and scientific
predecessors do not conflict. Completion order is not scientific priority.
Root relays cross-owner work; EM and CM never communicate directly.

The project branch is `EM -> Root -> CM -> Operator -> Root -> same-direction
EM`. EM decides scientific questions and interpretations; CM owns engineering
and technical acceptance; Operator owns mechanics. Use direction, candidate,
revision, isolation, active authorization, run binding, and receipt as anchors,
not as state gates.

Every ordinary B run fixes question, candidate, comparator, exact code/config,
seeds, a small budget, and interpretation boundary. A later named B adjustment
has a recorded reason. Only C freezes full estimand/null/population/stop/decision
criteria. An ordinary B does not create a Pro requirement.

The return from CM is **technical-result return and scientific intake**. The
separate conditional **Direction Action Map semantic-delta installation** carries
only a small EM-authored direction delta via Writer and Root candidate handling,
then EM direction-semantics acceptance and Root full-map acceptance/install. It
does not move a full map and is not required per experiment.

After integration, owner migration uses a short resume card: current goal,
evidence, next owner/action, missing-kind, completion, and pointers. Historical
narrative, old hashes, and completed installs are not current next actions.

Each direction starts only from its exact Root assignment and named pointers.
Root retains relay, user contact, managed-worktree lifecycle, physical writes,
macro comparison, and full-map acceptance. EM and CM are Root siblings; neither
loads a sibling, portfolio, or runtime corpus by implication. One writable
scope has one Root-managed worktree shared only by exact disjoint L2 writers;
no child performs Git or worktree lifecycle actions.

Use source-first, single-axis discriminators. Adaptive consultation is bounded
and prospective, not a roster, quorum, phase, or fourth mode; child context has
no hidden parent or sibling material. Project Scout supplies factual repository
confirmation only. Candidate evidence, temporary artifacts and returned results
remain isolated: attribution, completion order and resource convenience do not
rank directions. The Artifact Writer only handles exact approved ordinary bytes,
temporary handoffs and assignment-specific small semantic deltas. Parked,
pending-implementation, pending-runtime and retired preserve scientific meaning
and never transform an engineering gap into a stop.
