# Parallel direction research

Directions may proceed independently when their named resources and scientific
predecessors do not conflict. Completion order is not scientific priority.
Root alone relays across directions; a Root-authorized same-direction EM/CM L1
pair communicates directly through its bounded channel.

For one stage the project branch is `EM <-> same-direction CM -> Operator -> CM
<-> same-direction EM`, with Root receiving only a decision milestone or
authority/integration request. EM decides direction-local scientific questions
and interpretations; CM owns engineering and technical acceptance; Operator
owns execution facts. Direct handoff transfers owner artifacts, never
scientific or technical acceptance authority.

Root starts `EM_<direction>` and `CM_<direction>` with the identical
`direction_id`, ordinary-language stage authority envelope and counterpart
canonical task name. It reuses the same L1 pair with `followup_task` until the
next decision-level scientific milestone, envelope end or pause. The envelope
states the objective, portfolio rationale, allowed treatment/comparator/
discriminator refinements, protected axes/hypothesis/claim/isolation, provider
authority, engineering/light-probe boundary, heavy-compute classes needing a
lease and Root return triggers. It is not a state machine, ticket or approval
taxonomy.

Allowed direct messages are exactly: EM to CM meaning-complete science card,
scientific clarification, Pro-closed revision, or authorized next treatment;
CM to EM scientific-definition ambiguity, technically accepted result packet,
or a request to change conditions that may affect existing data. Both the
`direction_id` and counterpart task names must match. Wrong-direction or
cross-direction content, evidence transfer, portfolio ranking, user requests,
shared-resource allocation and authority transfer return to Root. Cross-
direction inspiration remains Root-only, provenance-bound and evidence-free.

EM manages already-authorized direction Pro/Gemini conversations inside the
envelope, keeping them separate and mutually blind. It may arrange exactly one
later fresh-tab attempt only after explicit `SEND_NOT_COMMITTED` with
`prompt_sent=false` and `response_received=false` for the identical request.
Ambiguous commitment, an existing provider turn, second noncommit, new
conversation or scope expansion returns to Root.

Heavy compute requires a Root-issued direction lease with resource limits,
concurrency, validity period and stage boundary. Within it CM owns production
guards, Operator dispatch, environment repair and unchanged-science retries
autonomously. Lease expansion, real cross-scope resource
conflict, new user authority or science change returns to Root.

Root milestones are support, contradiction or non-identification of the core
mechanism; material claim-ceiling or strongest-alternative change; cross-
direction competition, absorption, fusion or joint hypothesis; no valuable
successor; envelope/resource overrun; a new provider conversation, broader
external authority or user decision; and final Git/canonical integration.
Ordinary revisions, code completion, focused checks, environment/no-data
repair, unchanged-science retries, Operator facts, provider page/wait facts,
first explicit-noncommit recovery, logs, temporary files and same-direction
handoffs stay in L1. EM's milestone packet contains conclusion, key observation,
strongest alternative, claim ceiling, possible portfolio effect, next
discriminator and the exact Root decision requested, never runtime or transport
streams.

Every ordinary B run fixes question, candidate, comparator, exact code/config,
seeds, a small budget and interpretation boundary. A later named B adjustment
has a recorded reason. Only C freezes full estimand/null/population/stop/
decision criteria. An ordinary B does not create a Pro requirement.

The return from CM is **technical-result return and scientific intake**. The
separate conditional **Direction Action Map semantic-delta installation** carries
only a small EM-authored direction delta via Writer and Root candidate handling,
then EM direction-semantics acceptance and Root full-map acceptance/install. It
does not move a full map and is not required per experiment.

Each direction starts only from its exact Root assignment and named pointers.
Neither paired L1 loads the portfolio, another direction or a runtime corpus by
implication. One writable scope has one Root-managed worktree shared only by
exact disjoint L2 writers; no child performs Git or worktree lifecycle actions.
Local EM/CM handoffs do not wait for Git. Owners append their own factual logs;
logging never wakes Root by itself.

Use source-first, single-axis discriminators. Adaptive consultation is bounded
and prospective, not a roster, quorum, phase or fourth mode. Project Scout
supplies factual repository confirmation only. Candidate evidence, temporary
artifacts and results remain direction-isolated; attribution, completion order
and resource convenience do not rank directions. The Artifact Writer handles
only exact approved ordinary bytes, temporary handoffs and assignment-specific
small semantic deltas.

The already-active VQFP treatment is grandfathered and is not retrofitted. A
later VQFP stage, plus the next SCDMP, CCIC and other new stages, uses this
workflow without rewriting historical logs or evidence.
