# Parallel direction research

Directions may proceed independently when their named resources and scientific
predecessors do not conflict. Completion order is not scientific priority.
Portfolio alone relays scientific inspiration across directions. A Portfolio-
owned EM and Operational-Root-owned CM exchange exact owner artifacts only
through the two Roots.

For one stage the branch is `Portfolio -> EM -> Portfolio -> Operational Root
-> CM -> Operator -> CM -> Operational Root -> Portfolio -> EM`. EM decides
direction science and interpretation; CM owns engineering and technical
acceptance; Operator owns execution facts. Each cross-root hop carries exact
owner-artifact pointers and never transfers acceptance authority.

Portfolio starts `EM_<direction>`; Operational Root separately starts
`CM_<direction>`. Both use the identical `direction_id`, object/revision and
compatible ordinary-language envelopes. Each Root reuses only its own L1. The
EM envelope owns science/provider boundaries; the CM envelope imports exact EM
paths and owns engineering/light-probe/lease boundaries. Neither is a state
machine or approval taxonomy.

Allowed cross-root packets are exactly: Portfolio to Operational Root, an
EM-authored card/clarification/Pro-closed revision/next treatment; Operational
Root to Portfolio, a CM-authored ambiguity/accepted result/cost or change
request. `direction_id` and object/revision must match. Wrong-direction or
cross-direction evidence, portfolio ranking in a CM packet, resource authority
in an EM card and authority transfer return to the sending Root.

EM manages already-authorized direction Pro/Gemini conversations inside the
envelope, keeping them separate and mutually blind. It may arrange exactly one
later fresh-tab attempt only after explicit `SEND_NOT_COMMITTED` with
`prompt_sent=false` and `response_received=false` for the identical request.
Ambiguous commitment or an existing provider turn remains no-resend. New
scientific conversation/scope returns to Portfolio; external permission returns
through Operational Root.

Heavy compute requires an Operational-Root-issued direction lease with resource limits,
concurrency, validity period and stage boundary. Within it CM owns production
guards, Operator dispatch, environment repair and unchanged-science retries
autonomously. Lease expansion, real cross-scope resource conflict or new user
authority returns to Operational Root; a science change is relayed to Portfolio.

Portfolio milestones are support, contradiction, non-identification, claim/
alternative change, cross-direction competition/fusion and science/provider
scope. Operational-Root milestones are technical acceptance, ambiguity,
lease/resource conflict, external authority and Git integration.
Ordinary revisions, code completion, focused checks, environment/no-data
repair, unchanged-science retries, Operator facts, provider page/wait facts,
first explicit-noncommit recovery, logs, temporary files and same-direction
handoffs stay in L1. EM's milestone packet contains conclusion, key observation,
strongest alternative, claim ceiling, possible portfolio effect and next
discriminator, never runtime or transport streams. CM returns only accepted
technical evidence or its exact engineering/authority question.

Every ordinary B run fixes question, candidate, comparator, exact code/config,
seeds, a small budget and interpretation boundary. A later named B adjustment
has a recorded reason. Only C freezes full estimand/null/population/stop/
decision criteria. An ordinary B does not create a Pro requirement.

The return from CM is **technical-result return through Operational Root, then
Portfolio-EM scientific intake**. The
separate conditional **Direction Action Map semantic-delta installation** carries
only a small EM-authored direction delta via Writer and Operational-Root candidate handling,
then EM direction-semantics acceptance and Operational-Root full-map acceptance/install. It
does not move a full map and is not required per experiment.

Each direction starts only from its exact owning-Root assignment and named pointers.
Neither L1 loads another direction or a runtime corpus by implication. One
writable scope has one Operational-Root-managed worktree shared only by
exact disjoint L2 writers; no child performs Git or worktree lifecycle actions.
Cross-root owner-artifact handoffs do not wait for Git. Owners append their own
factual logs; logging never wakes the opposite Root by itself.

Use source-first, single-axis discriminators. Adaptive consultation is bounded
and prospective, not a roster, quorum, phase or fourth mode. Project Scout
supplies factual repository confirmation only. Candidate evidence, temporary
artifacts and results remain direction-isolated; attribution, completion order
and resource convenience do not rank directions. The Artifact Writer handles
only exact approved ordinary bytes, temporary handoffs and assignment-specific
small semantic deltas.

All work already active on 2026-08-21 is grandfathered unchanged to its current
exact milestone: no cancellation, restart, reparenting, resend or coordinate
change. A later science stage uses a Portfolio EM and Operational-Root CM. VQFP
retains its additional historical activity-boundary protection. Historical logs
and evidence are not rewritten.
