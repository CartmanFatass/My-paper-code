# Explorer project validation

The goal is a natural-language, direction-local treatment chain: EM explains
why the candidate and comparator matter and requests one bounded treatment;
Root relays; CM and its Operator build/run it and CM technically accepts it;
Root returns the evidence to the same EM for scientific intake. The brief names
objects and relations, owner, allowed judgment, completion evidence, and return.
Direction, candidate, revision, isolation, active authorization, run binding,
and receipt are anchors only, not admissions or state transitions.

The file-backed ignored relay uses `temp/handoffs/explorer_to_code_manager/` for
the exact EM-approved outbound brief and
`temp/handoffs/code_manager_to_explorer/` for CM's accepted result. The Artifact
Writer may write/remove only EM-approved outbound bytes; Root routes both files
and may remove an exact copy only after confirmed intake. Handoffs never enter
Git and are not archives.

The prose preserves direction, candidate, proposition, revision, source/evidence
locators, frozen/unfrozen facts, uncertainty, required action/resource/conflict,
active authorization, completion and return. If a binding or material scientific
cue conflicts, preserve the artifact and return one exact clarification through
Root while unrelated work continues. CM's conclusion-first return retains those
bindings before technical evidence, locators, counts and adjustment reasons.
EM's subsequent intake is scientific-only: it does not recompute CM schema,
readability, receipts, counts, locators, retry history or technical consistency
unless a fact changes scientific interpretation.

Missing scientific meaning (including comparator or estimand) returns to EM.
Missing code, runner, adapter, package, dependency, or environment belongs to
CM and remains active engineering work. For ordinary B, each run fixes question,
candidate, comparator, exact code/configuration, seeds, small budget, and
interpretation boundary; later named adjustments record why. Full C-level
estimand/null/population/stop/decision freezes do not apply to ordinary B.

The only routine return is **technical-result return and scientific intake**:
`CM -> Root -> same-direction EM`. The separately conditional **Direction
Action Map semantic-delta installation** is EM small-delta authoring, Writer
temporary copy, Root complete-map candidate, EM direction-semantics acceptance,
then Root full-map acceptance/install. Never transport a full map or require the
delta after every treatment.

`publication` means only Root's ordinary non-force configured-upstream push of
an owner-accepted exact path set, producing GitHub-readable remote, branch,
commit, and repository-relative paths. It is not a commit, handoff, intake, Pro
send, acceptance, or promotion.

Explorer-origin Pro review is `EXPLORER_PROJECT_ALIGNMENT_AUDIT`, requested and
intaken by EM only through Explorer transport after an explicit full-flow
request, an existing named trigger, or `OVERNIGHT_BRANCH_BLOCKER_REVIEW`.
CM's formal review remains its CM-owned formal audit. The overnight review
requires exhausted applicable in-scope recovery and legal owner relay; Root
pushes the Git-bound report/evidence and the raw Pro response is fully archived,
committed, and pushed before returning to the original owner. A user decision
requirement stops only that branch.

This procedure defines a post-integration migration handoff only. It does not
edit or rejudge actual continuity, a Direction Action Map, or CM current work.
The proposed resume card says current goal, evidence, next owner/action,
missing-kind, completion, and pointers.
