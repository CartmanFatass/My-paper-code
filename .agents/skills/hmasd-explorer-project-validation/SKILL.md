# Explorer project validation

The goal is a natural-language, direction-local treatment chain: EM explains
why the candidate and comparator matter and requests one bounded treatment;
in the default split Portfolio relays the exact EM artifact to the engineering
lane; the named CM and its Operator build/run it and CM technically accepts it;
the exact CM artifact returns for the same-direction EM's scientific intake.
The active main Root may perform or directly dispatch both lanes locally and
omit cross-session relay, while preserving distinct EM science and CM technical
artifacts, acceptance, and claim boundaries.
The brief names objects and relations, owner, allowed judgment, completion
evidence, and return. Direction, candidate, revision, isolation, active
authorization, run binding, and receipt are anchors only, not admissions or
state transitions.

The file-backed ignored relay uses `temp/handoffs/explorer_to_code_manager/` for
the exact EM-approved outbound brief and
`temp/handoffs/code_manager_to_explorer/` for CM's accepted result. The Artifact
Writer may write/remove only EM-approved outbound bytes; CM owns its reverse
result. The two Roots exchange only the exact file locators and may remove
their own temporary copies after confirmed intake. Handoffs never enter Git and
are not archives.

The prose preserves direction, candidate, proposition, revision, source/evidence
locators, frozen/unfrozen facts, uncertainty, required action/resource/conflict,
active authorization, completion and return. If a binding or material scientific
cue conflicts, preserve the artifact and return one exact clarification through
Operational Root to Portfolio/EM while unrelated work continues. A wrong-
direction/cross-direction cue or portfolio consequence returns to Portfolio;
resource allocation, user request or authority expansion returns to Operational
Root. CM's
conclusion-first return retains those bindings before technical evidence,
locators, counts and adjustment reasons. EM's subsequent intake is
scientific-only: it does not recompute CM schema, readability, receipts, counts,
locators, retry history or technical consistency unless a fact changes
scientific interpretation.

Missing scientific meaning (including comparator or estimand) returns to EM.
Missing code, runner, adapter, package, dependency, or environment belongs to
CM and remains active engineering work. For ordinary B, each run fixes question,
candidate, comparator, exact code/configuration, seeds, small budget, and
interpretation boundary; later named adjustments record why. Full C-level
estimand/null/population/stop/decision freezes do not apply to ordinary B.

The separated-session return is **technical-result return through Operational
Root, then Portfolio-EM scientific intake**. In a main-local path the same
semantic return happens without relay ceremony. Engineering incidents remain CM facts without
becoming scientific or routing states. The separately
conditional **Direction
Action Map semantic-delta installation** is EM small-delta authoring, Writer
temporary copy, Operational-Root complete-map candidate, EM direction-semantics acceptance,
then Operational-Root full-map acceptance/install. Never transport a full map or require the
delta after every treatment.

`publication` means only Operational Root's ordinary non-force configured-upstream push of
an owner-accepted exact path set, producing GitHub-readable remote, branch,
commit, and repository-relative paths. It is not a handoff, intake, Pro send,
acceptance, promotion, or prerequisite for local scientific continuation.

Explorer-origin Pro review is `EXPLORER_PROJECT_ALIGNMENT_AUDIT`, requested and
intaken by EM only through Explorer transport after an explicit full-flow
request, an existing named scientific trigger, or an optional
`OVERNIGHT_BRANCH_BLOCKER_REVIEW`. CM's formal review remains its CM-owned
formal audit. Operational Root publishes Git-bound evidence only when the provider needs
repository visibility. The raw Pro response returns immediately to EM for
intake; archival, commit and push may follow as non-gating audit work. A user
decision pauses only the exact external action needing that authority, not the
direction.

This procedure defines a post-integration migration handoff only. It does not
edit or rejudge actual continuity, a Direction Action Map, or CM current work.
The proposed resume card says current goal, evidence, next owner/action,
missing-kind, completion, and pointers.

Grandfathered in-flight work continues unchanged to its current exact milestone under the old direct pair. Do not
cancel, restart, reparent, resend or rebind it for migration. Every later stage
normally uses the two-root artifact path above when sessions are separate; main
may instead use the local role-separated path without changing evidence meaning.
