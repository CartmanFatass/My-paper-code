# Research engineering

## Inputs and return

Before editing, record five concise L0 facts in the existing task/card: deliverable;
owned checkout/paths/entrypoints; preserved semantics; acceptance; budget and stop.
Reuse card sections. Add interface/shapes/dtype/ownership (L1), state/RNG flow (L2) or
skeleton (L3) only for actual risk. Read the nearest directory AGENTS explicitly.
DM implements direction work; Root implements shared control. No new CM/Implementer
or generic substitute. Optional leaf specialists provide bounded facts, not acceptance.
Return diff/commit, checks, complete-output evidence, limitations and next authorized step.

## Scope and checks

Core (`hmasd`, `ha_ctse_process`, `envs`, `hmasd_*.py`, core launchers/configs) preserves
routes, public interfaces, numerical/RNG behavior and checkpoint compatibility unless
explicitly selected otherwise. Research candidates/run scripts/tests may be disposable
and break their own earlier attempts; core must not acquire research dependencies.
Use one argparse runner with seed, launch SHA and summary containing the card readings.

Do not build unrequested distributed/multiprocess/multinode workers, generic pools,
schedulers, retries, leases, heartbeats, recovery orchestration, hash/authority guards,
incident trees, internal JSON validators, registries, single-use abstractions, extra
telemetry frameworks or compatibility shims. The card (or owner for core) must name
an added facility and scientific need; record `scope: <item> per <card line>`, else none.
Existing infrastructure is reused, not rebuilt. No repeated smoke per launch/slice.
Research cumulative limits: 2,000 new non-test lines per attempt, 600 runner lines;
record named excess or split scientifically, never split commits to hide logical cost.
Orchestration share 30% is a review signal, not rejection. No 100-line exception
application for ordinary research. Research-directory tests total five minutes excluding
runner smoke; preserve necessary scientific coverage and return a concrete gap if budget
cannot support it. Aim for a first run within one session; explain unrequested machinery
if it prevents this. None of these bounds authorizes an experiment.

Self-check changed behavior and the primary output once with proportionate existing or
focused tests, including branch rules where present. Independent read-only Reviewer is
required for shared core, scientific meaning, numerics, RNG, recurrent/replay state,
checkpoint/result identity or external effects, including control/Pro/launch changes.
A thin file that changes such semantics still needs review. Pure wording and reviewed
thin bindings use self-check. Give Reviewer independent contract/invariants/diff/evidence;
findings name reachable failure and impact. The owner repairs and technically accepts;
Reviewer is not a scientific or permission authority. Recheck only changed/failing gaps.

Trace collector → storage → recurrent replay → loss/update → evaluator/publication.
Check actor/critic leakage, snapshot cadence/identity, masks, resets, normalizer state,
termination/truncation/bootstrap, RNG addresses, optimizer exposure and train/eval
isolation. For numerical changes inspect intermediates/gradients over the actual domain.
Use dtype/scale/conditioning/decision-based tolerances, not universal bit equality.
Independent checkers must not reuse the candidate answer as their proof. Keep required
diagnostics even if the primary branch does not consume them. Failed publication limits
its dependent claim; credible unrelated paths need no full historical replay.

## Runtime and bounded execution

Describe full work before acceleration: imports/build/init, rollout/learning/replay,
evaluation/checking, synchronization and final output/readback. Separate cold/warm reuse,
shared preparation once, support/queue time and unmeasured costs. Never delete scientific
work to claim speed. Costs use actual version/node/device/shapes/threads and complete
phase measurements; synthetic projections remain estimates, not serial time/core count.

Ordinary in-process batching and a named function's single-layer fixed synchronous
native team are permitted within the card: fixed lifetime/participant bound, private
mutable state/output, needed synchronization, logical-order result/error merge. No
dynamic executor service. Respect causal/recurrent order, RNG/mask/reduction/tail and
sample/update/replay semantics; count internal BLAS/OpenMP/Torch teams. Card-specific
thread/device/batch/isolation constraints prevail. Optimize measured hotspots with
existing array/native boundaries; no automatic GPU/JIT/language/dependency migration.
Minimal whole-invocation user+system CPU may include actual children without double
counting threads when parallelism changes cost meaning. No standing profiler. RSS scope
must be explicit; sums of per-process peaks are not simultaneous peaks.

General investigation thresholds have conflicting inherited values (AGENTS 2700/43200s
versus runtime spec 5400/64800s). Their numerical consolidation is pending owner resolution;
do not infer a launch/stop/validity gate from either. DM can make a proportionate engineering
judgment from existing costs at a clean boundary. Ordinary wall/watchdog plans can be
prospectively adjusted, including during a live run, without changing frozen scientific
exposure or genuine owner/platform hard limits. Record time/reason and actual cumulative
cost. A killed invocation remains killed; repair grants no retry. Named exact resource
objects retain their own caps. Never report unknown costs as zero.

Use `.codex/hmasd-compute.toml` for real routing, interpreter and supervisor. Publish source
before launch; use detached exact-SHA worktrees. Each run/resume/retry/slice has fresh
actual-node `scripts/hmasd_resource_preflight.py admit-memory --out <receipt>` requiring
physical AND effective available memory >=4 GiB, before scientific initialization.
On remote, preflight `&&` exact runner is inside the same configured agent-task command.
Concurrent checks reserve no memory: serialize launch/acceptance and remeasure capacity.
Unmeasured RSS requires conservative concurrency from existing allowance, updated from
the first planned fit; no extra profiling fit. Stage only declared frozen artifacts with
their given digest; never ship dirty source. Local fallback needs predeclared portability,
confirmed no remote process and fresh local admission. Preserve live handles and reconcile
uncertain acceptance on the same identity; no duplicate launch or process migration.
Assign accepted handles to the DM's monitor; verify direct adoption before ending operator
polling. DM collects, technically accepts and scientifically intakes; exit zero is no verdict.

## Historical exceptions and stops

Frozen objects retain their complete bound card, appendices and accepted input SHA, not
only these common methods. DISH A05 and CBSC B1 have object-only source A/D bounds and
required verification; VNFC E01 has a fixed four-participant batch8, 60s wall/300 CPU-s
assessment and no automatic full census grant. ACVC/RCLE retained-policy exceptions
are object-only. The migration record pins original source versions; load an appendix
only when assigned that named object. Do not transfer an exception to a successor.

An actual scope, scientific-meaning, writer, resource or uncertain-effect conflict stops
only dependent action. Report evidence and owner; continue independent authorized work.
Keep optional resource gaps distinct from missing primary measurements. Clean only own
verified scratch; preserve source/evidence and pending delivery before authorized cleanup.
