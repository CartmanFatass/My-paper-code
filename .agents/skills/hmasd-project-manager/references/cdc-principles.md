# HMASD CDC Research Principles

The scientific outer loop is Conjecture -> Derivation -> Counterexample or
Disproof -> Correction. External GPT-5.6 Pro owns scientific decisions in this
loop. The Research Project Manager preserves the decision, records its durable
delta and checks operational executability. Preserve the strict evidence inner
loop.

## Research objects

- Maintain several live explanations when the evidence permits them. Scheduling
  one action never makes the other explanations illegal.
- State each conjecture as a conditional mechanism -> behavior -> capability
  claim, with scope, strongest simpler explanation and observable consequences.
- Derive intervention, natural-execution and held-out consequences before
  selecting an evidence action. Add an exclusion consequence when a simpler
  recurrent, capacity or information-path explanation is material.
- Seek a construction that satisfies the surface metric without the claimed
  semantics before implementing a new mechanism.
- Record the smallest retained lemma and the smallest refuted unit after every
  result. A result may refute an implementation, measurement, benchmark-control
  pair, conjecture scope or, only with strong independent evidence, a mechanism
  family.

## Action selection

Choose one scheduled action by information gain, cost and reversibility, using
this default order:

1. derivation;
2. counterexample;
3. reanalysis of accepted evidence;
4. constructive toy;
5. bounded prototype;
6. formal experiment.

An action is a resource decision, not an epistemic declaration. Unscheduled
ideas remain live or parked with an explicit reactivation condition.

Create an implementation handoff only when implementation is the cheapest
necessary action and the research object is defined well enough that two
reasonable implementations would instantiate the same estimand. Do not require
a code-ready or exhaustive result contract for an earlier theoretical action.

## Evidence discipline

Freeze evidence, not theory. Before observing a result, freeze provenance,
primary estimand, comparator information and resource boundaries, probability
and credit authority, reward semantics, leakage boundaries and conclusion-
bearing metrics. Afterward, preserve the observation and its original meaning
while allowing a conjecture, definition, scope, benchmark or architecture to be
corrected.

Keep these outcomes orthogonal:

- engineering failure: no scientific update;
- invalid implementation: update only the implementation;
- valid implementation with invalid estimand: update the measurement;
- benchmark no-access or non-identification: update that benchmark-comparator
  pair, not mechanism truth;
- identified counterexample: update the implicated conjecture or its scope.

Ordinary recurrent MARL is a matched comparator and access diagnostic, never a
universal admission gate. A gate answers one local question; it is not the
algorithm objective and does not automatically select a successor or trigger
integration.

## Durable records

Use the controller-owned records under `docs/research/cdc/`:

- `CONJECTURES.md` for versioned conjecture cards;
- `LEMMA_COUNTEREXAMPLE_LEDGER.md` for retained lemmas and counterexamples;
- `IDEA_PORTFOLIO.md` for live, parked, blocked, refuted and integrated ideas;
- `EVIDENCE_NOTES/<id>.md` for one completed evidence action.

External Pro review may be a full plural round or a focused continuation. It
generates conjectures, counterexamples and definition corrections, and selects
one scheduled action without declaring one legal successor or writing an
implementation plan.
