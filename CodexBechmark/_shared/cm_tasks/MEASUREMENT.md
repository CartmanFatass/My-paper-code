# 质量、上下文与全链条成本

## 一条流程一份完整账

主计量单位是一个配置在一个冻结流程上的一次独立运行。CM 连续负责整条流程，子代理
及其修复全部属于该次运行。每次记录真实 session ID；不能用模拟调用次数、字数、
wall time 或手填模型名称估算美元。

团队成本包括 CM 的读题/方案/规范编写/委派/沟通/实现或接管/验收，以及 implementer、
团队 reviewer 的所有正常与返工 turn。初次失败、错误方向和最终被放弃的改动也要保留。
独立最终裁判、通用题包制作与协议校准另列评测成本，同时给包含评测开销的总账。
逐次撰写 L3 的规范和范例制作是 CM 正常工作成本，不能归到免费公共材料中。
reuse 策略的版本固定模式库首次制作/维护另列；每次选择、阅读、填差异和纠错仍属团队。
同时报告未摊销投入与按实际观察复用次数的摊销，不能把库当免费，也不能重复计入每次费用。

本次模式初稿来自持续研究 Root 与筛选子代理，制作费用尚未独立量得。不能把整个历史
Root tree 的费用当成这一份库的成本，也不能随意按消息长度分摊。正式制作/校准使用
任务边界明确的记录；若仍不可得，就把首次投入标为 unmeasured，暂不声称净节省或回本次数。

使用既有 `codex-task-cost-analysis`，由它读取本地 SQLite/rollout、判断完成边界、
计算用量和价格。按模型/effort/角色用 self cost；只有整条流程归属唯一 CM 根会话时
才用该根的 tree cost 表示团队成本。不要把 tree cost 再加上其子节点 self cost。
也不要把整段 child cost 分摊到某一个 parent turn。

每条测试流程使用新根会话，避免历史复用 session 中其他任务费用混入。普通负结果和
预算耗尽应正常写完整终止记录；不为“降低费用”中止日志。意外中断、不闭合 turn、
回退计数器或缺失价格必须写 unavailable/UNPRICED，不能写零。
目前工具只计完整 turn；若某次失败有未计量消耗，完整团队成本也必须标为不完整。
不能删掉这种运行再计算成功组的便宜均值。

## 价格口径

保存运行时价格日期、来源、币种、真实模型与 service tier。输入、cached input、
cache write、output 分别处理；reasoning tokens 是 output 的组成，不重复相加。
API 参考美元与订阅额度/实际账单分开，不能互相替代。

本次查阅到的官方模型页已与成本 skill 自带的 2026-07-26 价表不同：
[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、
[Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra)、
[Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、
[Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)。
正式运行需冻结当时适用价表，不能从旧脚本价格推断当前支出。

这些页面还区分超长单次输入的计费；Astra 页同时列出不同服务方式的倍率。
当前既有分析脚本只接受每模型一套固定费率，不能凭整个会话的累计 tokens 判断某次请求
是否跨越上下文计费阈值。若实际 tier、单请求分段或价格不能核实，只能报告明确标注的
统一标准费率参考值，或保留美元缺失；不能声称实际账单。无需为本次设计修改全局成本工具。

## 结果字段与解释

| 类别 | 至少保留 | 用途 |
| --- | --- | --- |
| 配置 | 场景/版本、流程、重复号、CM/implementer/reviewer 实际模型与 effort、CLI/角色/源码版本 | 确定实际接受了哪个处理 |
| 质量 | 目标数、首次实现通过、最终验收通过、严重错误、前序回归、漏出缺陷、未完成目标 | 同一质量条件下比较 |
| Review | 有效缺陷、无依据指责、未修有效问题、返工轮次、CM 接管 | 检查 reviewer 是否只是把负担移回 CM |
| 委派 | 规定档位、实际交接、档位遵循、追问、规范错误/遗漏、父代理重做 | 说明多寡如何影响完整成本 |
| 上下文 | 事件位置/累计输入工作、持续或冷交接、错误绑定/约束丢失、实际可得的压缩记录 | 区分任务与注意力压力；未知不猜 |
| 用量 | 各角色 input/cached/cache-write/output/reasoning tokens 与测量缺口 | 缓存可解释，角色可追踪 |
| 费用 | 角色 self、完整团队、独立裁判、准备费用、价格来源及参考/实际标签 | 不藏 CM 和评测成本 |
| 时间 | 流程开始至最终交付、工具/等待事实及测量范围 | 报实际关键路径；不把并行子代理时长相加当等待时间 |

主质量结果以整条两题流程为单位，题目级明细用于定位，不把同一 CM 的两个目标当成两个
独立样本。重复运行、共享 episode 和共享父会话的依赖关系在统计中保留。
既给完整流程结果，也给任务位置的通过情况，观察后半段是否退化。

费用充分可测时，`每个通过流程的消耗 = 所有尝试流程的总消耗 / 通过流程数`；
失败消耗在分子，零通过时不生成有限“平均成功成本”。另报通过组条件均值，明确二者不同。
样本不完整时不生成这个比值，不用成功样本替代全队列。

首轮不强行给单一综合分。优先满足同一行为和语义验收，再看成本与时间；同时报告严重
失败和不确定性。检查隐藏测试本身是否覆盖实际不变量，测试绿并不自动证明科学正确。
裁判不能给“更多行代码/更多工具/更多测试/更长说明”额外加分。

## 本次历史提取的作用与局限

历史消耗只是选题/测量可行性的旁证，不能当成模型比较或新测试预算。
见 [EXTRACTION_NOTES.md](_host/cost/EXTRACTION_NOTES.md)。所有历史 CM 配置相同、任务不同，
且部分计数器不满足现有工具要求；因此本次不发布历史模型优劣或完整美元成本结论。
实际新测试成本只在新流程执行后填入，当前矩阵全部为未运行。

## 当前自动实现

一句话入口绑定新打开的顶层 CM；最后 accepted 后，收尾进程等 SQLite/rollout 中真实
turn 结束再调用既有成本工具。团队与独立 Astra/high 裁判分别输出原始报告到 cost/，
不在 runner 中另写 token 或美元公式。实际子代理模型、effort、角色、父子关系和公开
原生交互另存 export.json；配置标签本身不能证明该配置实际运行。

当前冻结价表见 [_host/pricing.json](_host/pricing.json)，为官方页面上的 API Standard
费率参考情景，观察日期 2026-09-10 UTC。它不包含未知 tier 或单请求超长倍率；
不将所得数字称为实际账单或订阅额度。缺失模型价格、未闭合 turn 与工具失败仍保留
UNPRICED/unavailable。只有这份新根会话确实专用于本轮时 tree cost 才代表完整团队。
不要在收尾期间继续用该 CM session 做其他工作，否则后续 turn 也可能进入该根统计。

实现已做离线流程与成本调用边界检查，没有新模型试跑或新模型费用结果。
库/题包的首次制作仍为 unmeasured；离线参考实现校准不能填成候选成功率。
