# CM 两题工作流程协议 cm-pair-v1

主问题是 RL 重复工程任务的 spec 应细到哪一层、如何复用才能减少澄清与返工并保持质量。
配置比较在同一 CM 的连续上下文中进行，见 [SPEC_DESIGN.md](SPEC_DESIGN.md)。

## 基线与角色

基线来自 HMASD `1385b56b6a0761d4064dcafbce0c66c590ecc5a2`：
Astra/medium CM 默认直接实现，语义改动由 Astra/high 独立 reviewer 审查。
五项交接是当前 L0；强制使用 Terra/high implementer 是委派场景的实验处理，
不是当前生产默认。来源路径、角色哈希和适配说明见 [_host/BASELINE.json](_host/BASELINE.json)。

独立目录中新打开的顶层 session 就是 CM；不要再创建 CM 子代理或第二个 CM CLI。
benchmark 的角色指令是针对本题边界的适配，不是生产角色 prompt 的逐字复制：
保留实际实现、独立审查、父级验收、同人修复、显式 Git 操作和科学语义；
去掉生产研究、远程训练、Transport 与 Pro 权限。各比较组使用相同适配版本。
子代理首次调用使用无历史继承的上下文；同任务后续修复可复用原执行者和 reviewer。

## 两题抽样与冻结

每轮仅两题：从五个经典范例随机抽一个，再从三个非范例随机抽一个。
默认第二题的 easy/medium/hard 预估标签不同于第一题；`--difficulty any` 取消此限制。
这是按约束抽样，不宣称各任务出现概率相同。所有难度均为设计估计，尚无模型成功率校准。
跨配置复用相同 seed、题库和依赖版本，跨新 session 独立执行。

题包是依据当前项目代码边界构造的小型 synthetic 修复，保留调用者和两个可编辑实现模块。
它们不是历史缺陷原样回放，也不代表完整多模块生产任务。每题说明完整给出科学假设、
接口、所有权和公开检查，所有 L0–L3 组得到相同事实与最终验收。范例不能覆盖题目例外。
第一题被接收后自动投递第二题；CM 继续保有第一题代码，最终同时核验两题。

准备时冻结源码哈希、题目、顺序、公开验收、隐藏 oracle、材料、事件、依赖版本和运行脚本。
复制每轮小型 runtime 后，后续维护不会漂移已准备 run 的输入。隐藏参考解和第二题身份
不提前交给候选。依赖为 NumPy 1.26.3、Torch 2.7.0+cpu；无科研训练。

## 边界、杂务与真实操作

每题依次提交 located、checked、reviewed、accepted。每次先保存实际源码、work/ 和 Git
事实，然后投递固定事件。它是工作边界投递，不是任意时刻异步中断，也不由 wall time
决定慢模型承受多少事件。真实子代理交互和工具输出自然累积；不填充随机长文本。

事件包含：邻接文件无关脏改动、背景 run 的迟到/缺失产物、旧失败日志、状态询问、
只改文档的独立提交和相似 run 名的完成声明。它们属于 synthetic 背景任务，不能替
当前候选代码出具通过证明。具体时序见 [_host/EPISODES.md](_host/EPISODES.md)。
真实 reviewer 独立看改动；主持者不会伪造与 patch 无关的审查结论。

候选实际运行公开检查、处理审查意见、按显式路径提交并推送本地 bare origin。
每题 accepted 单独检查提交和 push，避免后来的主持提交掩盖前题漏交付。
邻接无关修改必须保留且不得纳入候选提交。默认每题三十分钟是软时间参考；
超时或失败按事实记录，仍提交剩余边界，不伪造成功、不另抽更容易的题。
未完成流程保留现场；最后边界后才自动评分，提前中断不算完整样本。

## 质量、日志与自动收尾

八个边界完成后，一次性后台辅助进程等实际顶层 CM 的 turn 完成，再读取 SQLite/rollout
中的角色、模型、effort、父子关系与公开原生调用/返回，排除私有推理内容。
候选自报角色或文本审查记录不能替代真实原生证据。配置不符或证据不足如实报告。

行为检查分别检验首次实现和最终状态；最终状态还检验前题回归、Git、背景身份和交付。
独立 Astra/high 裁判读取冻结最终产物、首次实现、任务事实、档位政策和实际公开交互，
评估规范准确性、review 依据、接管、工作流与未完成事项。裁判与候选 CM/团队 reviewer
独立；成功退出且记录了不同的真实会话 ID 才能参与完整通过判定。模型标签从配置副本移除，
但政策必须可见、自由文本仍可能带线索，因此不声称完全盲评。

成本在 CM turn 真正闭合后调用现有成本 skill；团队 tree 与独立裁判分开，
公共库首次制作仍 unmeasured。完整通过不是成本结论，一次两题也不能产生“最佳模型”
或“最佳 spec”结论。实际模型试跑、角色加载及在线评分体验仍需首个真实候选运行验证。
