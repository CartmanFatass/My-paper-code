# CM 真实工作流程测试设计 v0.2

## 问题与基线

主问题是：RL 重复工程任务的 spec 应细到哪一层、怎样复用，才能减少澄清和返工并保持
质量。先固定模型回答它，再考察 CM 直接编码和不同执行者配置；所有主比较均在同一 CM
连续工作与杂务压力下进行。主研究顺序以 [SPEC_DESIGN.md](SPEC_DESIGN.md) 为准。

当前 `.codex/agents/hmasd-cm.toml` 已要求 CM 默认直接实现，implementer 只在独立并行或
上下文隔离有益时使用。高风险改动保留独立 reviewer。因此：

- 架构基线：Astra/medium CM 直接实现 + Astra/high reviewer。
- 委派基线：在强制委派的场景内，L0 使用当前五项交接方式；这不是声称当前所有任务都委派。
- 现有 semantic implementer 为 Astra/medium，routine implementer 为 Luna/max。
  测试中改变模型时使用同一套与该题风险相符的角色职责；不能把 Luna 的 routine 禁止语义
  变更规则带入语义题，再把拒绝执行解释为模型能力不足。

基线来自固定维护 revision 的实际配置。测试副本删去生产端点/真实发送能力，保留本题
必要的所有权、科学不变量、验收与工程范围规则；所有比较组使用同一份副本。
不趁模型比较同时重写角色提示词。之后若要研究角色提示词精简，另立版本比较。

## 相同任务，真实工作

CM 必须真的读代码、编辑、运行公开检查、处理 reviewer 意见并完成交付。
implementer 和团队 reviewer 是被测 CM 发起的真实独立子代理，不由 CM 模拟它们的回复。
机械 runner 只分发既定材料和记录产物，不决定如何实现、修复、委派或接受。

每条流程包含 2–3 个有依赖的编码目标以及若干业务事件，CM 始终是同一会话。
同模块修复复用原 implementer；reviewer 在第一次审查前不接收实现者内部讨论，后续修复
可复用原 reviewer。不得把 CM 全部历史默认交给 implementer，否则说明颗粒度的差异会消失。
子代理上下文策略固定并记录；若运行时不能实现约定隔离，应记录为实现偏差，不偷换成文本模拟。

测试输入来自历史，但任务在答案未知的源码快照上重新完成。历史修复 patch、未来事件、
结果结论与隐藏检查只给主持者。保留必要调用链、依赖和公开测试；不把真实多模块问题裁成
一段只需补空的函数。每个题包至少固定输入 revision、文件清单、依赖版本、公开验收、
保护语义、最终可观测行为及隐藏检查。历史 commit、实验数据和外部文献不自动授予访问权。

不要求重跑历史科研训练。编码/单元检查真实执行；远程运行回执由固定本地材料重放。
模拟回执不能当成候选代码已通过端到端验证；技术质量由同一独立检查集合判定。
Git 杂务在隔离测试仓库真实操作，可以使用本地 bare remote，不接触生产分支或网络服务。

## 连续上下文与注意力压力

压力主要来自要完成的工作，而非随机填充长文。具体事件在选题时冻结：

| 事件 | 需要候选完成的实际工作 | 观察点 |
| --- | --- | --- |
| 前一改动的 reviewer 返回 | 核对事实、修复有效缺陷、给出依据充分的异议 | 未处理意见、盲从或漏改 |
| 原 run 延迟回执、相似的新 seed/run 名称 | 对齐正确任务，收集所给产物，更新待办 | 错绑定、旧 seed 回写、重复启动 |
| 新的小修复与原保护条件并存 | 在现有代码上修，不丢前面已接受行为 | 前序回归、任务遗漏 |
| 文档独立更新、邻接文件存在无关修改 | 只提交所属改动，按内容判断是否冲突 | 覆盖他人工作、无谓重跑 |
| 完成声明与实际缺文件不一致 | 查看产物，识别不完整交付，继续必要收尾 | 只信回执、过早结束 |
| owner 中途询问状态 | 简短答复后继续原任务 | 把询问当取消或新审批条件 |
| 原错误仍在旧日志，最新证据已更正 | 依据时间和来源更新事实、保留历史 | 使用过时结论 |

自然 review 返回由被测团队产生；固定回执属于外部事件。两者在记录中分开，不能强行向
没有该缺陷的 patch 注入“你有这个 bug”的 reviewer 结论。

第一版在固定工作边界自动投递事件：读完任务/定位后、首个检查后、review 返回后、
准备交付前。每组的外部事件正文、顺序和代码目标相同；按边界投递，避免以墙钟延迟
让慢模型受到不同干扰。所有检查点必须访问，包括跳过公开检查的失败路径。
这属于边界式中断重放，尚不能称为任意时刻异步打断。真实工具输出与团队交互自然累积。

不要为了使某模型通过而临时缩短日志、重述先前约束、换简单任务或清空上下文。
也不强求各组生成同样多的 tokens；额外阅读、冗长说明和返工造成的上下文增长是结果。
记录任务所处位置、已历事件数和实际可得的上下文/压缩事实；未知项写 unmeasured。
允许候选使用日常笔记和自然压缩，不由主持者替某组整理记忆。

## 对照与复现

主要结果来自持续同一 CM 的完整流程。冷启动控制只用于区分编码与上下文问题：在预先
约定的交接点复制该候选当时的实际源码、未完成事项和证据，同时保留 warm 分支继续；
cold 分支由新 CM 接收同样的最小书面交接。两边带有相同已产生缺陷，不能只给冷启动组
一份修正后的标准代码，也不能给它温启动组的完整对话。它测的是持久会话与交接策略差异，
不是抽象的纯 token 长度效应。额外冷启动成本单列。

筛选流程与留出流程按完整任务家族划分；同一 bug 的改名版本不能同时充当训练题和留出题。
重复运行使用新的顶层会话和独立仓库；同一轮内部不重置 CM。
保留因果依赖，轮换互不依赖杂务的位置；配对配置使用相同顺序。对比顺序随机化并保存，
避免缓存、服务负载或熟悉题目影响总是偏向后测配置。模型与 effort 分列，当前矩阵比较
部署配置，不能把 Astra/medium 对 Luna/max 的差异全部归因于模型本身。

首轮校准只能修题包缺陷，不据候选表现改验收。修题后升级题包版本，旧结果保留并标注。
先完成有限筛选，再对事先规定数量的入围配置做留出验证；不能发现某配置差就不断给它
新提示直到通过，或仅保留成功的一次。没有缺陷覆盖/足够样本时不宣称最佳配置。

## 质量与独立评分

团队 reviewer 是被测系统的一部分；最终裁判必须独立于该团队，且不同组使用相同规则。
最终检查在候选提交后运行，隐藏结果不得反馈给候选再作为同一次的正常返工。
先用可执行行为检查，再由独立裁判核实语义/范围/历史保持；尽量隐藏模型、价格与提示档位。
对不能匿名的残余线索明确标注。裁判自身产生的费用作为评测费用分列。

分别报告：首个实现快照的通过情况、团队 review/修复后的最终通过、有效缺陷检出、
无依据 review 指责、review 后仍漏出的缺陷、返工轮次、未完成目标和关键约束遗失。
漏出的科学语义错误、无关工作被覆盖、错误任务/seed 绑定等单独列严重失败，不能用文字
完整度或廉价成本抵消。不奖励多造框架、额外测试数量或冗长说明。

最终选择先看是否满足同一验收，再比较完整成本和完成时间。结果按任务形态与风险分层；
历史 census 的会话比例仅帮助选题，不当成真实任务频率或计算量权重。
单次筛选只给候选排序线索；正式选择看留出流程、重复结果和不确定性，并保留质量/成本
互有优势的配置。若预算不足以区分两个配置，结论为未分出，不强行选赢家。

## 自动执行接口（待实现）

延续 root_delegation 的轻量主持思路，但不复用它“只写模拟动作”的答案协议：

1. 主持命令 prepare：选择场景、配置、流程和重复号，准备隔离代码仓库与专用角色配置。
2. 从该 run 工作目录启动新的 Codex CLI；CM 按本项 AGENTS 自动 next/checkpoint 循环。
3. CM 自己实际委派、处理回复、测试和收尾；runner 按既定边界给后续工作，不替 CM 调度子代理。
4. 每次 checkpoint 保存对应源码/交接/团队 review 记录；export 产出完整流程与实际 session 清单。
5. 独立 judge 在候选结束后运行隐藏验收并写结果；成本工具事后读取实际会话记录。

各 run 拥有独立 `.codex` 配置与工作目录，不继承 HMASD 根目录指令，不修改全局配置。
实际生效的 CM/子代理模型、effort、CLI 版本、全局指令来源、工具/权限、上下文继承必须记录；
仅自报模型不足以标记配置正确。官方支持为自定义子代理设置模型、effort 与只读角色，
但本机是否按本测试装载须由实际元数据验证：[官方子代理说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)。

目前只交付设计与筛选，prepare/next/checkpoint/export/judge 是后续实现契约，不能照本文
假定命令已经存在。正式执行前先完成题包、参考实现与隐藏检查的交叉验证，以及一个流程
的协议校准；校准消耗计入测试准备，不冒充模型胜率。不得自动启动完整矩阵。
