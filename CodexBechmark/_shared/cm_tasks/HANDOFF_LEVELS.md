# 委派说明 L0–L3

四档是**累积增加**的信息，不是四种不同任务。所有档位得到相同基础任务、源码、公开验收、
保护语义、所有权与执行限制；最终独立评分相同。涉及科学含义的必要事实不能故意从 L0
删除。现有 AGENTS 中的通用代码规则也不能只给 L1。L1 增加的是本任务的具体工程约定。

| 档位 | CM 要实际生成给 implementer 的交接 | 必须避免 |
| --- | --- | --- |
| L0 当前默认 | 当前五项：交付目标；所属路径/入口；保护语义；验收及精准引用；预算/停止条件 | 长篇复述科学历史或暗藏 L2 逐步方案 |
| L1 +代码规范 | L0 +本任务接口、数据形状/类型、返回/错误处理方式、现有工具复用与测试组织等适用约定 | 增加新功能或新验收门槛；只把 L0 改写得更长 |
| L2 +具体逻辑 | L1 +数据/状态如何流转、操作顺序、关键分支、边界和伪代码 | 改变算法或科学不变量；把研究选择委派给 implementer |
| L3 +代码范例 | L2 +小型函数骨架或局部实现示例、输入输出示例 | 提供历史最终 patch 或隐藏测试答案；把整个任务预先做完不计费 |

主实验中 CM 依据档位**现场编写**交接：fresh 写本次完整内容，reuse 引用该档版本固定的
模式/范例并补差异；两者的查阅、编写、澄清、返工和验收均计费，库制作另列首次投入。
先固定 CM、implementer 与团队 reviewer，只改变档位和交付方式，再扩展 implementer 模型。
implementer 先负责完整指定代码面；CM 可检查与集成，若直接接管修复必须记录接管原因、
代码范围与成本。这是委派政策的实际结果，不能在分析时只挑没有接管的样本。

第二个诊断视角可用冻结交接包交叉投递给不同 implementer：同任务、同档位用完全相同
文本，以辨别模型接收说明的差异。交接包先统一制作，不针对某个 implementer 的失败优化。
其生成成本单列或按预先指定次数分摊；不能用免费固定包的结果证明真实 CM 委派更省钱。
诊断视角不替代上方真实 CM 工作流程，也不默认展开另一套全量矩阵。

可复用模式见 [patterns/README.md](patterns/README.md)，主研究顺序见
[SPEC_DESIGN.md](SPEC_DESIGN.md)。模式内容要按档分发；引用不得让 L0 间接读到 L3 范例。

四档比较能回答“增加到哪一层是否值得”；不能单独识别代码规范、逻辑、范例的独立
因果效应或所有交互。只有出现值得解释的差异，再预先设计如 L0+范例 的消融。

## 同一任务的示意：新增 seed 参数贯穿已有路径

这里只说明档位差别，不是任何实际 HMASD 科学调用的可执行合同。
正式题目要固定真实源码、RNG 不变量和验收。

- L0：把已选定的新 seed 传入指定已有 runner/study/初始化/结果元数据；默认行为、RNG
  命名空间和科学预算不变；给入口、文件与公开检查。
- L1：补充已存在的 Config 字段位置/类型、函数签名、metadata 字段复用方式；禁止创建
  第二份 seed 真值，按既有错误处理和测试目录组织。
- L2：补充 argparse → Config → 既有初始化/训练/评估工厂 → 结果写出的传递顺序；
  哪些函数必须接显式 seed，哪些命名空间必须保持常量；默认参数与新参数的分支行为。
- L3：再给一段使用不同名称的局部“参数透传到既有工厂”的示例和最小测试骨架；保留目标
  任务中需要阅读与完成的调用链，不给最终 patch。

输出长度是档位的测量结果，不按相同字数强行裁剪。记录实际结构是否符合档位、缺漏/错误
信息、implementer 的追问和 CM 接管；提示写了 L3 不等于真实交接就达到 L3。
档位不合规照原分配组保留分析，并另报遵循率，不能事后重标档位来美化结果。
