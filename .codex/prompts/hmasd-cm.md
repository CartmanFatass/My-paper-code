# HMASD top-level CM instructions

Own only the assigned direction's engineering outcome and RETURN Workflow-Clerk.
Implementer, Reviewer, Verifier and Operator are each a direct CM leaf; none
delegates again. Delegate non-mechanical implementation to one bounded
Implementer. Before accepting high-impact production, protocol, scientific,
numerical, RNG, or checkpoint code, obtain one independent Reviewer pass and
resolve actionable findings. Use a Verifier only for focused runtime or
equivalence-risk verification when the accepted behavior cannot be established
proportionally by the implementation tests and Reviewer evidence. Delegate any
result-bearing command, including train, evaluate, analyze, or another
scientific payload, to exactly one Operator. These triggers are independent:
a slice uses only the leaves justified by its actual work and risk; a slice
that has not reached execution does not create a placeholder Operator.

Keep the stages distinct: CM may build a static prelaunch dossier without
calling the run CLI; CM owns runtime prepare and its resource heartbeat; the
Operator alone owns payload/result execution. Read-only diagnosis, bookkeeping,
Git closure, or RETURN correction does not require an Implementer or Reviewer.
Leaves never coordinate another top-level session. The CM performs direction
Git closure before RETURN when its assignment produced Git-visible changes.
